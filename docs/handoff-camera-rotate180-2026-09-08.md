# 카메라 영상 180° 회전(설치 방향 보정) 요청 — 펌웨어/백엔드 핸드오프 (2026-09-08)

> 작성: Flutter 앱 담당. 대상: FB2_P4_CAM 펌웨어 + terra-server/petcam-api 담당.
> 요청 요약: **카메라 센서 단에서 180° 회전을 지원해 달라.** 앱은 설정 토글 UI만 붙인다.

## 1. 배경 — 왜 필요한가

- 사육장 구조상 카메라를 **천장·측면에 거꾸로 설치**하는 경우가 있다. 이때 라이브·클립·썸네일이 전부 뒤집혀 보인다.
- 사용자가 물리적으로 캠을 돌릴 수 없는 위치(부착형 마운트)가 실제로 존재한다 — 설치 자유도를 소프트웨어가 보정해줘야 한다.

## 2. 왜 앱 표시 플립이 아니라 **센서(펌웨어) 단**인가

앱에서 `Transform.rotate`로 표시만 뒤집는 방안을 먼저 검토했고, **한계가 명확해서 기각**했다:

| 방안 | 라이브/앱 내 재생 | 기기 저장(mp4) | 공유(share) | 커뮤니티 피드 | 계정 간 동기화 |
|---|---|---|---|---|---|
| 앱 로컬 표시 플립(Hive) | ✅ | ❌ 거꾸로 | ❌ 거꾸로 | ❌ 타 사용자에게 거꾸로 | ❌ |
| 서버 메타데이터 + 앱 표시 플립 | ✅ | ❌ 거꾸로 | ❌ 거꾸로 | △ 포스트마다 플래그 복사·플레이어 배선 필요 | ✅ |
| **센서 단 회전(요청안)** | ✅ | ✅ | ✅ | ✅ | ✅ (캠 자체 설정) |

핵심: 표시 플립은 **픽셀 원본이 그대로**라서, R2에 저장되는 클립·썸네일·내보내기 파일·커뮤니티 스냅샷이 전부 뒤집힌 채 남는다. 소스에서 바로잡으면 모든 파생물이 자동으로 맞고 앱·서버는 아무 후처리도 필요 없다. "설치 방향" 문제이므로 해결 지점도 카메라가 맞다.

## 3. 요청사항 (펌웨어)

**R1. 180° 회전 = `vflip + hmirror` 동시 적용.**
esp_camera 계열 센서는 `set_vflip(1)` + `set_hmirror(1)`을 함께 켜면 재인코딩 없이 레지스터 수준에서 180° 회전이 된다. ⚠️ **vflip 하나만 켜면 상하만 뒤집혀 좌우가 거울상이 된다** — 반드시 두 개 세트로.

**R2. 설정 영속화.** 회전 여부를 NVS(또는 동등 저장소)에 저장해 **재부팅·재연결 후에도 유지**. 기본값 false(정방향).

**R3. 적용 범위 = 센서 출력 전체.** 별도 분기 없이 라이브(WebRTC) 스트림·모션 클립 녹화·썸네일 캡처가 같은 센서 출력을 쓰므로 자동으로 전부 적용될 것으로 이해하고 있다. 만약 경로별로 파이프라인이 갈린다면 알려달라.

**R4. capabilities 보고에 회전 지원 여부 포함.**
`devices.capabilities.led_dimmable`처럼 `rotate_180` 지원 여부를 보고해주면, 앱이 미지원 카메라(구 펌웨어)에는 토글을 숨긴다. (capabilities 보고는 LED 건으로 이미 대기 중인 항목 — 같이 실어주면 좋다.)

## 4. 요청사항 (서버 — 전달 경로·계약)

**R5. 앱 → 서버 → 카메라 설정 전달 경로.**
사육장 기기는 `commands`/`device_settings` REST가 있는데 **카메라(FB2_P4_CAM)에는 앱이 설정을 보낼 채널이 현재 계약에 없다.** 제안(어느 쪽이든 수용):

- (a) `cameras` 테이블에 `rotate_180 boolean` 컬럼 + 카메라가 부팅/주기 폴링 또는 MQTT로 구독해 반영, 또는
- (b) device 계열과 동일한 명령 테이블/토픽으로 `camera_rotate` 명령 추가.

앱 쪽 선호는 (a) — 상태형 설정이라 명령보다 선언이 맞고, 유실(mist 블랙아웃 계열) 걱정이 없다. 서버가 정하는 계약을 따르겠다.

**R6. 적용 시점 명시.** 라이브 스트림 중 토글 시 즉시 반영되는지, 다음 세그먼트/재연결부터인지 계약에 적어달라. 앱 안내 문구("잠시 후 적용돼요")가 여기 달려 있다.

## 5. 알고 있는 한계 (요청 아님, 공유)

- **이미 녹화된 과거 클립은 소급되지 않는다.** 필요해지면 앱이 과거 클립에 한해 로컬 표시 플립을 얹는 방안을 별도 검토한다(공유·저장물은 원본 방향이라는 한계 포함).
- 90°/270°는 요청 범위 밖(케이스 없음). 180°만.

## 6. 앱 쪽 계획 (참고)

- 카메라 설정(사육장 설정의 기기 타일 문법, `DeviceSettingSheet` 계열)에 "화면 뒤집기(180°)" 토글 추가.
- capabilities 미보고 카메라는 토글 숨김.
- 계약 확정 → 앱 배선까지 반나절 내 대응 가능.

## 7. 회신 요청 항목 정리

1. R1~R4 펌웨어 수용 여부 + 예상 일정
2. R5 전달 경로 결정((a)/(b)/제3안) + 스키마/토픽 확정
3. R6 적용 시점
4. capabilities 보고(LED 건 포함) 일정
