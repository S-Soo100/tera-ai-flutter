# 비바나트 — 시각 디자인 방향

> **작성일**: 2026-08-08
> **범위**: 시각 언어(위계·타이포·색 역할·시그니처). 화면 구조는 기획안(`docs/prd-vivnanaut-app.md`)이 정한다.
> **팔레트·컴포넌트 규격**: Figma `Asset` 섹션이 SOT — `docs/figma-final-design-transcript.md` §4. **이 문서는 그 값을 바꾸지 않고, 어디에 어떻게 쓸지만 정한다.**

---

## 1. 무엇을 고치려는 것인가

기존 화면이 "별로"였던 원인은 취향 문제가 아니라 **구조 문제**였다. 근거:

| 증상 | 실제 코드 |
|---|---|
| 눈이 어디로 갈지 모른다 | 온습도·차트·제어가 전부 같은 `Card` + `padding 16` + `radius 16`. **위계가 없다** |
| 가장 중요한 숫자가 안 보인다 | `현재 24.5°C`가 `titleMedium`(~16px) — 본문과 같은 크기 |
| 차트가 정보를 못 준다 | 높이 64px에 온·습도 두 선이 겹침. 형태가 뭉개져 **통계로 넘어갈 이유가 안 생긴다** |
| 문구가 시스템 말투 | `"차트 터치 시 통계 탭으로 이동 ›"` — 시스템이 자기 동작을 설명한다 |
| 제어 상태를 훑을 수 없다 | ON/OFF가 **텍스트로만** 구분됨. 타일 생김새가 동일 |

---

## 2. 이 앱은 무엇인가

**귀여운 반려동물 앱이 아니라 야간 관측소다.**

- 개체가 야행성이라 사용자는 **밤에** 앱을 켜고, 아침에 "간밤에 뭐 했나"를 읽는다
- 게코는 꼬리를 흔들지 않는다. **데이터가 사용자와 개체 사이의 거의 유일한 대화 수단**이다
- 히터 과열은 폐사로 이어진다. 이 앱의 숫자는 장식이 아니라 생사에 걸린 정보다

이 성격이 아래 결정 전부의 근거다.

---

## 3. 시그니처 — 밤 띠 (Night Band)

**시간축을 쓰는 모든 차트에 `22:00~06:00`을 배경으로 깐다.**

- 기획안 §3.1 ②가 정한 **활동 집계 창**과 정확히 같은 구간이다. 즉 **장식이 아니라 규칙의 표시**다
- 사용자는 "그래프의 어디가 우리 애가 사는 시간인지"를 읽지 않고 알아본다
- 주행성 반려동물 앱에 옮기면 **의미를 잃는다** — 이 앱에서만 성립하는 요소다
- 메인컬러 `#192553`이 마침 한밤중 하늘색이라는 점을 활용한다

**제약**: 데이터 선을 절대 가리지 않는다. 라이트는 `brandNavy` 6%, 다크는 흰색 5% — 다크 배경에 남색을 더 깔면 아무것도 안 보인다. 구현: `AppTheme.nightBand(brightness)`, `home/domain/night_band.dart`.

띠 옆에 범례(`밤 10시–6시`)를 한 번 붙인다. 색만 깔면 *"왜 저기만 어둡지?"*가 된다.

## 4. 위계 — 카드를 줄인다

세 요소가 같은 무게였던 것이 문제였으므로, **무게를 다르게** 준다.

| 요소 | 담는 그릇 | 이유 |
|---|---|---|
| 현재 온·습도 | **카드 없음.** 화면에 직접 | 가장 중요하니까 가장 먼저 보여야 한다 |
| 24시간 차트 | **카드 없음.** 폭 전체 | 두 선의 *관계*가 읽혀야 한다. 좁은 카드 안에서는 뭉개진다 |
| 제어 4종 | 타일(카드) | 누르는 것이므로 경계가 필요하다 |

---

## 5. 타이포 — 숫자가 주인공

Pretendard 고정. 크기·굵기로 역할을 가른다.

| 역할 | 스펙 | 쓰임 |
|---|---|---|
| **Readout** | **48px / Bold / tabular figures** | 현재 온·습도. 화면에서 가장 큰 글자 |
| 단위 | 20px / SemiBold / muted | `°`, `%` |
| 타이틀 | 18px / SemiBold | 섹션 |
| 본문·라벨 | 14px | |
| 캡션 | 12px / muted | 축 라벨, 최고/최저, 범례 |

**`tabular figures` 필수** — 값이 1초마다 바뀌는데 비례폭이면 숫자가 좌우로 흔들린다.

**48px는 이 방향의 리스크다.** 상단 1/3을 숫자 둘이 차지한다. 보통은 카드에 담아 정리하는데 반대로 갔다. 근거: 밤에 어두운 방에서, 손에 든 폰을 멀리서도 읽어야 하는 숫자다.

> ⚠️ 큰 글자는 가장 먼저 넘친다. **잘라내지 말고 `FittedBox(scaleDown)`으로 줄인다** — 숫자를 ellipsis로 자르면 값이 달라 보인다(`24.5` → `24…`).

## 6. 색 — 데이터에만 쓴다

Figma 팔레트를 바꾸지 않고 **적용 범위만 좁힌다.**

- **채색은 온도(`#ff3752`)·습도(`#8abcfc`) 둘뿐.** 나머지는 무채색
- 지표 색은 **숫자가 아니라 라벨 앞 점**에만. 숫자를 칠하면 값에 따라 색이 변하는 것처럼 오해된다. 아래 차트 선 색과 이어지는 연결고리만 있으면 충분하다
- **동작 마커(분무·팬·히터·LED)는 무채색.** 기기마다 색을 주면 온·습도 선과 색이 경쟁해 정작 읽어야 할 곡선이 묻힌다
- 제어 타일: 켜짐 = `brandNavy` 채움 / 꺼짐 = 흰 바탕 + `lineColor` 테두리 (Figma Button 규격 §4.3). **색으로 먼저 보이고 글자가 확인해주는 순서**

## 7. 문구

- 시스템 동작 설명 → 사용자 행동으로. `차트 터치 시 통계 탭으로 이동 ›` → **`통계 보기 ›`**
- 값이 없으면 `0`이 아니라 **`--`**. 0은 실측처럼 보이는데 이 앱에서 0°C는 센서 오프라인 센티넬이다
- 최고/최저는 둘 다 있을 때만 낸다. `-- / 23.5` 같은 반쪽은 읽는 사람을 헷갈리게 한다

## 8. 품질 기준

- **레이아웃은 테스트로 지킨다** — `test/features/home/control_tab_layout_test.dart`가 393px·320px·`textScale 1.5`에서 렌더한다. Flutter는 오버플로를 예외로 던지므로 이 테스트가 곧 안전망이다. (실제로 이 방식으로 초안의 오버플로 4건을 잡았다)
- 값이 없는 상태(`--`)를 항상 렌더 가능해야 한다

## 10. 화면 미리보기

`test/features/home/control_tab_golden_test.dart`가 **실제 위젯을 393×820으로 렌더해 PNG로 남긴다**(`test/features/home/preview/`). 목업이 아니라 진짜 화면이라, 방향을 눈으로 검토할 때 이걸 본다.

```bash
flutter test test/features/home/control_tab_golden_test.dart --update-goldens --plain-name "라이트"
```

- Pretendard를 직접 로드하고 ko 번역을 초기화한다 — 안 하면 글자가 네모로, 문구가 i18n 키로 찍혀 실제와 전혀 달라진다
- **Material Icons는 안 실린다.** 아이콘이 네모로 나오는 것은 렌더 한계이며 실제 앱에서는 정상이다
- ⚠️ 라이트·다크를 **한 번에 돌리면 다크가 백지**로 나온다(원인 미확정). 갱신은 `--plain-name`으로 하나씩
