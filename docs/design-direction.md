### 0-이전. 솔리드 다크/라이트 2벌 (A안 2차, 2026-08-14 오후 — 저녁에 B안으로 교체)

**다크/라이트 2벌 — 솔리드 문법 동일, 값만 반전. 전역 다크 고정 철회(2026-08-14 오후).** 같은 날 오전 리뷰 수정(`6848e6e`)에서 `AppTheme.light`를 지우고 `themeMode: dark`로 못 박았는데, 사용자가 다크/라이트 구분을 요구해 되돌리며 제대로 만들었다. 색 토큰은 전부 `lib/core/theme/glass_palette.dart`의 **`GlassPalette`(ThemeExtension) 인스턴스 필드**로 옮겼고(`GlassPalette.dark` = 기존 값 그대로, `GlassPalette.light` = 웜 그레이 바닥 `#F4F5F9`·흰 표면·검정 8% 테두리·**딥 네이비 활성 타일 `#1E2640`**·텍스트 `#14181F`·기기 틴트는 밝은 바닥 대비로 채도 조정), 소비처는 `context.glass.overlay`처럼 현재 테마에서 꺼낸다. **`AppTheme.glassX` 정적 색 상수는 삭제**했다 — 두 벌이 남으면 라이트에서 다크 값이 샌다. 모드는 `themeModeProvider`(Hive `app_settings/theme_mode`, 기본 **시스템**)가 고르고 프로필 화면의 "화면 모드" 세그먼트(시스템/라이트/다크)로 바꾼다. 차트 토큰(밤 띠·격자·미도래 밴드·마커)도 밝기별 값을 팔레트가 든다. 라이브 영역(`liveSurface`)만 두 모드 공통으로 어둡다(영상 뷰포트). 랩 A·B(`/design-test`)도 토큰을 2벌 인스턴스로 바꾸고 셸 상단 ☀️/🌙 토글을 달았다(랩 로컬 state, 기본 시스템 밝기).

**2026-08-14 결정: A안 개선 · B안 유지 · C안 폐기.** A안 1차(Liquid Glass)의 유리(반투명 오버레이 + blur + 그라데이션 월페이퍼 + glow)를 **전부 걷어내고 솔리드하고 차분한 면**으로 바꿨다. 이유: ① **차분함** — 유리·글로우가 야간 관측소 성격(§2)보다 장식으로 읽혔다 ② **가독** — 반투명 표면 위 텍스트 대비가 배경 위치마다 달라졌다 ③ **성능** — 독의 BackdropFilter saveLayer. 바닥은 정적 단색(`#141A2E`), 표면은 불투명 네이비 그레이(`#1E2640` / strong `#242D4A` / faint `#1A2138`), 테두리는 흰 8%, radius 26→20, 기기 틴트 4종은 채도·명도를 낮췄다. **토큰·위젯 이름의 `glass`는 역사적 명칭**이다 — 33개 소비처가 참조하므로 이름은 두고 값·내부만 바꿨다(`GlassCard.blur`는 `@Deprecated` no-op). 아래 1차 서술 중 "유리·blur·그라데이션·glow"는 더 이상 유효하지 않고, 위계 문법(활성=밝은 불투명면, 타이포 위계, 플로팅 독, 밤 띠)은 그대로다. 홈 상단 카메라 영역은 같은 날 풀블리드 4:3으로 넓혔다.

**1차(2026-08-13) 기록 — A안(Apple Home iOS 26 문법)을 전면 적용했다.** 디자인 랩 3안 비교(`/design-test`, `lib/features/dev/design_lab/` — **비교 페이지로 존치**)에서 사용자가 A안을 골랐고, 4탭 전부 + 보조 라우트가 이 시스템으로 넘어왔다.

새 시스템의 문법 (토큰 SOT: `lib/core/theme/app_theme.dart`의 "Liquid Glass" 섹션):

- **월페이퍼가 바닥** — 딥 그라데이션(`glassWallpaperTop→Mid→Bottom`, 네이비→틸) + 은은한 glow. 구현 `shared/widgets/wallpaper_background.dart`
- **UI는 유리 표면** — blur 24 + 흰 오버레이(~14%) + 얇은 테두리. `GlassCard`/`GlassChip`/`GlassDock`/`GlassSegmentedControl`/`GlassTabHeader`/`GlassPageShell`
- **활성은 유리가 아니라 불투명 흰색**(`glassActiveTile`) — 켜짐/선택을 면으로 말한다
- **기기 틴트 4종**(히터 주황·분무 파랑·LED 노랑·팬 민트)은 활성 타일 아이콘·센서 칩에만
- **타이포 위계는 유리 전용 스타일**(`glassHeaderTitle` 28 ~ `glassTileStatus` 13, Pretendard)
- ~~**라이트/다크 분기가 없다**~~ → **2026-08-14 오후 철회.** 다크/라이트 2벌(`GlassPalette`), 모드는 시스템/수동 3단(위 §0 머리). 화면별 `Theme(data:)` 래핑은 여전히 하지 않는다 — 4탭 루트 프레임은 `GlassTabShell` 한 곳이 맡고 바닥색은 `context.glass.wallpaper`
- 탭바는 **플로팅 유리 독**(`GlassDock`, `extendBody: true`) — 스크롤 뷰가 `MediaQuery.padding.bottom`을 소비해야 마지막 항목이 안 가려진다

**Figma 팔레트 SOT 갱신은 후속 과제다** — 아래 §6 등 구 팔레트 서술과 Figma `Asset` 섹션(`docs/figma-final-design-transcript.md` §4)은 아직 구 시스템 기준이며, Figma 반영은 사용자 작업이 필요하다.

**홈 온습도 = 애플 날씨 행 문법 / 통계 = 연속 곡선 (2026-08-17 확정).** 홈과 통계가 같은 `EnvChart` 곡선을 두 번 보여주던 것을 걷어내고, 홈은 **애플 날씨 앱 문법**으로 바꿨다 — "지난 24시간" 시간대 스트립(`시각 / 기기 동작 아이콘 / 온도°`, 지금 + 3시간 간격 8칸, `HourlyEnvStrip`)과 "이번 주" 7행 리스트(`요일 | 분무 횟수 | 최저° | 노랑→주황 범위 바 | 최고° | 습도 평균%`, 오늘이 맨 위, 오늘 행에 현재 온도 흰 점, `WeeklyEnvRowsCard`). 이유: 홈은 **훑고 넘어가는 자리**라 숫자와 바가 곡선보다 빨리 읽히고, 통계는 시간축을 따라가며 스크럽하는 자리라 연속 곡선이 맞다 — 둘이 같은 그림이면 통계 탭으로 갈 이유가 없다. 습도는 (b) 우측 평균 숫자만(범위 바는 온도만). 범위 바 색은 애플 온도 색 그대로(`AppTheme.weatherBarWarmStart/End`), 트랙은 이번 주 전체 min~max라 행끼리 길이가 비교된다. 밤 띠(§3)는 홈 곡선과 함께 홈에서는 빠졌고 통계 탭 문법에는 원래 없었다 — 시그니처는 어젯밤 리포트·타임라인이 이어간다. 랩 A·B(`/design-test`)도 같은 행 구조로 동기화했다(`lab_weather_rows.dart`, 옷만 다름).

아래 §1~§8은 2026-08-08 작성 원문이다. **§2(야간 관측소)·§3(밤 띠)·§5(숫자 주인공)·§7(문구)·§8(품질)은 여전히 유효**하고, §4(카드를 줄인다)·§6(구 팔레트 적용 범위)은 **구 시스템 서술**로 남긴다 — 유리 문법에서는 "카드 없음" 대신 "유리 카드 vs 불투명 활성면"으로 위계를 가른다.

## 1. 무엇을 고치려는 것인가

기존 화면이 "별로"였던 원인은 취향 문제가 아니라 **구조 문제**였다. 근거:

| 증상 | 실제 코드 |
|---|---|
| 눈이 어디로 갈지 모른다 | 온습도·차트·제어가 전부 같은 `Card` + `padding 16` + `radius 16`. **위계가 없다** |
| 가장 중요한 숫자가 안 보인다 | `현재 24.5°C`가 `titleMedium`(~16px) — 본문과 같은 크기 |
| 차트가 정보를 못 준다 | 높이 64px에 온·습도 두 선이 겹침. 형태가 뭉개져 **통계로 넘어갈 이유가 안 생긴다** |
| 문구가 시스템 말투 | `"차트 터치 시 통계 탭으로 이동 ›"` — 시스템이 자기 동작을 설명한다 |
| 제어 상태를 훑을 수 없다 | ON/OFF가 **텍스트로만** 구분됨. 타일 생김새가 동일 |

## 2. 이 앱은 무엇인가

**귀여운 반려동물 앱이 아니라 야간 관측소다.**

- 개체가 야행성이라 사용자는 **밤에** 앱을 켜고, 아침에 "간밤에 뭐 했나"를 읽는다
- 게코는 꼬리를 흔들지 않는다. **데이터가 사용자와 개체 사이의 거의 유일한 대화 수단**이다
- 히터 과열은 폐사로 이어진다. 이 앱의 숫자는 장식이 아니라 생사에 걸린 정보다

이 성격이 아래 결정 전부의 근거다.

## 3. 시그니처 — 밤 띠 (Night Band)

**시간축을 쓰는 모든 차트에 `22:00~06:00`을 배경으로 깐다.**

- 기획안 §3.1 ②가 정한 **활동 집계 창**과 정확히 같은 구간이다. 즉 **장식이 아니라 규칙의 표시**다
- 사용자는 "그래프의 어디가 우리 애가 사는 시간인지"를 읽지 않고 알아본다
- 주행성 반려동물 앱에 옮기면 **의미를 잃는다** — 이 앱에서만 성립하는 요소다
- 메인컬러 `#192553`이 마침 한밤중 하늘색이라는 점을 활용한다

**제약**: 데이터 선을 절대 가리지 않는다. 라이트는 `brandNavy` 10%, 다크는 `brandNavyDark` 18% — 다크 배경에 원본 남색을 더 깔면 아무것도 안 보인다. 구현: `GlassPalette.nightBand`(`context.glass.nightBand`), `shared/domain/night_band.dart`.

띠 옆에 범례(`밤 10시–6시`)를 한 번 붙인다. 색만 깔면 *"왜 저기만 어둡지?"*가 된다.

## 4. 위계 — 카드를 줄인다

세 요소가 같은 무게였던 것이 문제였으므로, **무게를 다르게** 준다.

| 요소 | 담는 그릇 | 이유 |
|---|---|---|
| 현재 온·습도 | **카드 없음.** 화면에 직접 | 가장 중요하니까 가장 먼저 보여야 한다 |
| 24시간 차트 | **카드 없음.** 폭 전체 | 두 선의 *관계*가 읽혀야 한다. 좁은 카드 안에서는 뭉개진다 |
| 제어 4종 | 타일(카드) | 누르는 것이므로 경계가 필요하다 |

## 5. 타이포 — 숫자가 주인공

Pretendard 고정. 크기·굵기로 역할을 가른다.

| 역할 | 스펙 | 쓰임 |
|---|---|---|
| **Readout** | **48px / Bold / tabular figures** | 현재 온·습도. 화면에서 가장 큰 글자 |
| 단위 | 20px / SemiBold / muted | `°`, `%` |
| 타이틀 | 18px / SemiBold | 섹션 |
| 본문·라벨 | 14px | |
| 캡션 | 12px / muted | 축 라벨, 최고/최저, 범례 |

**`tabular figures` 필수** — 값이 1초마다 바뀌는데 비례폭이면 숫자가 좌우로 흔들린다.

**48px는 이 방향의 리스크다.** 상단 1/3을 숫자 둘이 차지한다. 보통은 카드에 담아 정리하는데 반대로 갔다. 근거: 밤에 어두운 방에서, 손에 든 폰을 멀리서도 읽어야 하는 숫자다.

> ⚠️ 큰 글자는 가장 먼저 넘친다. **잘라내지 말고 `FittedBox(scaleDown)`으로 줄인다** — 숫자를 ellipsis로 자르면 값이 달라 보인다(`24.5` → `24…`).

## 6. 색 — 데이터에만 쓴다

Figma 팔레트를 바꾸지 않고 **적용 범위만 좁힌다.**

- **채색은 온도(`#ff3752`)·습도(`#8abcfc`) 둘뿐.** 나머지는 무채색
- 지표 색은 **숫자가 아니라 라벨 앞 점**에만. 숫자를 칠하면 값에 따라 색이 변하는 것처럼 오해된다. 아래 차트 선 색과 이어지는 연결고리만 있으면 충분하다
- **동작 마커(분무·팬·히터·LED)는 무채색.** 기기마다 색을 주면 온·습도 선과 색이 경쟁해 정작 읽어야 할 곡선이 묻힌다
- 제어 타일: 켜짐 = `brandNavy` 채움 / 꺼짐 = 흰 바탕 + `lineColor` 테두리 (Figma Button 규격 §4.3). **색으로 먼저 보이고 글자가 확인해주는 순서**

## 7. 문구

- 시스템 동작 설명 → 사용자 행동으로. `차트 터치 시 통계 탭으로 이동 ›` → **`통계 보기 ›`**
- 값이 없으면 `0`이 아니라 **`--`**. 0은 실측처럼 보이는데 이 앱에서 0°C는 센서 오프라인 센티넬이다
- 최고/최저는 둘 다 있을 때만 낸다. `-- / 23.5` 같은 반쪽은 읽는 사람을 헷갈리게 한다
