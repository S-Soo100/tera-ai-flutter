# Clarity 정책 — 기획자가 알아야 할 것

2026-09-12 · **목적은 합의됐고, 아래 운영 방식은 제안이다. 앱에 적용됐다는 뜻은 아니다.**

## 1. 세 가지 질문에 답한다

**Clarity는 사용자가 앱에서 무엇을 했는지 보고, 개선할 곳을 찾는 데 쓴다.**

| 질문 | 무엇을 볼까? | 어떻게 판단할까? |
|---|---|---|
| 어디서 막히나? | 하려던 일을 끝내지 못하고 반복 누르기·대기·재시도가 생긴 장면 | 정상적으로 끝낸 장면과 비교해 원인을 찾는다. |
| 무엇을 많이 쓰나? | 기능을 직접 선택해 사용한 앱 이용 기록 수 | 같은 기간·앱 버전끼리 비교한다. 쓸 기회가 있었는지도 함께 본다. |
| 무엇을 좋아하나? | 북마크·저장한 영상 다시 보기·공유 같은 자발적 행동 | 선호의 단서로 보고, 필요하면 사용자에게 이유를 물어 확인한다. |

‘앱 이용 기록’은 Clarity가 묶은 한 번의 이용 단위다. 기록 하나가 사람 한 명을 뜻하지 않는다. ‘리플레이’는 그 이용 과정을 다시 보는 기능이다.

## 2. 해석할 때 다섯 가지만 지킨다

1. **자동으로 보인 화면과 직접 사용한 기능을 구분한다.** 자동 재생은 별도로 보고, 같은 기록에서 반복 클릭해도 사용 기록은 1건으로 센다.
2. **많이 쓰는 것과 좋아하는 것은 다르다.** 긴 체류는 로딩 때문일 수 있고, 좋아요는 특정 영상에 대한 반응일 수 있다. 공유창 열기는 공유 완료가 아니다.
3. **적게 쓰는 이유부터 확인한다.** 기능이 안 보였거나, 기기·영상이 없어서 못 썼을 수 있다. 사용량만 보고 기능을 없애지 않는다.
4. **확인한 것만 말한다.** 기록 종료는 포기의 증거가 아니다. 골라 본 몇 건으로 전체 실패율을 말하지 않고, 측정되지 않은 값은 ‘확인 불가’로 적는다.
5. **시도와 성공을 구분한다.** 연결 버튼을 누른 것, Wi-Fi가 연결된 것, 라이브가 재생된 것은 서로 다른 결과다. 제어 요청 접수를 실제 기기 동작 완료로 보지 않는다.

## 3. 기획자는 매주 이렇게 쓴다

1. **질문 하나를 고른다.** 예: “카메라 연결 중 어디서 멈추는가?” 기간과 앱 버전을 정한다.
2. **확인된 숫자와 장면을 본다.** 기능별 사용량을 살펴보고, 선택한 흐름의 문제 장면과 정상 장면을 비교한다. 기능별 측정이 준비되지 않았다면 확인 가능한 리플레이 관찰만 한다.
3. **개선할 것 하나를 남긴다.** 아래 네 줄에 기록하고, 변경 후 같은 기준으로 다시 본다.

| 남길 내용 | 적는 방법 |
|---|---|
| 본 사실 | 기간·버전·확인한 기록 수와 실제 화면 반응 |
| 내 해석 | 막힌 이유 또는 좋아할 것 같은 이유. 추측임을 표시 |
| 바꿀 것 | 개선안 하나와 담당자 |
| 다시 볼 것 | 확인할 결과와 날짜 |

예시(실제 관찰 아님): **연결 버튼을 반복해서 누름 → 진행 여부를 모를 수 있음 → 진행 안내 개선 → 배포 후 같은 구간의 반복 누르기와 연결 결과 확인.**

## 4. 준비와 보호는 담당자를 나눈다

| 담당 | 할 일 |
|---|---|
| 기획자 | 세 질문으로 관찰하고 개선안을 만든다. 이용 기록을 공개 공유·다운로드하지 않는다. 개인 정보가 보이면 공유를 멈추고 운영 담당자에게 알린다. |
| 개발 담당자 | 테스트와 운영 데이터를 구분하고, 기능별 ‘사용’과 ‘성공’을 일관되게 측정한다. 민감한 내용을 가리고, 계정 전환 시 다른 계정의 기록·선택이 섞이지 않게 검증한다. 분석 도구 오류가 앱 이용을 막지 않게 한다. |
| 운영 담당자 | 수집 시작 기준과 열람 권한을 정하고, 보관·삭제·수집 중단 방법을 확인한다. 기획자에게 볼 수 있는 데이터와 한계를 알려준다. |

**보호 원칙 제안:** 로그인·가입·계정 관리 화면은 초기 수집에서 제외한다. 이메일·Wi-Fi 정보·이름·입력한 글·사진·영상 등 사용자 내용은 가리고, 별도 분석 데이터에도 넣지 않는다. 계정 ID 연결은 초기 범위에서 제외한다.

기획자는 개발·운영 담당자의 보호 검증이 끝난 범위만 열람한다. 보관 기간과 삭제 가능 범위는 운영자가 확인한다. 수집을 중단해도 이미 전송한 기록이 자동으로 삭제됐다고 간주하지 않는다.

## 5. 지금 어디까지 준비됐나?

| 항목 | 현재 상태 |
|---|---|
| Clarity를 앱에 연결 | 코드에서 확인됨 |
| 실제 리플레이와 민감 정보 보호 | 확인 필요 |
| 기능별 사용량·성공/실패 측정 | 추가 구현과 확인 필요 |
| 운영 수집 시작 기준 | **미확정.** 사용자 동의 후 시작을 제안한 상태 |
| 운영 권한·보관·삭제·중단 절차 | 확정과 검증 필요 |

**운영 분석은 담당자가 수집 기준·보호·데이터 확인을 마친 뒤 시작한다.** 동의 방식을 택한다면 거부·철회가 앱 사용을 막지 않아야 한다. 이 문서 수정으로 현재 수집 설정이 바뀌지는 않는다.
