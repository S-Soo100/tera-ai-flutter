# 디자인 테스트 공개 설계 — 테스트 유저용 A/B/C 체험 (2026-08-14)

> 목적: 테스트 유저가 **로그인 없이** 비바나트 디자인 3안(A: Apple Home Liquid Glass /
> B: Flighty / C: Copilot)을 4탭 풀 체험으로 비교하게 한다.
> 결정(2026-08-14 사용자): ① 접근 = 비로그인 공개 ② 선호 수집 = 인앱 수집 없음(구두/채팅)
> ③ 라이브 = 번들 루프 영상. **체험 전체가 mock** — 라이브 영상·사육장 제어·그래프 모두
> 실 서버를 건드리지 않는다(랩 격리 유지).

## 1. 체험 흐름 (유저 관점)

```
[로그인 화면] "디자인 미리보기" 링크(둘러보기 아래)
   → [선택 화면] "모든 데이터는 데모입니다" 안내 + A/B/C 카드
      → 각 시안: 4탭(홈/통계/마이크레/커뮤니티) 풀 체험
         · 홈: 루프 영상 라이브 + mock 제어 타일(탭=로컬 토글, 실명령 미발행)
         · 통계: mock 온습도 그래프(시안별 문법)
         · 뒤로가기(엣지 스와이프) → 선택 화면 → 다른 시안
```

- 피드백은 화면에 넣지 않는다 — 구두/채팅 수집 결정. 선택 화면 안내문에
  "느낀 점은 운영자에게 알려주세요" 한 줄만.

## 2. 신규 작업

### 2.1 A안 mock 셸 (핵심 — 공정 비교의 전제)
현재 A안은 실앱(실데이터)이고 랩에는 홈 1장뿐이라, 계정·기기 없는 테스트 유저는
A안을 제대로 볼 수 없다. **B·C와 같은 방식의 A안 4탭 mock 셸**을 만든다:
- `variant_a_shell.dart` — 유리 독 탭바(실앱 문법), IndexedStack 4탭
- `variant_a_stats_screen.dart` — 실앱 통계 구성(기간 세그먼트+지표 칩+주간 그래프)을
  A 토큰·fixtures로 재현
- `variant_a_pets_screen.dart` / `variant_a_community_screen.dart` — 실앱 구성 미러
- 기존 `variant_a_home_screen.dart`는 셸 탭0으로 흡수(장식 독 → 셸 탭바로 대체)
- **B·C와 동일 fixtures** 사용. 랩 격리 유지(variant_a_tokens만, AppTheme 미참조)

### 2.2 mock 라이브 루프 영상
- `assets/videos/mock_live.mp4` (5~10초, 무음) — 실 motion_clips에서 짧은 클립 1개를
  받아 번들(사용자 본인 계정 영상이라 문제 없음. 몇 MB 증가)
- `mock_live_player.dart` — video_player 무한 루프·무음·컨트롤 없음 + LIVE 배지 +
  타임스탬프. A·B 홈의 라이브 영역 공용(C는 라이브 영역 없음 — 현행 유지)
- 로드 실패 시 현행 그라데이션 플레이스홀더로 폴백(테스트가 영상 하나에 안 죽게)

### 2.3 공개 진입
- 라우트 `/design-test`(공개, `kPublicPaths` 추가) = 선택 화면. 기존 `/dev/design-lab`
  경로는 이것으로 **교체**(같은 화면 두 경로 불필요, 문서·습관만 갱신)
- 로그인 화면 하단 "디자인 미리보기" 텍스트 버튼(ko.json 키) → `context.push('/design-test')`
- 선택 화면 문구를 테스트 유저 대상으로 개편: 데모 데이터 안내 + 시안 요약

### 2.4 롤백 스위치 (테스트 종료 시)
로그인 화면 진입점 1줄 + `kPublicPaths` 1줄 제거로 일반 사용자에게 숨김.
랩 자체는 개발 자산으로 존치. 이 두 줄 위치를 본 문서에 기록해 두는 것으로 충분
— 별도 feature flag는 과잉.

## 3. 하지 않는 것
- 실 서버 연동(명령·텔레메트리·Realtime) — 체험은 전부 로컬 mock
- 인앱 투표/설문 — 수집 안 함 결정
- 계정 생성 유도 — 비로그인 체험이 목적
- C안 라이브 영역 신설 — Copilot 문법에 라이브가 없고, 비교 대상은 문법이지 기능 아님

## 4. 구현 순서 (Critical — flutter-dev)
1. mock_live_player + 영상 에셋 + A·B 홈 배선 (커밋 1)
2. A안 셸 + 통계/마이크레/커뮤니티 3화면 (커밋 2)
3. `/design-test` 공개 라우트 + 로그인 진입점 + 선택 화면 개편 + 버전 bump (커밋 3)
- 각 커밋 analyze 0 + 테스트 통과, 시뮬레이터 눈검증(비로그인 흐름 전체) 후 push

## 5. 리스크
- 영상 에셋 용량(수 MB) — 짧은 클립 1개로 제한
- 공개 라우트에서 실 provider 접근이 없어야 함 — 랩 격리 규칙이 이미 보장,
  리뷰에서 grep 재확인
- `/dev/design-lab` 경로 교체로 갱신할 문서: CLAUDE.md 라우트 표, design-lab-benchmark-specs.md
