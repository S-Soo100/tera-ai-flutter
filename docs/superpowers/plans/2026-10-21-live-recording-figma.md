## 2. 사용자 체험 흐름

**세로 확대 화면(카메라 라이브 확대 버튼 → `/crecam/cameras/:id/live`)**
1. 위: 닫기(X) + 카메라 이름. 영상(4:3, 좌우 12 여백 r12) 오른쪽 아래에 가로 전환 버튼(영상 위에 겹침).
2. 아래 목록:
   - **실시간 녹화** / 부제 "최대 2분" / 오른쪽 [◉ 녹화 시작] 알약(회색 면).
   - **카메라 180° 회전** / 부제 "회전 켜짐·꺼짐" / 빨간 토글(기존 PATCH 흐름).
   - **전원** / "ON" / [켬|끔] — 기기 상세와 같이 ON 고정, 명령 없음.
   - 맨 아래 [카메라 재시작] — 할 수 있을 때만 빨갛게(오프라인에서 재시작 가능 조건이면 활성), 아니면 흐림.
3. [녹화 시작] → 알약이 검정 [■ 녹화 중단]으로, 부제가 "녹화 중 00:01"로 올라간다.
4. [녹화 중단] 또는 X·뒤로 → 확인창 "녹화를 중단하시겠습니까? / 중단 시점까지의 녹화 영상이 저장됩니다" [아니요][중단하기].
5. 2분이 되거나 [중단하기] → 토스트 "녹화 영상 저장 완료"(체크, 영상 선택과 같은 `showClipToast`). 알약은 [녹화 시작]으로 돌아간다.
6. 오프라인·연결 전: 영상 자리에 "카메라가 꺼져 있거나 인터넷에 연결되지 않았습니다"(단어 단위 줄바꿈) + [카메라 재연결][네트워크 변경](최대 폭 175). 이때 가로 전환 버튼은 숨김. 녹화·회전·전원 줄은 흐리고 누를 수 없다.

**가로(전환 버튼)**
1. 닫기(좌상), [◉ 녹화 시작] 알약(우상), 축소(우하)만 둔다 — 회전 버튼은 가로에서 뺀다(Figma 메모).
2. 녹화 중 우상 알약은 검정 [● 00:01].
3. 조작 버튼은 **5초 뒤 사라지고**, 화면을 탭하면 다시 나온다. 녹화 중에도 같다(알약 포함 — Figma 1525:5830 빈 화면).
4. 세로↔가로를 바꿔도 녹화는 이어진다.

**끊김:** 영상이 끊기거나 재연결·시청 제한·다른 기기 전환·백그라운드 → 그때까지 저장하고 "연결이 끊겨 N초까지 저장했어요"(기존 문구 유지, Figma 밖).

**보관함:** 북마크 목록에 녹화 카드("직접 녹화 · 1:12" 배지). 업로드 전엔 "업로드 대기", 업로드 실패 계속이면 같은 표시 + 재시도는 자동. 카드 삭제 → 서버에서도 삭제. 선택 모드 동안 녹화 카드는 감춘다(병합 시 결정).

**업로드(E) 보완**
- owner별 대기열. 로그아웃·계정 전환 시 진행 중 업로드 정지, 로컬 녹화 목록은 owner 필터.
- 오류: 등록 400 = "업로드 실패"(재시도 없음, 카드 표시) / PUT 403 = URL 만료로 보고 재등록(같은 `client_id`) / complete 409 `upload_missing` = 처음부터 / 401 = 토큰 갱신 후 1회 / 409 quota = 보류 / 5xx·망 = 지수 백오프.
- 재등록 응답 `recording_id`가 바뀌면(23.5시간) Hive 값 교체 후 처음부터. Hive에 `recording_id` 저장(다음 릴리스 F의 중복 제거에도 사용).
- 보류 재평가: 앱 시작·녹화 직후·보관함 진입·카드 삭제 뒤. 보류분은 오래된 것부터 순서대로, 409 quota가 나면 그 자리에서 멈춤.
- 삭제 상태 기계: 미등록 → 파일만 삭제 / 업로드 중 → 업로드 취소 후 DELETE / DELETE 실패 → Hive에 "삭제 예정" 표시, 다음 실행에 재시도, 404는 성공.
- 영구 실패 카드: "업로드 실패" + 길게 눌러 삭제.

**검증 추가:** 확인창 중 녹화 종료, 3초 미만 중단, 계정 전환 시 업로드 정지, 삭제 상태 기계 단위 테스트. G996 체크리스트에 끊김 4종(회전 토글 시도·재시작 시도·시청 제한 종료·백그라운드) + 세로↔가로 전환 중 녹화 유지.

## 10. P단계 실측 결과 (2026-10-21, G996)

- 1차(1.5Mbps 요청, 하드웨어 Exynos): Android VQApply가 VBR 하한으로 **3.98Mbps** 강제 → 2분 119.7초 **54MB**(741프레임, 6.2fps). CBR 미지원, 하한 끄는 키는 앱에서 무효.
- 해결: CBR 미지원 하드웨어면 소프트웨어 인코더(`c2.android.avc.encoder`) + CBR 1.5Mbps → 40.9초 **4.9MB**(0.97Mbps) → 2분 약 15MB. 서버 크기 한도 30MB 안. 화질 차이 작음.
- 2026-10-20의 2.5Mbps 패치는 삼성에서 효과가 없었다(기록 정정).
- 남은 확인: 2분 동안 발열·끊김(소프트웨어 인코딩), 실제 iPhone 녹화(사용자 기기 필요).
- 2분 확인(소프트웨어 인코더): 파일 113.2초·**13.6MB**(0.96Mbps, 708프레임 6.3fps), 오류 없음, 배터리 32.8℃. 타이머 120초보다 파일이 약 7초 짧다(인코더 첫 프레임까지 지연) → E에서 `duration_ms`는 타이머가 아니라 **파일 실제 길이**로 등록한다.

## 11. E단계 실서버 스모크 (2026-10-21, G996, 0.156.0+424)

- 앱 시작 대기열: 60초 이하 3건 `POST /recordings 201 → PUT 영상 200 → PUT 썸네일 200 → complete 200 → ready`, DB `live_recordings` status=ready 확인. 60초 초과 4건은 `blocked(length)` → 보관함 "업로드 대기".
- 삭제: 재생 화면 삭제 → `DELETE 204` → DB 행 없음 확인.
- 남은 것: 실제 iPhone 녹화, 서버 120초 반영 후 상수 상향, F(다른 폰 목록) 다음 릴리스.
- **서버 120초 반영 확인(2026-10-21, terra-server #23):** G996 85초 녹화 → `POST 201 → PUT 200×2 → complete 200 → ready`, DB `duration_ms=85172`·`size_bytes=5444573`(5.4MB)·1280×960·썸네일 있음. 앱 `kServerRecordingMaxMs=120000`(0.156.0+425). 120초 반영 전 400으로 실패 표시된 테스트 녹화 3건은 그대로 둔다(실사용자 없음).

## 12. iPhone 미검증 이슈 (2026-10-21) — iOS는 당장 배포하지 않음(사용자 결정)

- **현상:** iOS 녹화(`FlutterRTCMediaRecorder.m`, AVAssetWriter)에 1.5Mbps·키프레임 5초를 지정해도 iPhone 13 mini 시뮬레이터에서 **2.7~2.9Mbps**(42.9초 14.4MB, 67.2초 24.1MB)가 나온다 → 2분 약 43MB로 서버 크기 한도 30MB를 넘는다.
- **시도:** `AVVideoExpectedSourceFrameRateKey`·`AVVideoAllowFrameReorderingKey`를 넣으면 녹화 도중 `-11800`(내부 `-12419`)로 매번 실패해 뺐다. 지금은 평균 비트레이트 + `AVVideoMaxKeyFrameIntervalDurationKey: 5`.
- **확인된 것:** 시뮬레이터에서 녹화·저장·R2 업로드(502 뒤 재시도 성공)까지 동작. Figma 화면 수치 일치.
- **미확인:** 실제 iPhone(하드웨어 인코더)의 비트레이트, 원격 트랙 녹화 안정성.
- **iOS 배포 전 할 일:** 실제 iPhone으로 1분 녹화 → 분당 15MB 이하면 그대로. 넘으면 VTCompressionSession으로 직접 인코딩하고 `kVTCompressionPropertyKey_DataRateLimits`를 건다(패키지 사본 수정).
- **안전장치:** 30MB 넘는 녹화는 앱이 업로드하지 않고 보관함에 "업로드 실패"로 남긴다(서버 400 방지). 로컬 재생은 된다.
- 코드 표기: `lib/features/my_cage/domain/live_recording.dart` `kLiveRecordingEnabled` 주석, `FlutterRTCMediaRecorder.m` 주석.
