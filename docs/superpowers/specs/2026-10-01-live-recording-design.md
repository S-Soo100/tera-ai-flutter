# 라이브 직접 녹화 기획 (초안, 2026-10-01)

> 상태: **1단계(기기 안 녹화·보관) 구현 — 브랜치 `feat/live-recording`, 0.151.0.** 실험 기능이라 `kLiveRecordingEnabled`(`my_cage/domain/live_recording.dart`)로 끈다. Figma 밖 기능(사용자 결정). 2단계(R2 업로드)는 서버 계약 대기.

| Q4 짧은 녹화 | 3초 미만 버림 |

## 2. 사용자 체험 흐름

1. **[화면]** 가로 전체화면 라이브, 영상이 나오는 중(`streaming`). 우측에 녹화 버튼(빨간 원).
   영상이 아직 안 나오거나(`connecting`·`recovering`·`failed`·`limited`) 시청 제한 종료까지 60초 미만이면 버튼 흐림.
2. **[조작]** 녹화 버튼 탭.
   **[반응]** 버튼이 정지 아이콘으로 바뀌고 상단에 `● REC 0:42` 남은 시간 카운트다운 + 둘레 진행 링.
   **[감정]** "지금 찍히고 있구나"가 분명해야 한다.
3. **[조작]** 기다리거나, 정지 버튼으로 일찍 끝냄(→ 미결 Q1).
   **[반응]** 60초가 되면 자동 종료 → 알약 안내 "녹화 저장 중…" → "보관함에 저장했어요 · 보기".
4. **[반응]** 업로드는 뒤에서 진행. 화면을 나가도 계속되고, 실패하면 보관함 카드에 "업로드 대기·다시 시도" 표시. 로컬 파일은 업로드 전에도 보관함에서 재생된다.
5. **끊김:** 연결 끊김(영상 없음 단계)·재연결(새 renderer)·15분 제한·다른 기기로 시청 전환·화면 이탈·앱 백그라운드 → 그 시점까지 저장, 안내 "연결이 끊겨 N초까지 저장했어요". 3초 미만이면 버린다(→ Q4).

## 3. 기술 구조

- **녹화:** `MediaRecorder.start(path, videoTrack: 원격 트랙)` → 60초 타이머 → `stop()`. 오디오 없음(카메라 무음).
  ⚠️ **iOS 원격 트랙 녹화 지원이 불확실** — 구현 전 **선행 검증(§5 0단계)** 필수. 안 되면 iOS는 버튼 숨김으로 출시하고 Android 먼저.
- **녹화와 시청 로직 분리:** `LiveRecordingController`(신규, my_cage/presentation)가 `WebRtcLiveController` 상태를 구독해 끊김 시 정지. 세대(`_gen`)가 바뀌면 그 녹화는 종료(이어 붙이지 않음).
- **보관함 연동:** 현 북마크는 `motion_clips.clip_id` 기준(`FavoriteClip` 로컬 mp4 + `favorite_clips` 클라우드). 직접 녹화는 서버 행이 없으므로 **서버가 녹화 행을 만들어 id를 줘야** 같은 보관함에 섞을 수 있다.
- **R2 업로드:** 앱에는 R2 쓰기 권한이 없다 → 서버 요청 필요(§4).
- **썸네일:** 녹화 끝에 첫 프레임 로컬 생성, 함께 업로드.

## 4. 서버 요청 (petcam / terra-server)

1. `POST /recordings` → `{recording_id, upload_url(presigned PUT), thumb_upload_url}` — 카메라 소유 확인.
2. 업로드 완료 `POST /recordings/{id}/complete` (크기·길이·started_at).
3. 저장 위치: `motion_clips`에 `source='manual'`로 넣을지 별도 테이블일지 → 하이라이트 규칙·전체 영상 목록에 섞일지와 직결(Q3).
4. 보관 기간·용량 한도·삭제 API.

## 5. 단계

0. **선행 검증(반나절):** Android·iOS 실기기에서 원격 트랙 60초 녹화 → 파일 재생 확인. 결과로 iOS 범위 확정.
1. 로컬 녹화 + 보관함 로컬 표시(서버 없이 동작).
2. 서버 계약 확정 후 R2 업로드·클라우드 보관함.

## 7. 1단계 구현 메모 (2026-10-01)

- `domain/live_recording.dart`(규칙·모델) · `data/live_recording_repository.dart`(Hive `live_recordings` JSON + 문서 디렉토리 **상대 경로**) · `presentation/live_recording_controller.dart`(녹화기 교체 심 `liveVideoRecorderFactoryProvider`) · `widgets/live_record_controls.dart`(가로 버튼·REC·결과 알약) · `live_recording_player_screen.dart`(`/crecam/recordings/:id`) · 북마크 화면 `_RecordingCard`.
- `stalled`(5초 멈춤)는 영상이 남아 있는 단계라 녹화를 끊지 않는다(멈춘 장면이 찍힌다).
- 녹화는 세로로 돌려도 이어진다(전체화면 화면 전체에서 구독). 단 세로엔 REC 표시가 없다 — 실기기 확인 후 판단.
- flutter_webrtc 1.4.1 네이티브 확인: Android·iOS 모두 원격 트랙(`peerConnectionId`)을 파일로 녹화, 사진첩 자동 저장 없음. **실기기 검증은 아직** — iOS에서 트랙을 못 찾으면 start는 조용히 넘어가고 stop이 실패 → "녹화하지 못했어요"로 안내된다.

## 8. 실기기 결과·보류 (2026-10-01)

- **Android S21+: 성공.** 60초 자동 종료, H.264 1280×960, 평균 약 6fps(369프레임), **33MB/분**(flutter_webrtc 비트레이트 6Mbps 고정). 북마크 재생 확인.
- **iOS 시뮬레이터(iPhone 17): 실패.** AVAssetWriter `-11800/-12419`로 약 2.5초 뒤부터 프레임 추가 실패 → stop 실패 → 파일 폐기·"녹화하지 못했어요". 시뮬레이터 인코더 한계로 추정, 실제 iPhone 미검증.
- **사용자 결정으로 보류.** 재개 시 할 일: ① 실제 iPhone 검증 ② 용량 축소(라이브러리 비트레이트 수정 권장 vs 녹화 후 재압축) ③ R2 업로드 서버 계약(§4). 브랜치 `feat/live-recording`은 main 미병합 상태로 유지.
