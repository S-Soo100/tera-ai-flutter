## 1. 한 줄 요약

카메라 탭의 **전체 영상 목록은 "하이라이트 규칙을 통과한 영상 전부"로 줄이고**, 그중 **밤 구간의 엄선본(대표)은 촬영 다음다음 날 아침 8시에 "하이라이트"로 공개**하며 알린다.

## 2. 왜 바꾸나

- 지금 전체 목록은 모션 클립을 거르지 않고 전부 보여준다(하루 42~220개, 최근 9일 실측). 대부분 게코가 없거나 거의 안 움직인 영상이라 **유저가 지친다.**
- 하이라이트는 조회 즉시 계산·표시돼 "도착"이라는 사건이 없다. 매일 아침 받아보는 리듬이 없다.

## 3. 확정 정책

### 3.1 전체 영상 목록 (카메라 탭 그리드 · 플레이어 필름스트립)

| 항목 | 결정 |
|---|---|
| 대상 | **하이라이트 규칙 O 전부** = 자동 규칙(`hl-rule-v0`: 움직임 ≥10초 또는 연속 ≥5초) 통과 + 사람 확정 O. 서버 `/highlights`가 주는 집합과 동일 |
| 공개 시점 | **기다리지 않는다.** GME 분석·판정이 끝나는 대로 보인다(어젯밤 영상을 오늘 아침에 볼 수 있다). 엄선본이 목록에 먼저 보이는 것은 문제 아님 — 라이브로도 다 볼 수 있다 |
| 낮 영상 | 규칙을 통과하면 목록에 나온다(하이라이트에는 안 나온다) |
| 미통과 영상 | **완전히 숨김.** "모든 영상 보기" 같은 우회로를 두지 않는다 |
| 예외 | 이미 북마크했거나 커뮤니티에 올린 영상은 그대로 유지. 활동시간 집계(마이크레·홈)는 지금처럼 **전체 클립 기준**(목록 필터와 무관) |
| 빈 목록 | 조용한 밤은 0개일 수 있다. 안내 문구로 설명한다("기준을 넘는 움직임이 없었어요"). 억지로 1개를 채우지 않는다 |

규칙 숫자는 운영자가 라벨링 웹에서 바꾼다 → 같은 영상의 목록 포함 여부가 나중에 바뀔 수 있고, 이는 의도된 동작이다.

### 3.2 하이라이트 (엄선본)

| 항목 | 결정 |
|---|---|
| 촬영 구간 | **밤만: D일 20:00 ~ D+1일 08:00 KST** |
| 공개 시각 | **D+2일 08:00 KST.** 예: 8/16 밤~8/17 아침 촬영 → 8/18 08:00 공개 |
| 검수 지연 | **기다리지 않는다.** 08:00에 그 시점의 자동 규칙+사람 확정 결과 그대로 공개. 공개 뒤 사람이 X로 확정하면 목록에서 빠질 수 있다(수용) |
| 게이트 주체 | **앱.** 공개 시각이 날짜만의 함수라 서버 상태가 필요 없다. 기기 시계·시간대와 무관하게 KST로 계산한다. 서버가 `publication`을 주기 시작하면 그 값을 우선한다 |
| 선정 기준 | 기존 그대로 — 서버 `/highlights/featured`의 대표(시간대당 최대 3, 하루 최대 15). 앱이 밤 구간 밖 대표를 뺀다(서버 옵션이 생기면 교체) |
| 도착 표시 | 공개된 최신 밤 묶음에 도착 배너(읽음·닫기는 기존 규칙: 실제 재생 진전=읽음, X=dismiss). 카메라 탭 하이라이트 카드 "업데이트 N일 전"은 **공개 시각 기준**. 단 공개된 최신 묶음을 **아직 안 봤으면 카드는 "새 하이라이트"**(배너와 같은 읽음 기준, 재생하면 "업데이트 N일 전"으로 복귀 — 2026-09-19 사용자 결정: 카드 "3일 전"과 배너 "도착했어요"의 불일치 해소) |
| 묶음 표기·재생 (구현 후 확정, 2026-09-19 `/code-review`) | 앱이 publication을 합성하므로 섹션 제목·배너 라벨은 "9월 14일 밤" 대신 **촬영 구간 날짜 범위**("2026. 9. 14 - 9. 15", Figma 1081:5235 서식), 하이라이트를 탭하면 **그 밤 묶음만** 재생목록이 되고 재생 시 그 밤이 읽음 처리된다. 사용자 결정: **그대로 둔다** |

### 3.3 알림

| 단계 | 동작 |
|---|---|
| 서버 알림 배포 전 | **앱 안 표시만** — 도착 배너 + 카드 "업데이트 오늘". 받은 알림함에는 안 쌓인다(서버가 넣는 것이라) |
| 서버 알림 배포 후 | 매일 08:00 KST, 그 밤 대표가 **1건 이상인 유저·카메라에만** `highlight.ready` 1건 → 받은 알림함 + Android 시스템 푸시. **0건이면 보내지 않는다.** 탭하면 `/crecam/highlights` |
| iOS | 시스템 푸시 없음(FCM 미지원 현행). 앱 안 표시·받은 알림함만 |

발행 주체는 **petcam-lab**(활성 GME 계약값을 가진 유일한 곳). 기존 `notification-ingest` 계약을 그대로 쓴다. 9/15에 요청한 **검수 승인 스냅샷·불변 배치 ID는 철회**한다.

## 4. 유저 체험 흐름

**아침 8시, 앱이 꺼져 있을 때(서버 알림 배포 후, Android)**
[화면] 잠금화면에 하이라이트 도착 알림(내용은 그저께 밤 촬영분) → [조작] 탭 → [반응] 앱이 하이라이트 화면으로 열리고 맨 위 도착 배너에 그 밤의 대표 썸네일 → [감정] "오늘 것도 왔네" — 매일 같은 시각에 오는 리듬.

**아침 8시 이후 앱을 그냥 열었을 때**
[화면] 카메라 탭 하이라이트 카드가 "업데이트 오늘" → [조작] 카드 탭 → [반응] 도착 배너 + 밤 묶음 목록. 배너의 영상을 실제로 재생하면 읽음 처리돼 배너가 사라진다 → [감정] 놓친 게 없다는 확신.

**전날 밤 영상을 당일 아침에 보고 싶을 때**
[화면] 카메라 탭 그리드에 어젯밤 시간대별로 **움직임이 있었던 영상만** 몇 개~수십 개 → [조작] 탭해서 재생 → [감정] 빈 영상을 넘기는 수고가 없다. 하이라이트 화면에는 아직 그 밤이 없다(내일 08:00 공개).

**조용한 밤**
[화면] 그리드가 비어 있고 "기준을 넘는 움직임이 없었어요" 안내 → [감정] 고장이 아니라 조용했다는 걸 안다. 라이브는 그대로 볼 수 있다.

## 5. 서버 의존과 단계

| 단계 | 내용 | 서버 작업 |
|---|---|---|
| **1단계 (앱 단독, 지금 가능)** | 전체 목록을 `/highlights`(cursor 페이지)로 교체 · 하이라이트 밤 필터+D+2 08:00 게이트 · 도착 배너·카드 공개 시각 기준 · 빈 목록 문구 | 없음 |
| **2단계 (petcam-lab 배포 후)** | ① 매일 08:00 `highlight.ready` 발행 ② `/highlights`에 `until` ③ `/highlights/featured` 밤 구간 옵션 | petcam-lab |

1단계에서 앱은 `until`을 **미리 보내고**(미배포 서버는 모르는 쿼리를 무시한다) 동시에 앱에서도 범위를 한 번 더 거른다 → 서버 배포 시 앱 수정 없이 빨라진다.
