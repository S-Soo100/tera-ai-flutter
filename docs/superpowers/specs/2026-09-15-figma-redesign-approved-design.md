## 1. 우선순위와 범위

1. 이 문서의 사용자 확정 결정.
2. 현재 Talk to Figma 채널 `wvkqunn6`의 `vivanaunt app` 페이지(`0:1`).
3. 기존 구현·문서. 기존 내용을 최신 결정처럼 되살리지 않는다.

대상은 Home, Camera, MyCre, 사육장·카메라 연결, 기기·그룹 관리, 개체 등록·관리 및 해당 Figma의 관련 화면 전체다. Community의 새 상세 디자인은 이 페이지에서 확인되지 않았다. 공통 내비게이션 스타일은 적용하되 별도 커뮤니티 기능 재설계는 추가하지 않는다.

Figma의 표기 `vivanaunt app`은 조사 대상 페이지 이름이고, 제품 영문명은 `vivanaut`이다. 현재 765 계열 노드의 file key를 확인하지 않았으므로 과거 다른 파일 URL에 새 node ID를 붙이지 않는다.

## 2. 공통 디자인·에셋

- 배경과 상·하단 내비게이션은 **#FFFFFF**, 카드·버튼 기본 면은 **#F4F4F4**. 이전 #FAFAFA 배경 결정보다 우선한다.
- Android에서 스크롤 전·중·후 상단 헤더·상태바 뒤가 회색으로 변하지 않는다. 원인은 아직 실기기에서 재현·확정하지 않았으므로 특정 AppBar 속성 하나로 해결됐다고 가정하지 않는다.
- 탭 헤더·하단 내비게이션은 고정, 본문은 단일 세로 스크롤. 마지막 항목이 내비게이션이나 키보드에 가리지 않는다.
- 세 탭의 좌측 상단 드롭다운 표시명: **선택 대상이 그룹에 속하면 그룹명**. 그룹이 없을 때만 **Home=사육장 이름 / Camera=카메라 이름 / MyCre=도마뱀 이름**을 표시한다. 선택된 헤더와 펼친 목록 항목에 같은 이름 규칙을 적용한다. 항목이 하나여도 드롭다운 표시와 선택 상태를 유지한다.
- 그룹명이 같아도 각 탭의 선택·조회·제어 대상은 해당 사육장/카메라/개체 ID로 유지한다. 표시명으로 대상을 식별하지 않는다. 그룹명 변경·이동·해제 후 소속에 맞게 표시명을 갱신하며, 상세 화면의 기기·개체 고유 이름을 그룹명으로 덮어쓰지 않는다.
- 표시 체험: [화면] 같은 그룹에 속한 항목은 Home·Camera·MyCre 헤더에서 모두 `사육 환경 1`로 보임 → [조작] 각 탭에서 해당 항목을 선택 → [반응] 그 탭의 사육장·카메라·개체 콘텐츠 표시 → [감정] 설정에 들어가지 않아도 같은 소속임을 알 수 있음. 그룹 없는 항목을 선택하면 해당 항목의 개별 이름으로 표시한다.
- 관리 진입 메뉴: 기기 추가 / 기기 관리 / 개체 추가·관리. 계정 버튼은 별도다.
- Figma SVG 원본을 사용한다. 임의 Material 아이콘 대체, 비율 왜곡, 다색 SVG 일괄 tint, 원형 배경 중복 그리기를 하지 않는다.
- 폰트·색상·아이콘 실제 도형 크기·부모 프레임·padding·radius·줄 높이·레이아웃을 함께 대조한다. 아이콘 파일의 viewBox와 화면 터치 영역을 동일시하지 않는다.
- 원본은 `assets/figma/2026-09-15/`: **SVG 70개 + x3 PNG 4개**, 에셋 보관 커밋 `996b349`. [manifest](../../../assets/figma/2026-09-15/manifest.json)의 SHA-256을 기준으로 원본을 보존한다.
- Empty 01~03은 1035×681 → 논리 크기 345×227. favicon은 168×168 → 논리 크기 56×56이며 80×80 카드용 고해상도 원본이라고 간주하지 않는다.
- 파일명의 `x3`만으로 Flutter 배율이 적용되지 않는다. 해상도 디렉터리 또는 명시적 scale을 설정한다. 마스크 변환이 필요하면 별도 runtime 사본을 만들고 원본 대응을 기록한다.

## 3. Home

### 상태·연결

| 상태 | 사용자에게 보이는 내용 |
|---|---|
| 사육장 없음 | Empty_03 + 기기 추가 |
| 사육장만 있음 | 온습도 → 제어 → 기기 설정. 라이브 영역과 그 여백 제거 |
| 사육장·카메라 있음 | 라이브 → 온습도 → 제어 → 기기 설정 |
| 카메라 오프라인 | 라이브 영역을 유지하고 연결 끊김·재연결 표시. 사육장 기능은 연결돼 있으면 사용 가능 |
| 사육장 오프라인 | 온습도 `--`, 마지막 수신 시각·연결 끊김 표시, 기기 제어 비활성화. 카메라가 정상이면 라이브 유지 |

사육장을 바꾸면 연결된 카메라·온습도·제어·일정·LCD 대상이 함께 바뀐다. 이전 대상의 늦은 응답이 새 대상 화면을 덮지 않는다. 재연결 후 새 상태를 받기 전에는 과거 값을 현재값으로 표시하지 않는다.

### 환기팬·냉각팬

- 꺼진 팬 탭 → 실행 시간 선택 → **시작을 눌러야 실행**. 선택·취소만으로 명령을 보내지 않는다.
- 기존 앱의 선택값은 10분 / 30분 / 1시간 / 2시간 / 계속 켜기, 최초 30분·이후 직전 선택값이다. 이 선택값은 기존 구현 기반 제안으로 검토됐으며 Figma에서 추출한 값이 아니다. 승인된 후속안은 시간 선택창을 유지하는 것이다. 구현 시 기존 선택값을 유지하고 디자인 보완 대상으로 관리한다.
- 켜진 팬 탭은 끄기, 진행 중 타이머 취소. 두 팬의 선택값·타이머·알림 식별자는 분리한다. 타이머 자동 종료는 펌웨어 책임이다.
- 냉각팬의 ‘준비 중’ 제안은 **철회**. 전달 문서에 서버·펌웨어·DB 반영 완료가 명시돼 있으며 앱에 `fan2`를 연결한다. 이 세션에서 운영 펌웨어 실측까지 했다는 뜻은 아니다.
- `fan2_on`, `fan2_off`, 필요시 즉시 제어의 `fan2_toggle`; 타이머는 `fan2_on + duration_ms`, 최대 7,200,000ms. 예약에는 절대 명령만 쓴다.
- 실제 냉각팬 상태는 `telemetry.fan2`. null이면 타일을 유지하고 `--` 표시·제어 비활성화. `devices.capabilities`의 존재하지 않는 fan2 플래그를 가정하지 않는다.
- 냉각팬 제어 기록·차트 마커를 환기팬과 별도 종류로 연결한다. 팬별 시작·종료 짝이 섞이지 않는다.

### LED

- 타일 탭 → 켜기·끄기·밝기 설정창.
- 밝기 지원 기기: **20~100%, 10% 단위**(20,30,40,50,60,70,80,90,100).
- 슬라이더 조작은 선택만 변경. ‘밝기 적용’을 눌러 전송, ‘끄기’는 별도 명령. 닫으면 변경 없음.
- 홈은 실제 보고값으로 ‘켜짐 · 50%’ / ‘꺼짐’을 표시한다. 장치가 다른 경로에서 75%를 보고했다면 현재 상태를 임의로 80%로 바꾸지 않는다. 선택창의 10% 단계와 실제 보고값을 구분한다.
- 밝기 미지원은 켜기·끄기만 제공, 밝기 값은 표시하지 않는다.

### 분무·LCD

- 홈 분무 탭은 즉시 **3초** 실행 후 자동 종료. 시간 선택·확인창 없음. 누른 뒤 **5초** 중복 입력 방지. 오프라인에서는 실행 불가.
- 분사 중 켜짐·종료 후 꺼짐. 기존 명령 잠금과 telemetry를 함께 처리하되 영구 로컬 ON으로 만들지 않는다.
- LCD 문구는 기기 이름과 **독립 저장**, **최대 20자**, 카운터 `입력 수/20`, **중복 허용**. 기존 64자 상한은 이번 앱 입력 정책에서 20자로 변경한다.
- LCD의 ‘중복되지 않는 이름’ 검증은 적용하지 않는다. 해당 오류 안내를 실제 제약처럼 표시하지 않는다.

## 4. 온습도 상세

### 일간·주간

- 오늘: 실시간 온습도 + 당일 최고·최저. 과거: 날짜별 평균 + 최고·최저.
- 유효값 없음은 `--`, 그래프는 공백. 0 채우기·결측 구간 선 연결 없음.
- 오늘 일간 그래프 초기 위치는 현재 시각 기준. 사용자가 이동한 뒤 실시간 갱신으로 되돌리지 않는다.
- 날짜 경계는 자정. 주간은 월요일~일요일, 온도·습도 각각 요일별 최고·최저 범위를 표시하고 상단에는 선택 주 전체 최고·최저.
- 이번 주는 현재까지의 유효값을 사용하며 미도래·결측 요일은 빈칸. 주간에는 제어 기록 목록을 표시하지 않는다.
- **과거 일평균**은 지표별 유효 표본 수를 사용한다. count 미제공을 임의 개수로 대체하거나 평균들의 단순 평균을 정확한 일평균으로 표시하지 않는다. 부족한 서버 집계 계약은 담당표 T3로 관리한다.

### 제어 기록: 서버 변경 없이 현재 데이터 사용 — 명시적 승인된 절충

Figma의 항목·문구는 유지한다. 아래 값은 순간 실측값이라는 보장이 없다는 점을 사용자가 설명받고 승인했다.

| 표시 | 계산·제약 |
|---|---|
| 작동 시점 온습도 | 명령 시각과 가장 가까운 유효 30분 평균값. 30분 이상 떨어진 값으로 임의 보완하지 않음. 사용할 값 없으면 `--` |
| 변화량 | 해당 팬 종료에 대응하는 평균값 − 시작에 대응하는 평균값. 짝·측정값 없으면 `--` |
| 시각 | 현재 데이터의 명령 발행 시각. 정확한 실제 작동 시각이라고 기술 문서에 주장하지 않음 |
| 과거 토글 기록 | 방향 미상이면 켜짐/꺼짐을 추측하지 않고 ‘작동’ |

짧은 동작은 같은 30분 평균에 매칭되어 차이가 0일 수 있다. 이 근사치 승인은 **제어 기록에 한정**되며 MyCre 활동 집계나 일평균 유효 개수 계약을 완화하지 않는다. 실행 성공·실패는 기존 `status`와 `result`를 함께 점검하고, 실패 명령을 성공 실행 기록으로 만들지 않는다. 냉각팬은 실제 `fan2` 기록이 있으면 표시한다. ‘냉각팬 기록 없음’은 문서 전달 이전 앱 상태 설명이었으며 후속 구현 정책이 아니다.

## 5. Camera·영상·메모

- 그룹명 드롭다운(그룹이 없으면 카메라 이름), 라이브, 하이라이트·북마크 진입, 기간 선택, 날짜·시간대별 **3열 영상 그리드**. 기본 기간은 **전체 기간**.
- 카메라 없음은 Empty_02 + 추가. 헤더·하단바 고정, 본문 스크롤.
- 일반·북마크 영상은 끝에서 정지하고 사용자 조작으로 이전·다음 이동. **하이라이트만 자동 다음 재생**.
- 세로/가로 플레이어의 삭제 버튼을 사용하고, 리스트에 새 휴지통 버튼을 추가하지 않는다.

### 북마크·메모 저장

- **북마크 목록은 기존 `clip_favorites` Supabase 동기화 유지**. ‘북마크도 로컬만’이라는 초기안은 사용자가 정정했다.
- **모든 영상에 메모 추가 가능**. 플레이어에서 편집 가능하되, 목록의 메모 카드 UI는 **북마크 목록에만** 표시.
- 북마크 저장 시 메모 유도 팝업, ‘메모 없이 저장’ 가능.
- 메모는 **계정·휴대폰별 로컬 Hive만 사용**, 서버에 메모 기능 추가 안 함. 기존 즐겨찾기 로컬 영상 보관 동작을 임의 제거하지 않는다.
- 북마크 해제 후 메모 유지, 메모 삭제 후 북마크 유지. 목록 정렬은 촬영 시각이 아닌 **북마크한 시각 내림차순**.
- 메모 색상은 Figma 6색. 최초 저장 시 직전에 새로 배정한 색을 제외한 5색에서 랜덤 배정, 첫 메모는 6색 중 선택. 수정·앱 재실행·북마크 재등록 시 색 유지. 색상 직접 선택 없음.
- ‘연속 같은 색 금지’의 적용은 이 대화에서 확정한 **신규 배정 순서**다. 삭제·재정렬 후 기존 카드의 색을 다시 칠하지 않는다. 색과 직전 배정 상태도 계정별 로컬 저장.

### 영상 삭제의 의미

- 사용자별 `user ID + clip ID` 숨김 기록을 서버에 저장해 같은 계정의 다른 기기에서도 반영.
- Camera / 하이라이트 / 북마크 / 재생 큐에서 제외. 기존 캐시도 필터에 맞춰 갱신.
- **R2 파일·원본 영상 메타·활동 통계는 삭제하지 않는다.** 시스템 검수 제외나 공유 `motion_clips` RLS에 이 숨김을 섞지 않는다.
- 사용자 숨김은 목록 필터다. 자동으로 원본 분석 판정·기존 메모·북마크 동기화 원장을 삭제하는 기능을 추가하지 않는다.

## 6. MyCre·개체 연결 이력

### 화면·집계

- 그룹명 드롭다운(그룹이 없으면 도마뱀 이름) → 선택 개체 프로필 → 일간 요약·시간별 그래프 → 주간 요약·요일별 그래프를 **한 페이지에 세로 배치**. 프로필에는 개체 이름을 유지한다. 개체 목록/리포트 탭 분리안을 유지하지 않는다.
- 개체 목록은 ‘개체 추가·관리’에서 제공. 개체 없음은 Empty_01 + 등록.
- **하루 00:00~24:00**. 기존 07시 활동일 규칙은 이 화면에서 폐기.
- 일간 총합=선택 날짜. 비교 ‘일평균 활동시간’=선택일 제외 직전 7일 중 관측 완료일 평균.
- 주간=월요일 00:00~다음 월요일 00:00. 총합에는 현재 주의 오늘 진행분 포함, 평균은 선택 주의 관측 완료일만 사용(진행 중 오늘 제외).
- 관측이 완료된 0은 포함, 미수집·미완료는 제외. 유효 분모가 없으면 `--`.
- 활동은 카메라가 검출한 활동 시간 구간의 합집합. 중복 제거, 시각 경계 분할, 시간별 합=일간 합, 일간 합=주간 합, 시간당 최대 60분. Figma의 ‘한 시간 62분’은 샘플 숫자다.
- 현재 카메라 기반 집계는 개체를 시각적으로 식별하는 모델이 아니다. 연결된 카메라의 활동을 개체 화면에 귀속시켜 보여준다. 원본 duration 또는 스칼라 `effective_activity_sec`만으로 실제 구간·관측 완료를 증명하지 않는다.

### 과거 기록·이동

- 신규 개체: 카메라 **연결 시점 이후** 활동만 표시. 이전은 ‘연결 전’, 활동 0으로 처리하지 않음.
- 동일 개체의 카메라 이동: 이전 연결 기간은 이전 카메라, 새 연결 기간은 새 카메라를 조회해 이어 표시. 연결 공백은 데이터 없음.
- **기존 사용자는 과거 활동을 계속 표시**한다. 도입 시점 이후만 보여주는 제안은 철회했다.
- 기존 연결은 실제 시작일을 지어내지 않고 **기존 데이터 승계**로 구분한다. 기능 도입 이후 변화부터 정확한 시작·종료 이력을 기록한다.
- 기존 조회 범위와 이전 리포트의 집계 범위를 migration 전에 확인한다. 과거 전체 카메라 합계를 근거 없이 특정 개체의 실측 기록으로 재작성하지 않는다. 승계 원본 범위와 출처를 보존한다.
- 기기 변경·그룹 이동·그룹 제외·개체 삭제 등 모든 연결 변경 진입점이 이력을 갱신해야 한다. 앱뿐 아니라 웹·서버 쓰기 경로도 담당자와 계약한다.

## 7. 기기 연결·기기 관리·그룹

### 연결 흐름

1. 사육장·카메라 검색 → 각각 하나 또는 함께 선택.
2. 네트워크 선택/직접 입력 → 비밀번호 → 연결.
3. 하나만 성공: 성공 기기 유지, 실패 기기만 재시도. 미루면 단일 등록 완료 화면.
4. 함께 등록하면 자동 그룹화. 완료 화면의 ‘이어서 추가’로 나머지 기기를 등록하면 앞선 기기와 묶는다.
5. 별도 추가이고 연결 대상이 여러 개면 사용자가 선택. 기존 그룹에서 이동하면 확인.
6. 두 기기가 준비되면 기존 도마뱀 연결 또는 신규 등록으로 연결. **나중에 하기 유지**, 완료된 기기·그룹을 보존하고 홈으로 이동.

- 사용자는 등록된 기기가 정상 BLE 검색에 잡히지 않는다고 설명했다. ‘추가 됨’은 디자인에만 남기며 이를 표시하려고 서버 기기를 BLE 목록에 추가하지 않는다. 등록 처리의 중복 검증은 유지한다.
- Figma의 `viva-iot-…`와 기존 프로토콜의 `terra-iot` 이름 차이를 확인한다. 표시명 변경을 BLE 프로토콜 변경으로 오인하지 않는다.
- 현재 문서의 BLE는 Wi-Fi만 전달하고 기기 token·owner는 사전 등록 방식이다. Wi-Fi 성공을 새 소유권 등록까지 성공한 것으로 표시하지 않는다. 완전 자동 신규 등록은 이관훈님과 계약 확인이 필요하다.
- ‘비밀번호 기억하기’ 체크 + 연결 성공 때만 보안 저장소 저장. 같은 계정·휴대폰·SSID에서 재사용. 미체크는 이번 연결에만 사용, Supabase 저장 없음. 기존 계정 무관 저장 구현을 이 정책에 맞춘다.

### 이름·전원

- 기기 이름: 같은 계정 내 중복 금지, 최대 10자.
- 신규 기기 기본값: `사육장 1`, `사육장 2`, `사육장 3`… / `카메라 1`, `카메라 2`, `카메라 3`…. 첫 기기도 공백과 `1`을 포함한다. 이미 사용 중인 이름을 건너뛰고, 직접 변경에도 중복 검사.
- 그룹 이름도 최대 10자·동일 계정 중복 금지. 신규 기본 그룹명은 `사육 환경 1`, `사육 환경 2`, `사육 환경 3`…이며 사용 중인 이름을 건너뛴다. Figma의 그룹 번호(생성 순서, `그룹 1` 등)와 실제 그룹 표시명(`사육 환경 1` 등)은 별개다.
- 기본 이름 변경은 신규 생성 시 적용한다. 이미 저장된 그룹·기기 이름은 자동 개명하지 않는다. 번호와 공백도 10자 제한에 포함하며, 개체 이름에 새로운 자동 번호 규칙을 추가하지 않는다.
- **기기 관리의 전체 전원 버튼은 ON 고정, 눌러도 변경·명령 없음**. 실제 기능 추가 시 연결. 연결 상태 온라인/오프라인과 별도다. 이 절충은 홈의 환기팬·냉각팬 실제 ON/OFF에 적용하지 않는다.

### 그룹 규칙

- 그룹당 사육장 1개·카메라 1개·도마뱀 **1마리**. N마리는 추후 확장으로 남긴다.
- 하나만 선택해도 생성 가능. 이름 → 구성 선택 → 최종 확인 → 생성.
- 기존 그룹 소속도 선택 목록에 현재 소속과 함께 표시. 이동 확인을 취소하면 유지, 확정하면 이동.
- ‘그룹 추가’ 표시: 미소속 기기·개체가 1개 이상이거나, 구성 총합이 2개 이상인 그룹이 하나라도 존재할 때. 둘 다 아니면 숨김. 등록 항목이 전혀 없으면 ‘기기 추가’ 표시.
- 그룹 구성 총합은 사육장+카메라+도마뱀을 센다. 도마뱀 2마리를 허용한다는 뜻이 아니다.
- 마지막 구성원 제외 후 빈 그룹은 자동 제거. 제외한 항목은 ‘그룹 없음’에 유지. 기기·개체 데이터는 삭제하지 않는다.
- ‘그룹 없음’ 표시 순서는 사육장 → 카메라 → 개체.

## 8. 개체 등록·삭제와 데이터 보존

### 등록

- 이번 신규 등록은 **크레스티드 게코와 해당 모프만** 지원. 다른 종·종 직접 입력은 추후. 기존 다른 종 DB 데이터를 삭제하거나 기존 개체를 강제 변환하지 않는다.
- 사진 선택 사항: 추가·교체·삭제. 이름 필수·최대 10자·계정 내 중복 금지. 종 필수. 모프 선택 사항·검색 가능.
- 성별 수컷/암컷/미구분, 기본 미구분. 생년월일·입양일·체중·메모 선택 사항. 그룹 미지정 가능.
- 필수값·중복 오류는 필드에 표시. 수정 중 나가기는 입력 폐기 확인.
- 2026-09-15 실제 공개 테이블 조회: `species` 17종, `morph_genetics` 3종. 크레스티드 DB 모프 17 / 라인브리딩 특성 22, 로컬 모프 23 / 특성 26. 데이터는 이미 있고 서로 다르다. `CareInfoRepository`는 로컬 JSON을 읽는다. 카탈로그 대조·출처 확인 후 등록용 기준을 통일한다.

### 삭제 — 기능과 문구의 의도된 차이

| 조작 | 실제 동작 | 문구 |
|---|---|---|
| 영상 삭제 | 사용자 목록에서 숨김, 원본·활동 집계 유지 | Figma 유지 |
| 그룹에서 제외 | 소속만 해제, 항목·데이터 유지, 빈 그룹 정리 | Figma 유지 |
| 기기 삭제 | 기기 등록·그룹 연결 해제, 기존 영상·활동 원본 보존 | Figma의 ‘기기와 연동된 데이터도 함께 삭제됩니다’ 원문을 우선 유지하도록 사용자 명시 승인 |
| 개체 삭제 | 프로필·그룹 연결 제거, MyCre에서 개체와 그래프 제거. 카메라·사육장 원본 유지 | Figma의 ‘크레 활동 데이터, 그래프도 삭제됩니다’ 유지하도록 사용자 명시 승인 |

위 문구를 근거로 물리 데이터 삭제를 구현하지 않는다. 현재 `CameraRepository.delete`/`SupabasePetRepository.deletePet`의 직접 DELETE를 그대로 재사용하기 전 FK·cascade·권한을 조사한다. 기기 삭제 후 재등록·소유자 변경으로 다른 계정에 과거 영상이 노출되지 않아야 한다.

## 9. 일정·보조 화면·공통 처리

- 일정은 선택 사육장 기준. 매일 또는 월~일 복수 선택, KST 시·분.
- 시점 예약 또는 시작~종료 구간. 월요일 22시~02시는 화요일 02시 종료로 표시·실행.
- 기존 예약 유지 + 냉각팬 on/off 추가. 분무 예약은 1/2/3초 유지. 목록에서 활성/비활성, 수정, 확인 후 삭제; 구간은 한 항목으로 취급.
- 현재 지원하는 실행 전 온습도 조건에 따른 건너뛰기 유지. 끄기에 guard를 걸지 않는다. 새 정지형 스마트 제어를 이 승인으로 추가하지 않는다.
- 일정 비활성·삭제는 예약 중단이며 현재 장치를 즉시 끄지 않는다. 조작 시 안내하고 홈에서 별도로 끌 수 있도록 한다. 진행 중 구간의 종료 예약까지 중단하는 영향을 감추지 않는다.
- 일정 생성·수정은 기존 REST 사용. Supabase 직접 INSERT로 `next_run_at` 계산을 우회하지 않는다.
- 팬·LED 하단 팝업, 일정 상세는 현재 Figma에서 세부 화면을 찾지 못했다. 기존 구조에 Figma의 공통 색·폰트·버튼·간격을 적용하고 비교 가능한 화면으로 검수한다. 기존 UI 자체가 Figma 원본이라는 주장 금지.
- 저장·명령 중복 입력 방지, 실패 시 입력 보존·재시도. 성공 상태를 미리 확정하지 않는다.
- 팬·LED 선택창은 적용 전 닫으면 폐기. 이름·개체·일정 편집 중 변경사항이 있으면 이탈 확인.
- 팝업 중 대상 기기 변경 시 이전 대상 명령 전송 차단·안내.
- 로딩은 프로젝트의 스켈레톤·상태 표시를 사용. CircularProgressIndicator 신규 도입 없음.

## 10. 완료 판정과 변경 관리

구현계획의 7단계와 승인 ID를 대조해 검수한다. 오류 재시도·오프라인·계정 변경·앱 재실행·자정/주간 경계·이름 동시 저장·부분 연결·데이터 보존을 확인한다. 시각 검수는 Figma 기준 폭 및 작은 화면·키보드·긴 이름·스크롤을 포함한다.

코드는 단계별 논리 커밋, 변경이 있으면 버전·한글 CHANGELOG 동반. 코드 검증은 analyze 오류 0과 관련 테스트, 실제 Android 상단 배경·BLE·명령 E2E. 이 문서 저장만으로 앱 구현·서버 배포·외부 요청 발송이 완료된 것은 아니다.
