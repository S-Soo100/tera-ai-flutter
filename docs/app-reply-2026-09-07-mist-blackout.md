## 1. 검토 결과 수용

빠른 검토 감사합니다. 다음을 그대로 수용합니다.

- **"펌프 블로킹" 추정 철회** — 현 펌웨어의 `mist`가 `relay_pulse()` + `esp_timer`로 이미 비블로킹임을 확인했습니다. 원인 후보(브라운아웃 / 전원·모터 노이즈 / 재연결 고정 비용 / 구 펌웨어)와 P0 실측 우선 방침에 동의합니다. 분사 시간(1~3초)과 무관하게 공백이 25~26초로 일정했던 실측과도 재연결 고정 비용 가설이 잘 맞습니다.
- **명령 유실 메커니즘** — clean session + retain=false 조합으로 단절 중 publish 명령이 영영 미전달된다는 설명으로 `sent` 영구 잔류 3건이 완전히 설명됩니다.
- **retain=true 일괄 적용 기각** — 동의합니다. 오래된 펌프 ON이 재구독 때 도는 것은 앱 입장에서도 최악입니다.
- **P3(라이브 20분 종료) 분리** — 동의합니다. §4에 앱이 제공할 수 있는 자료를 적었습니다.

## 2. 앱 반영 완료 (회신 당일, v0.84.1)

서버/펌웨어 수정과 무관하게 앱은 다음을 이미 배포 라인에 올렸습니다.

| 반영 | 내용 |
|---|---|
| ACK 15초 유예 | 미ACK(`pending`/`sent`) 명령은 발행 15초까지만 "실행됨"으로 취급. 유실된 `fan_on`이 팬 타이머 칩을 거짓 카운트다운하던 것 차단 |
| 미전달 스낵바 | 발행 15초 후 상태 재조회 — `pending`/`sent`/`expired`/`lost`면 "기기가 응답하지 않았어요" 안내. **`lost` 상태가 생겨도 앱은 이미 대비되어 있습니다** |
| 라이브 자동 재연결 | failed 시 3→60초 지수 백오프 무제한 재연결(뷰가 떠 있는 동안만). P3와 별개로 체감 완화 |

## 3. 서버 P1 계약 확정 요청 — 구현 전에 3가지만 정해 주세요

`sent` 미ACK 30초 만료 + 절대 명령 제한 재전송을 수용해 주신 것에 감사합니다. 앱이 `commands`를 직접 읽어 타이머·안내를 계산하므로, 아래가 확정되어야 앱 휴리스틱을 서버 상태 기반으로 교체할 수 있습니다.

1. **만료 상태 문자열** — `expired` 재사용인지 신설 `lost`인지. 앱은 둘 다 처리하지만, 기존 `expired`(pending TTL)와 의미를 구분하려면 `lost` 신설을 권합니다.
2. **재전송의 행 정체성** — 같은 행 재발행인지 새 행 생성인지. **새 행(새 `issued_at`) 생성을 강하게 권합니다.** 앱의 팬 타이머 종료 시각이 `issued_at + duration_ms`인데, 같은 행을 30초 뒤 재전송해 그때 ACK되면 실제 팬 정지 시각과 앱 표시가 최대 30초 어긋납니다. 새 행이면 어긋남이 없고, 원 행은 `lost`로 닫혀 이력도 정직해집니다.
3. **재전송 `msg_id`** — 펌웨어 RAM 중복 방지(최근 8개)에 걸리게 **같은 `msg_id` 유지**인지, 새 id인지. 절대 명령이라 중복 실행도 안전하지만, 계약에 명시돼 있으면 좋겠습니다. (2번에서 새 행을 만들더라도 `msg_id`만 유지하는 조합도 가능합니다.)

P1 배포 시점을 알려주시면 앱의 15초 유예 휴리스틱을 서버 상태 기반으로 교체하는 후속 작업을 바로 진행하겠습니다.

## 4. 협조 가능 항목

- **P0 실측 보조** — 시리얼/전압 측정 중에 정해진 타이밍으로 앱에서 `mist`·`fan_on`을 발행해 드릴 수 있습니다(재현 절차는 원 핸드오프 §1 그대로: mist 후 3~10초 내 fan_on). 원하시는 시각을 알려주세요.
- **P3 재현 자료** — 앱은 라이브 연결의 단계별 계측 로그(`[webrtc-timing]`: config/answer/connected/firstFrame ms)를 남깁니다. 다음 재현 때 연결 시작~종료 타임라인을 뽑아 드리겠습니다. 참고로 앱에 자동 재연결이 들어갔으므로, 이후 재현 로그에는 종료 직후 재협상(offer 재전송)이 따라붙습니다 — 세션 로그 볼 때 감안해 주세요.
- **§6.1-4(재연결 시 마지막 처리 명령·출력 상태 보고)** — 이 보고가 생기면 앱이 "명령이 실제 반영됐는지"를 텔레메트리 추론 없이 표시할 수 있습니다. 페이로드 초안이 나오면 공유해 주세요.
