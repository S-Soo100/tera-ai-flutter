# petcam-lab 전달용 — MyCre 활동 데이터·하이라이트 공개 정보 연동 요청

수신: petcam-lab 담당자님

작성일: 2026-09-15

대상: 비바나트(vivanaut) 앱 디자인 개편

안녕하세요. 앱 디자인 개편 기획이 확정되어, MyCre 활동 그래프와 카메라 하이라이트 화면에 필요한 데이터 계약 확인을 요청드립니다.

**이미 제공되는 기능은 기존 API·뷰·필드와 응답 예시를 알려주시고, 없는 항목만 필요한 보완 범위와 예상 일정을 회신 부탁드립니다.** 아래 필드 설명은 필요한 의미를 정의한 것이며 신규 컬럼명을 일괄 지정한 것은 아닙니다.

## 1. MyCre 활동 그래프에 필요한 데이터

앱에서는 도마뱀을 선택하면 연결된 카메라의 활동 기록을 해당 개체의 기록으로 보여줍니다. 개체 식별 AI를 새로 요청하는 것은 아니며, **카메라가 관측한 활동 구간을 개체–카메라 연결 기간에 맞춰 집계**합니다.

### 1-1. 활동 구간과 중복 제거

다음 정보를 기존 분석 결과에서 제공할 수 있는지 확인 부탁드립니다.

| 필요한 정보 | 확인 요청 |
|---|---|
| 카메라 ID, 활동 시작·종료 시각 | 임의의 연결 시작·종료 시각으로 자를 수 있는 실제 활동 interval 또는 동등한 정확도의 조회 결과가 있는지 |
| 유효 활동 판정 | 제외 조건과 적용 정책/version을 확인할 수 있는지 |
| 중복 구간 처리 | 같은 카메라의 겹치는 활동 구간을 어느 계층에서 합집합으로 처리하는지 |
| 시간 범위 조회 | UTC 시각 범위, 카메라 필터, 정렬·pagination/cursor, 사용자 접근 권한 계약 |
| 과거 데이터 | 보관 범위, 재분석 시 값 변경 여부와 기존 데이터의 지원 수준 |

현재 앱에서 참조하는 `v_clip_effective_activity`의 `effective_activity_sec` 같은 **합계 초만으로는 클립 내부의 활동 위치, 겹침, 연결 시각 경계 분할을 복원할 수 없습니다.** 실제 구간이 없다면 그 점을 명시하고, 동등한 결과를 제공할 수 있는 기존 집계 API가 있는지 알려주세요. 시간 버킷을 제공하는 경우에도 임의의 연결 시각에서 정확하게 나눌 수 있는지가 필요합니다.

### 1-2. 활동 0과 데이터 없음의 구분

평균의 분모를 정확히 잡기 위해 다음 상태를 구분해야 합니다.

- 관측과 분석이 완료되었으며 유효 활동이 0인 구간
- 관측과 분석이 완료되었으며 유효 활동이 있는 구간
- 카메라 미수집·오프라인 등으로 관측이 부족한 구간
- 분석 대기·진행 중·실패 또는 완료 여부를 알 수 없는 구간

분석 완료 여부만으로 촬영·수집까지 완전했다고 판단하지 않으려 합니다. **수집 coverage와 분석 completeness 각각의 근거, 범위, 완료 판정 조건**을 알려주세요. 카메라가 지금 온라인이라는 정보만으로 과거 날짜를 관측 완료로 처리하지 않습니다.

수집 원장이 terra-server에 있다면 필요한 원천 필드와 담당 범위를 이관훈님 측과 맞춰주시면 됩니다. 앱 팀도 두 계약을 연결하겠습니다.

### 1-3. 앱의 확정 집계 규칙

- 일간 경계: KST 00:00 이상~다음 날 00:00 미만.
- 주간 경계: KST 월요일 00:00 이상~다음 월요일 00:00 미만.
- 일간 총합: 선택한 날짜의 활동 시간.
- 일간 화면의 비교 평균: 선택일을 제외한 직전 7일 중 관측·분석 완료일의 평균. 완료된 0분은 포함하고 결측일은 제외합니다.
- 주간 총합: 해당 주의 활동 시간. 이번 주는 오늘의 진행분도 포함합니다.
- 주간 평균: 해당 주의 관측·분석 완료일만 사용하며, 진행 중인 오늘은 제외합니다.
- 활동 구간은 합집합으로 계산하고 날짜·시간·연결 경계에서 나눕니다. 시간당 최대 60분이며 시간별 합, 일간 합, 주간 합이 일치해야 합니다.

이 규칙을 petcam-lab에서 모두 계산해달라는 뜻은 아닙니다. **원천 구간과 완료 근거를 제공하는 방식, 또는 같은 의미를 보장하는 집계 API 방식 중 기존 구조에 맞는 계약**을 제안 부탁드립니다.

### 1-4. 연결 변경과 기존 기록 보존

- 새 개체 연결은 실제 연결 시작 시각 이후 데이터만 귀속합니다.
- 같은 개체의 카메라가 바뀌면 이전 카메라의 연결 기간 기록과 새 카메라의 연결 기간 기록을 이어서 보여줍니다.
- 기존 사용자의 이미 보이던 과거 기록은 개편 배포일을 기준으로 잘라내지 않습니다. 앱 팀이 기존 조회 범위를 승계하며, 알 수 없는 과거 연결 시작 시각을 임의로 만들지 않습니다.
- 기기 등록 해제 후에도 기존 계정의 과거 영상·통계를 보존해야 합니다. petcam-lab 조회 권한이 현재 기기 소유자만 따르는 구조라면, 재등록·소유자 변경 시 과거 접근권 보존 방법을 이관훈님 측과 함께 확인 부탁드립니다. 새 소유자에게 이전 소유자의 과거 영상이 노출되면 안 됩니다.

연결 이력 저장과 앱 집계는 앱 팀이 맡습니다. petcam-lab에는 위 기간별 조회와 과거 접근을 지원할 수 있는지 확인을 요청드립니다.

## 2. 하이라이트 공개 배치와 앱 조회 정보

기존 하이라이트 푸시 연동 요청과 **동일한 `highlight_batch_id` 및 검수 승인 스냅샷**을 앱의 하이라이트 목록·도착·읽음 표시에 연결하려 합니다. 별도의 배치 체계는 만들지 않습니다.

다음 의미의 데이터를 앱에서 조회할 수 있는지 알려주세요.

| 정보 | 의미 |
|---|---|
| `highlight_batch_id` | 기존 푸시 이벤트와 동일한 안정적인 배치 식별자 |
| 승인 스냅샷 | 사람이 검수해 승인한 고정 영상 ID 목록과 순서 |
| 촬영 구간 | 배치가 대상으로 하는 촬영 시작·종료 시각 |
| 승인 시각·상태 | 검수 완료 여부와 승인 시점 |
| 실제 공개 시각·상태 | 앱 사용자가 배치를 조회할 수 있게 된 실제 시점과 공개 여부 |
| 조회 권한·pagination | 계정별 조회 및 목록을 이어서 불러오는 방법 |

`scheduled_for`는 푸시 발송 예정 시각이며 실제 공개 시각과 별개입니다. 촬영 시각·승인 시각·발송 예약 시각을 실제 공개 시각으로 대신 표시하지 않겠습니다. 공개 메타데이터가 아직 없다면 기존 영상 목록·재생은 유지하되 도착 시각을 임의로 만들지 않습니다.

기존 FCM 정책은 유지합니다. KST D일 20:00~D+1일 08:00 촬영분을 D+1일에 검수하고, 정상 알림은 D+2일 08:00에 예약합니다. 목표 시각과 같거나 늦게 승인되면 승인 이후 처음 오는 08:00로 예약합니다. **MyCre의 자정 기준 집계는 이 촬영·검수·알림 정책을 변경하지 않습니다.** 기존 `highlight.ready` 이벤트·재시도 계약과 이번 조회 메타데이터가 같은 배치를 가리키도록 부탁드립니다.

## 3. 앱 팀이 담당하는 범위

- Flutter 화면, 개체–카메라 연결 이력과 기존 데이터 승계, 앱 조회·표시
- 기존 `clip_favorites`를 이용한 북마크 목록 연동
- 영상 메모의 계정·기기별 로컬 저장: 메모 서버 기능은 요청하지 않습니다.
- 사용자별 영상 숨김용 앱 전용 데이터와 목록 필터: 삭제 버튼은 해당 사용자의 목록에서만 숨깁니다. R2 영상 원본을 삭제하지 않습니다.

**사용자 숨김은 petcam-lab의 시스템 검수·분석 제외와 별개이며 활동 통계에 영향을 주면 안 됩니다.** `fn_motion_clip_visible_to_owner` 등 공유 영상 RLS나 활동 분석 view에 사용자 숨김 조건을 추가하는 방식은 사용하지 않으려 합니다.

## 4. 함께 확인할 검증 예시

| 예시 | 기대 결과 |
|---|---|
| KST 23:59:50~다음 날 00:00:10 활동 | 두 날짜에 각각 10초 |
| 같은 카메라의 00~20초, 10~30초 활동 | 합집합 30초. 40초로 합산하지 않음 |
| 완료일 10분, 완료일 0분, 미수집일 | 평균 5분, 분모 2 |
| 개체가 12:00에 새로 연결됨 | 12:00 이전 활동은 새 개체에 귀속되지 않음 |
| 카메라 변경 및 기존 사용자 승계 | 각 연결 구간 기록과 기존에 보이던 과거 기록 유지 |
| 사용자가 영상 하나를 숨김 | 사용자 목록에서만 사라지고 활동 통계·R2 원본은 유지 |
| 공개된 하이라이트 조회와 푸시 | 같은 배치 ID·승인 목록을 사용하고 실제 공개 시각과 예약 시각을 구분 |
