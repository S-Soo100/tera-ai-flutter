## 1. 요약

11/3 회신에서 "자동 환기·분무는 계획 없음"으로 받았습니다. 이번 문서는 **이 기능을 정식으로 요청**하는 것입니다. 급하지 않으며, 일정과 방식은 의견을 먼저 듣고 정하겠습니다.

- 사용자가 정한 적정 온습도(MIN/MAX)를 기준으로 **환기팬을 자동으로 켜고 끄고**, 습도가 낮으면 **분무를 자동으로 1회** 하는 기능입니다.
- 앱이 꺼져 있어도 돌아야 하므로 앱에서는 만들 수 없습니다. 판정·실행은 서버나 펌웨어가 맡아야 합니다.
- 앱팀 의견은 **서버 판정**입니다. v4 이탈 판정이 이미 `device_settings.target_*_min/max`를 60초 TTL로 읽고 있어 같은 자리에 붙이기 쉬워 보입니다. 펌웨어 쪽이 낫다면 그 의견도 부탁드립니다(§6-1).
- 앱은 계약이 생길 때까지 토글을 만들지 않습니다(지금과 같음).

## 3. Figma에 없는 규칙 — 앱팀 초안

디자인에는 시작 조건만 있습니다. 그대로 만들면 문제가 될 지점을 아래에 정리했습니다. 숫자는 앱팀 초안이고 확정이 아닙니다. 편하신 값으로 바꿔 주세요.

### 3-1. 자동 환기 (`fan_on` / `fan_off`)

| 항목 | 초안 | 이유 |
|---|---|---|
| 시작 | 습도 > MAX **또는** 온도 > MAX가 **연속 N분**(예: 3분) | 한 번 튄 값으로 켜지지 않게 |
| 종료 | 시작시킨 조건이 **여유 폭 안으로** 돌아오면(예: 습도 ≤ MAX−5%, 온도 ≤ MAX−0.5℃) | "적정 범위 도달"을 MAX 바로 아래로 잡으면 켜짐·꺼짐을 반복함 |
| 1회 최대 | 켤 때마다 `fan_on` + `duration_ms`(예: 1시간, 펌웨어 상한 2시간)로 보내고, 계속 필요하면 다시 보냄 | 서버가 멈추거나 연결이 끊겨도 펌웨어가 스스로 끔 |
| **분무 직후 보호** | 분무(수동·예약·자동) 뒤 **M분**(예: 60분)은 **습도 조건으로는** 시작하지 않음 | 습도 가이드가 "최대 습도는 분무 직후 측정된 습도에 맞춰 설정"이라, 분무 직후 MAX를 넘는 건 정상임. 보호가 없으면 뿌리자마자 환기가 돌아 분무 효과가 사라짐. 습도 이탈 알림도 "1시간 이상 초과"일 때만 보내므로 그 기준과 맞춤 |
| 온도 우선 | 온도 > MAX가 원인이면 습도와 상관없이 유지 | 고온은 개체 폐사 위험이라 습도보다 우선 |

### 3-2. 자동 분무 (`mist` + `duration_ms`)

| 항목 | 초안 | 이유 |
|---|---|---|
| 시작 | 습도가 MIN **아래로 내려가는 순간** 1회(연속 N분 확인 후) | "1회 분무" 원문 |
| 다시 뿌리는 조건 | 습도가 **MIN 이상으로 회복된 뒤** 다시 내려가야 함 + 직전 분무와 **최소 간격**(예: 2시간) | 습도가 계속 낮으면(물통이 비었거나 센서가 이상하면) 끝없이 뿌릴 수 있음 |
| 하루 상한 | 예: 하루(KST 자정 기준) 4회 | 과습·물 부족 방지. Figma 할일 메모에 "분무 몇번 하면 물 채우라고 안내 푸시"가 있어 물통 관리가 디자인 쪽에서도 걱정거리임 |
| 분무 시간 | 고정 3초(앱 기본값과 같음) — 또는 사용자 지정 | Figma에 없음. §6-4 참고 |
| 환기 중 | 환기팬이 켜져 있으면 보류하고, 환기가 끝난 뒤 다시 판정 | 환기와 분무가 서로를 상쇄하며 번갈아 돌지 않게 |

### 3-3. 공통

- **기준값**: `device_settings.target_temp_min/max`, `target_humid_min/max`. 비어 있으면 v4 판정과 같은 기본값(온도 18~27℃, 습도 40~80% — 11/4에 온도 상한 26→27 변경).
- **작동하지 않는 경우**: 센서 오류(`a_ok = false`)·값 없음·기기 오프라인. 값이 없으면 판정을 미루고, 추정해서 켜지 않습니다.
- **수동 조작 우선**: 사용자가 직접 환기팬을 끄면 **K분**(예: 30분) 동안 자동으로 다시 켜지 않습니다. 끄자마자 다시 켜지면 고장으로 보입니다. 사용자가 켠 타이머를 자동이 끄지도 않습니다. 자동 종료는 **자동이 켠 것만** 끕니다.
- **예약 실행 중**: Figma에서 토글이 비활성입니다. 예약이 그 장치를 돌리는 동안에는 자동 판정을 쉬는 것으로 이해했습니다(§6-5).
- **기본값**: 두 토글 모두 꺼짐. 켠 사용자만 작동합니다.

## 4. 앱이 필요한 계약

| # | 필요 | 앱팀 제안 형태 (서버 편한 대로) |
|---|---|---|
| C1 | 토글 저장 | `PATCH /devices/{id}/settings`에 `auto_vent_enabled`, `auto_mist_enabled`(bool, 기본 false). `GET`에도 포함 |
| C2 | 자동 명령 구분 | 자동으로 낸 명령은 `commands.source = 'auto'` + payload나 별도 컬럼에 원인(`humid_high` / `temp_high` / `humid_low`). 앱 제어 기록에 "자동 환기 켜짐"으로 따로 표시하고, 제어 확인 대기·타이머 계산에서 구분하려고 함 |
| C3 | 지금 상태 | 자동 환기가 동작 중인지, 수동 조작으로 쉬는 중이면 언제까지인지(예: `devices.auto_vent_active`, `auto_paused_until`). 없으면 C2의 최근 행으로 앱이 추정하지만, 수동 조작 뒤 쉬는 시간은 앱이 알 수 없음 |
| C4 | 지원 여부 | 서버 판정이면 환기팬·분무가 있는 기기는 모두 지원으로 봅니다. 기기·펌웨어별로 다르면 `capabilities` 키(예: `auto_env: true`)로 알려 주세요 |
| C5 | 예약과의 관계 | 자동 명령이 예약 목록·마지막 실행 결과(`source='schedule'`)에 섞이지 않게 |

## 5. 그동안 앱 (변경 없음)

- 환기팬·분무 시트에 자동 토글을 그리지 않습니다.
- 적정 온습도 설정 화면의 "사육장 자동 작동 기준으로 사용됩니다" 문구는 Figma 그대로 남아 있습니다. 기능이 오래 늦어지면 이 문구를 빼는 것도 디자이너와 상의하겠습니다.

## 6. 여쭙는 것

1. **가능 여부·방식·대략 일정** — 서버 판정 vs 펌웨어 판정. 서버가 하면 OTA 없이 전 기기에 적용되고, 펌웨어가 하면 서버 장애 중에도 돕니다. 앱팀은 서버 + `duration_ms` 안전장치를 추천합니다.
2. **§3 초안 숫자**(연속 N분, 여유 폭, 분무 직후 보호 M분, 분무 최소 간격, 하루 상한, 수동 후 K분) — 운영 데이터(텔레메트리 주기, 분무 후 습도 곡선)를 보시면 더 나은 값이 있을 것 같습니다. 확정값을 주시면 앱 설명 문구에 반영하겠습니다.
3. **고온일 때 어느 팬** — Figma는 환기팬 시트에만 토글이 있습니다. 냉각팬(`fan2`)이 있는 보드에서는 고온 때 냉각팬도 함께 켜는 게 맞는지 의견을 부탁드립니다. 앱은 디자이너와 따로 확인하겠습니다.
4. **자동 분무 시간** — 고정값(3초 제안)으로 할지, 기기별 사용자 선택값을 서버에 저장할지.
5. **"예약 실행 중"의 정의** — 그 장치에 켜진 예약이 있기만 해도인지, 예약이 지금 그 장치를 돌리는 구간(구간 예약 on~off 사이)만인지. 앱은 같은 정의로 토글을 비활성 처리하겠습니다.
6. **자동 작동 푸시** — Figma에 없어 앱은 만들 계획이 없습니다. 물통 비움 의심(자동 분무를 해도 습도가 안 오름)처럼 서버가 알릴 만한 상황이 있으면 의견 부탁드립니다.

## 7. 회신 뒤 추가 질문 (2026-11-05 저녁)

회신(`APP_AUTO_ENV_2026-11-05.md`) 감사합니다. 앱은 계약대로 붙여 main에 합쳤고(0.174.0+479), 토글은 "전체 켬" 전까지 숨겨 둡니다. 출시 전에 아래 답이 필요합니다.

1. **Figma 습도 조건이 바뀌었습니다.** 11/5 오후 디자이너가 습도 자동 환기 조건을 "습도 {Max}% 초과 **1시간 이상 유지**(습도 주의 이벤트와 같은 조건)"로 고쳤습니다(메모 `1657:5409`, 환기 시트 설명). 회신 §1은 "3분 연속 + 분무 뒤 60분 보호"입니다. **습도 조건을 1시간 이상 연속 초과로 바꿔 주실 수 있을까요?** 바뀐다면 분무 뒤 60분 보호를 남길지도 알려 주세요. 섀도 모드 일정상 어렵다면 그렇게 답해 주시면, 앱은 디자이너에게 3분 기준 문구를 받겠습니다. 온도 조건(3분)은 Figma와 같습니다.
2. **`vent.schedule_hold`** 는 자동 환기가 꺼진 기기에서도 계산되나요? Figma "예약 실행 중" 화면을 붙일지 정하는 데 씁니다. 앱은 지금 이 값을 쓰지 않습니다.
3. **테스트 허용 목록** — 앱 실기 확인용으로 앱 계정 기기 1대를 넣을 수 있을까요?
4. **재켜짐 간격 상한** — 원인이 계속될 때 1시간 타이머가 끝난 뒤 다시 켜는 `fan_on`이 최대 몇 분 안에 나가나요? 앱은 제어 기록에서 "끝 + 10분" 안의 자동 `fan_on`을 한 줄로 합칩니다(서버의 "꺼진 팬 재명령 최소 5분 간격"을 덮는 값).
5. **자동 분무 명령 모양** — `action='mist'` + `payload.duration_ms=3000`이 맞나요? 제어 기록의 "자동 분무 3초 작동" 표시가 이 값을 씁니다.
