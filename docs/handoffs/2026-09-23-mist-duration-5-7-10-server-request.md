# 분무 분사 시간 5/10초 — 서버·펌웨어 요청 (2026-09-23)

> **개정(같은 날):** 사용자 결정으로 7초를 뺐습니다. 선택지는 **5초 / 10초**, 기본은 **5초**입니다. 서버 허용값에 7000은 없어도 됩니다(넣어 두셔도 앱이 보내지 않습니다). Slack으로 처음 보낸 요청(5/7/10초)보다 이 문서가 우선합니다.

받는 분: 이관훈님 (terra-server / 펌웨어)
보내는 쪽: 비바나트 앱

## 배경

사용자 결정으로 분무 한 번의 분사 시간을 **5초 / 10초 중에서 고를 수 있게** 바꿨습니다(기본 5초). 앱은 0.131.0에 반영했습니다.

- 홈 분무 제어 시트(즉시 작동): "분사 시간" 칩 5·10초 + 기존 "1회 분사 시작" 버튼
- 분무 예약 편집기: 같은 칩. 새 예약 기본값은 5초
- 명령 형식은 그대로입니다: `mist` + `payload.duration_ms` (5000 / 10000). OFF는 보내지 않고 펌웨어가 스스로 끄는 방식도 그대로입니다.

**다만 지금은 이 값이 실제로 동작하지 않습니다.** 서버와 펌웨어 두 곳이 막고 있습니다.

| 위치 | 현재 | 결과 |
|---|---|---|
| terra-server `command_service.py:36-42` | `duration_ms` 화이트리스트 1000/2000/3000 | 5000/10000은 **400 거절**. 앱에는 "분무 실행 실패"가 뜹니다 |
| 펌웨어 | 5초 상한으로 clamp | 서버를 풀어도 10초가 **알림 없이 5초로 줄어듭니다** |

두 번째가 더 위험합니다. 사용자는 10초 뿌렸다고 믿는데 실제론 5초라서, 습도 관리를 잘못 판단하게 됩니다.

---

## 요청 1. 서버 — `mist.duration_ms` 화이트리스트에 5000/10000 추가

- 즉시 명령(`POST /commands`)과 예약(`POST/PATCH /schedules`) 양쪽 검증에 똑같이 적용해 주세요.
- **기존 1000/2000/3000도 계속 허용**해 주세요. 사용자가 저장해 둔 옛 분무 예약(1/2/3초)이 남아 있고, 앱은 이 예약을 사용자가 직접 다시 고르기 전까지 저장값 그대로 둡니다.
- 최종 허용값: `{1000, 2000, 3000, 5000, 10000}`

## 요청 2. 펌웨어 — 분무 상한을 10초 이상으로

- 현재 5초 clamp를 **10000ms 이상**으로 올려 주세요.
- 펌프 연속 구동 10초가 하드웨어에서 괜찮은지(발열·전원 강하) 확인 부탁드립니다. 09-07에 분무 시 약 25초간 통신이 끊기는 현상을 브라운아웃으로 의심했는데, 분사 시간이 길어지면 이 현상이 심해질 수 있습니다.
- 분사 중 같은 `mist`가 또 오면 지금처럼 `busy`로 거절해 주시면 됩니다. 앱은 분사 시간 + 2초 동안 버튼을 잠급니다(10초 분무면 12초).

## 요청 3. 배포 순서

**펌웨어를 먼저, 서버를 나중에** 올려 주세요. 반대 순서면 서버는 받아 주는데 펌웨어가 5초로 잘라서, 앞에서 말한 "10초로 알았는데 실제론 5초" 상태가 생깁니다.

## (선택) 요청 4. 펌웨어 능력 보고

펌웨어를 순차로 플래시하는 동안 구 펌웨어(5초 상한) 기기가 섞여 있게 됩니다. `devices.capabilities.mist_max_ms`(예: 5000 / 10000)를 보고해 주시면, 앱이 LED `led_dimmable`처럼 구 펌웨어에서는 10초 칩을 숨길 수 있습니다. 필수는 아니고, 해 주시면 앱에서 분기를 붙이겠습니다.
