# 요청 — 기기가 연결된 Wi-Fi 이름 보고 (`wifi_ssid`) · 2026-11-19

> **받는 분:** 이관훈님 (terra-server · 펌웨어)
> **보내는 쪽:** 앱
> **이전 요청:** `2026-09-28-wifi-change-firmware-requests.md` §4와 같은 내용입니다. 아직 배포되지 않았고, 이번에 이 값이 필요한 화면이 생겨 다시 요청드립니다.

## 왜 필요한가

Figma에 **"네트워크 관리"** 화면이 새로 생겼습니다(홈 상단 설정 메뉴 4번째, 섹션 `1877:14741`). 화면 구성은 아래와 같습니다.

- **기기 목록:** 줄마다 기기가 **지금 붙어 있는 Wi-Fi 이름**(예: `iptime1354111`)과 신호 세기(−68 dBm)를 보입니다. 연결이 없으면 "네트워크 연결 없음"이라고 씁니다.
- **기기 상세:** "연결된 네트워크" 줄에 같은 이름을 보입니다.

신호 세기는 지금도 받고 있습니다(사육장 `sys_state.rssi`, 카메라 `clip_stats.sys.rssi`). **Wi-Fi 이름은 서버에 없습니다.** 그래서 앱은 이 폰이 BLE로 직접 붙인 기기만 이름을 기억해 보여 줍니다. 다른 폰으로 붙였거나 앱을 다시 깔면 이름이 비고, 다른 폰에서 바꾸면 옛 이름이 남습니다.

앱은 서버 값이 생기기 전까지 **아는 이름만** 보이고 출시합니다. 모르는 기기는 신호 세기만 보입니다(2026-11-19 결정).

## 요청

1. **펌웨어:** 부팅할 때와 Wi-Fi에 다시 붙을 때, 상태 메시지(사육장 `sys_state`, 카메라 heartbeat `clip_stats.sys`)에 현재 SSID를 넣어 주세요. 사육장·카메라 공통입니다.
2. **서버:** `devices.wifi_ssid`, `cameras.wifi_ssid`에 text 컬럼을 추가하고 받은 값을 저장해 주세요. 앱은 본인 기기 행을 Supabase에서 직접 SELECT합니다. 기존 RLS로 읽히면 충분하고 REST는 필요 없습니다.
   - 대신 상태 메시지 안에만 두셔도 됩니다(예: `sys_state.ssid`). 앱은 어느 쪽이든 읽을 수 있습니다. 어디에 넣으셨는지만 알려 주세요.
3. **값 규칙:**
   - 붙어 있는 동안에만 현재 SSID를 둡니다.
   - Wi-Fi가 끊긴 뒤에는 마지막 SSID를 그대로 두셔도 됩니다. 앱은 `is_online=false`면 "네트워크 연결 없음"을 보입니다.
   - 숨긴 SSID나 빈 값은 null로 주세요.

## 앱에서 이미 해 둔 것

- `wifi_ssid`가 행에 있으면 그 값을 먼저 쓰도록 읽는 자리를 만들어 두었습니다(`redesign_group_repository.dart`). 컬럼이 생기면 앱 수정 없이 기기 상세에 바로 보입니다. 네트워크 관리 목록도 같은 규칙으로 읽습니다.
- **추가 이점:** Wi-Fi를 바꿀 때 대상 기기가 옛 Wi-Fi로 계속 온라인이면, 지금 앱은 새 신호가 새 Wi-Fi에서 온 것인지 가릴 수 없습니다. 그래서 "연결돼 있지만 확인 못 했어요"라고 안내합니다. `wifi_ssid`가 방금 보낸 이름으로 바뀌는 걸 보면 성공을 확정할 수 있습니다.

## 회신 부탁드리는 것

- 어디에 넣을지: 새 컬럼인지, 상태 메시지 안인지
- 펌웨어·서버 배포 예상 시점
