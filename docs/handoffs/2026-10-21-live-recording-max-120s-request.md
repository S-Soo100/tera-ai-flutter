# 라이브 직접 녹화 — 길이 한도 60초 → 120초 변경 요청 (2026-10-21)

받는 분: 백엔드 (terra-server, `/recordings`)
보내는 쪽: 비바나트 앱
기준 합의: `docs/handoffs/2026-10-20-live-recording-server-requests.md` "합의 결과" 절, 서버 회신 `terra-server/docs/BACKEND_HANDOFF_REPLY_LIVE_RECORDING_2026-10-20.md`

## 요청

디자인(Figma "실시간 녹화")이 녹화를 **최대 2분**으로 확정했습니다. `POST /recordings` 검사를 아래처럼 바꿔 주세요.

| 항목 | 지금 | 변경 |
|---|---|---|
| `duration_ms` | 3,000 ~ 60,000 | **3,000 ~ 120,000** |
| `size_bytes` | ≤ 30MB | **그대로 30MB** |

크기 한도는 그대로 둡니다. 앱이 녹화 화질을 2.5 → **1.5Mbps**로 낮춰 2분에 약 23MB(카메라 영상이 초당 약 6장이라 화질 차이는 작음)로 맞추고, 업로드 전에 30MB 초과를 앱에서도 걸러 냅니다.

## 앱 동작 (변경 반영 전까지)

- 60초를 넘는 녹화는 `POST /recordings`를 **부르지 않고** 폰에 "업로드 대기"로 둡니다(400을 받아 실패시키지 않으려고).
- 서버 반영을 알려 주시면 앱 상수(`kServerRecordingMaxMs`)를 120초로 올린 업데이트를 내고, 대기 중인 녹화를 오래된 것부터 차례로 올립니다(409 `recording_quota_exceeded`가 나면 거기서 멈춤).

## 확인 부탁

1. 배포 상태: 회신서의 "배포 상태" 체크가 아직 비어 있다면 현재 운영 반영 여부(마이그레이션·`/recordings` 전 엔드포인트)를 알려 주세요. 앱은 실계정으로 등록 → PUT → complete → 목록 → DELETE 스모크를 한 번 돌린 뒤 업로드를 켭니다.
2. 120초 반영 예정 시점.
