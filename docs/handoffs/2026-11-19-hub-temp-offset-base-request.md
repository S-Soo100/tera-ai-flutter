# 서버·허브 펌웨어 요청 — 허브 카메라 온도 보정이 "+1.5"로 보이는 문제 (2026-11-19)

> **보내는 쪽**: 앱(비바나트) · **받는 쪽**: terra-server(이관훈님), 허브 펌웨어(`terra-hub-p4`)
> **요청 한 줄**: 허브 카메라의 공장 보정은 0인데, 서버가 기준값 미보고를 −1.5로 가정해 `temp_offset_user_c`를 **1.5**로 기록합니다. 허브는 기준값을 **0으로 보고**하게 하거나, 서버가 **허브의 미보고 기준값을 0으로** 봐 주세요.
> **관련 서버 문서**: `backend/temp_offset.py`(기준값 폴백), `specs/stage-t-temp-offset-base-per-device.md`(T5 폴백, "hub 동결"), `docs/APP_TEMP_OFFSET_2026-11-10.md`

---

## 1. 증상

테스터 계정 사육장 **'승수홈'**의 온도 보정이 앱에 **+1.5℃**로 표시됩니다. 서버 담당자는 이 기기에 보정을 넣은 적이 없습니다.

## 2. 원인 — 보정이 들어간 것이 아니라 계산 결과입니다

'승수홈'에 묶인 기기는 사육장 보드가 아니라 **허브 카메라**입니다. 운영 DB 값(2026-11-19 조회):

| device_id | 펌웨어 | `temp_offset_c` (적용값) | `temp_offset_base_c` (기준) | `temp_offset_user_c` (사용자) |
|---|---|---|---|---|
| `p4hub-4f5e0647` (카메라 3, **승수홈**) | `terra-hub-p4 0.5.32-20261113` | **0** | **null** | **1.5** ❌ |
| `p4hub-ff94f0b5` (카메라 4) | `terra-hub-p4 0.5.0-20261109` | 0 | null | 1.5 ❌ |
| `p4hub-cfb51bef` (카메라 5) | `terra-hub-p4 0.5.31-20261113` | 0 | **0.0** | **0.0** ✅ |

- 기기에 실제로 걸린 보정은 **0**입니다. 온도를 1.5℃ 바꾸고 있지는 않습니다.
- 허브 펌웨어의 공장 보정은 0입니다. 카메라 5가 기준값을 `0.0`으로 보고하고 있고, 사용자 보정도 `0.0`으로 맞게 계산됩니다.
- 기준값을 보고하지 않는 허브(0.5.32, 0.5.0)에서는 서버가 `TEMP_OFFSET_BASE_C`(−1.5)로 폴백합니다. 그래서 사용자 보정 = 0 − (−1.5) = **+1.5**가 됩니다.
- 11-18 02:43에 이 기기로 `set_temp_offset {offset_c: 0}`(source `manual`, ok) 명령이 한 번 나갔지만, 값은 그 전후로 0이라 이 문제와는 관계가 없습니다.

**0.5.31은 기준값을 보고하는데 0.5.32는 보고하지 않습니다.** 허브 펌웨어에서 기준값 보고가 빠진(퇴보한) 것으로 보입니다.

## 3. 영향

- **표시**: 보정을 켠 적 없는 허브 사용자에게 "측정값 +1.5℃ 보정"이 보입니다.
- **저장(더 위험함)**: 허브에서 보정을 "끔"으로 저장하면 서버가 `offset_c = 0 + (−1.5)`로 보냅니다. 허브는 실제로 **1.5℃ 낮게** 재기 시작하고, 고온 경고가 늦어집니다. 새 계약(`user_offset_c`)으로 보내도 서버 합산 단계에서 똑같이 일어납니다.
- 앱은 아직 옛 계약을 쓰고 있어서, 이번 앱 업데이트(아래 §5)로 앱 쪽은 막았습니다. 하지만 앱의 새 계약 스위치를 켜면 서버 계산에 그대로 의존하므로, **스위치를 켜기 전에 서버 수정이 필요합니다.**

## 4. 요청

둘 중 하나, 가능하면 둘 다 부탁드립니다.

1. **허브 펌웨어**: 0.5.32 이후 버전도 telemetry에 `temp_offset_base_c: 0.0`을 다시 보고하게 해 주세요(0.5.31 동작 복원).
2. **서버 폴백**: `base_c(device_uuid)`가 미보고(null)일 때, 허브 기기는 env −1.5 대신 **0**을 쓰게 해 주세요. 앱은 `devices.capabilities.hub == true`로 허브를 구분합니다(서버는 `device_id` 접두어 `p4hub-`로 구분해도 됩니다). 그러면 기존 허브 행의 `temp_offset_user_c`도 다음 telemetry부터 0.0으로 바로잡힙니다.

**확인 방법**: 수정 뒤 위 표의 세 허브가 모두 `temp_offset_user_c = 0.0`인지 확인합니다. 허브에 `user_offset_c: 0`을 보내면 `offset_c: 0`이 발행되는지(−1.5가 아닌지)도 확인합니다.

## 5. 앱에서 한 것 (0.184.2)

- 옛 계약(`offset_c`·`temp_offset_c`)에서 공장 보정 기준을 기기마다 정합니다. ① `temp_offset_base_c` 보고값 ② 없으면 허브(`capabilities.hub`)는 0 ③ 그 외는 −1.5.
- 그래서 '승수홈'은 앱에서 보정 0(꺼짐)으로 보이고, 허브에서 "끔"을 저장하면 `offset_c: 0`이 나갑니다.
- 운영 콘솔에서 보드 기준을 바꾼 경우(예: `terra-cb7cf18a` −2.0)도 보고된 기준값으로 풀기 때문에, `APP_TEMP_OFFSET_2026-11-10.md` §1의 "−0.5 표시" 문제도 함께 해소됩니다.
- **새 계약 스위치는 아직 켜지 않았습니다.** 허브 서버 폴백이 고쳐진 것을 확인한 뒤 켜겠습니다.
