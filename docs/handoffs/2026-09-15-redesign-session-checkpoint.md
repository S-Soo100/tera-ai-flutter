## 3. 가장 최근 변경 — 반드시 보존

사용자가 기획자의 변경사항과 스크린샷 2장을 전달했다. 이미지의 2안에 따라 다음으로 변경했다.

- **Home·Camera·MyCre 헤더/드롭다운: 그룹 소속이면 그룹명.** 그룹 없는 항목만 각각 사육장·카메라·도마뱀 이름을 표시한다.
- 그룹명은 표시 용도이며 선택·조회·제어는 원래 기기/개체 ID로 한다. 상세·프로필의 개별 이름은 유지한다. 이름 수정·소속 이동·해제 시 표시를 갱신한다.
- 신규 기본 그룹명: `사육 환경 1`, `사육 환경 2`, `사육 환경 3`….
- 신규 기본 기기명: `사육장 1`, `사육장 2`… / `카메라 1`, `카메라 2`…. **첫 항목도 공백과 1을 포함**한다.
- 사용 중인 이름을 건너뛰며 동시 등록에서도 중복을 막는다. 기존 저장 이름은 자동 개명하지 않는다.
- 기기·그룹·개체 이름은 최대 10자·동일 계정 중복 금지. 공백과 번호도 글자 수에 포함한다. 개체의 새 자동 이름 규칙은 추가하지 않았다.
- `그룹 1` 같은 생성 순서 번호와 실제 그룹 이름 `사육 환경 1`은 별개다.
- LCD 문구는 기기 이름과 별개, 20자·중복 허용이다.

## 4. 핵심 승인 결정 요약

### 디자인·에셋

- Figma 원본 SVG 사용, 색·도형 크기·부모 프레임·padding·layout·폰트를 실측한다. 임의 Material 아이콘 대체나 SVG 일괄 tint 금지.
- 흰 배경/헤더/상태바 뒤 `#FFFFFF`, 카드·기본 면 `#F4F4F4`. Android 스크롤 시 상단이 회색으로 변하지 않게 검증한다. 원인·수정은 아직 미확정.
- 원본 `assets/figma/2026-09-15/`: SVG 70개 + x3 PNG 4개, manifest SHA-256 보존. Empty 01~03은 1035×681, 논리 크기 345×227. x3 파일명만으로 Flutter 배율이 적용되지 않는다.
- Figma 조사 채널 `wvkqunn6`, 페이지 `vivanaunt app` (`0:1`). 주요 노드 ID는 확정 기획에 있다. Talk to Figma 규칙을 따르며 임시 연결 세션이 압축 후에도 살아 있다고 가정하지 않는다.

### 영상·메모·통계

- 북마크 목록은 기존 `clip_favorites` 동기화 유지. 처음의 북마크 전부 로컬 안은 후속 결정으로 대체됐다.
- 메모는 계정·기기별 로컬 저장. 모든 영상에서 편집 가능하지만 목록의 메모 UI는 북마크 영상에만 표시.
- 메모 색은 6색 중 무작위 배정하되 직전 배정 색과 연속 중복 금지. 기존 색은 유지.
- 영상 삭제 버튼은 해당 사용자 목록에서 숨김. R2·영상 원본·분석/활동 통계는 유지한다. 시스템 검수 제외·공유 clip RLS와 사용자 숨김을 합치지 않는다.
- MyCre는 연결 카메라의 관측 활동을 개체 활동처럼 친화적으로 표시. 개체 식별 AI 요청이 아니다.
- 활동 구간 합집합, 시간·자정 경계 분할. 시간당 최대 60분. 관측 완료 0과 결측·분석 대기를 구분. 2026-09-16부터 MyCre는 현재 카메라만 조회하여 과거 연결 경계로 기간을 자르지 않는다.
- KST 자정 기준 일간, 월요일 기준 주간. 일간 비교 평균은 선택일 제외 직전 7일의 완료일, 주간 평균은 선택 주의 완료일. 진행 중 오늘은 주간 총합에 포함하지만 평균에서 제외.
- **2026-09-16 변경 확정:** MyCre는 현재 그룹의 카메라 조회 가능 기록을 보여준다. 등록/연결일 제한 없음. 카메라 교체 시 선택 날짜를 유지하고 새 카메라로 전환하며 과거 카메라 기록을 이어 붙이지 않는다. DB 연결 이력의 가공·삭제는 하지 않는다. 평균 표시는 검수 후 논의한다.

### 연결·등록·그룹

- 그룹당 사육장 최대 1대 + 카메라 최대 1대 + 도마뱀 최대 1마리. N마리는 미래 범위이며 이번에는 Figma대로 1마리.
- 한 종류만으로 그룹 생성 가능. 이동은 확인, 빈 그룹 제거 시 구성원 원본은 유지. 동시 연결 일부 성공 시 성공 기기는 보존하고 실패 기기만 재시도.
- 신규 개체 등록 종은 크레스티드 게코만. 기존 다른 종 자료는 보존. DB/로컬 모프 카탈로그 대조가 필요하다.
- 기기 삭제는 등록/그룹 연결 해제. 기존 계정의 과거 접근권 보존, 다른 계정 재등록 시 이전 소유자 영상 노출 금지.
- Wi-Fi 성공과 ownership claim 성공은 별개. 사전 등록 베타 방식 외 완전 자동 최초 등록은 외부 계약 회신 대기.
- 기기 관리 전체 전원 버튼은 ON 고정 표시. 실제 전원 기능은 추후 연결한다.

### 제어·기록

- fan2는 사용자 제공 `APP_FAN2_2026-09-07.md` 계약대로 on/off·타이머·예약·상태·기록 연결. 새 서버 개발 요청 항목이 아니다. 실제 미보고 값은 `--`/비활성으로 구분한다.
- LED 20~100%, 10% 단위. 선택 후 적용 시 전송, 타일에는 실제 보고값 표시.
- 팬 작동 시간 선택창 유지: 10/30/60/120분/연속, 초기 30분 또는 기억값. Figma에 생략됐어도 사용자 승인한 선택 흐름을 없애지 않는다.
- 홈 분무 3초, 5초 중복 잠금. 일정 분무는 기존 1/2/3초.
- 제어 기록의 시점 온습도·변화량은 승인된 30분 평균 근사치와 기존 명령 시각 사용. 근거 없으면 `--`. Figma 문구·항목은 유지하고 새 정밀 snapshot 서버 기능은 요청하지 않는다.
- 과거 온습도 정확 일평균은 지표별 유효 표본 수가 필요하며 제어 로그 근사치 승인과 별개다.
- 기존 예약 보존 + fan2 확장. KST 요일/매일·자정 넘김·on만 guard 등 상세 정책은 확정 기획 참조. 예약 비활성/삭제가 현재 작동을 즉시 끄는 것으로 표시되지 않게 한다.

## 5. 외부 요청 현황·남은 확인

| 대상 | 전달 상태 | 필요한 회신 |
|---|---|---|
| 이관훈님 / terra-server | 사용자 직접 전달 완료 | 등록/claim/unlink·BLE ID/광고명, 공통 그룹 write·이름 원자 할당·연결 이력, 기록/소유권 보존, 온습도 valid count, coverage 원천 |
| petcam-lab | 사용자 직접 전달 완료 | 활동 구간·겹침 제거·coverage/분석 완료, 기간별 과거 접근, 기존 FCM과 동일 하이라이트 배치/승인 목록/실제 공개 시각 |

- 기존 지원 API·필드·응답부터 확인하고 없는 항목만 보완 범위를 정한다. 전달을 개발 완료로 취급하지 않는다.
- 우리 담당: Flutter, 로컬 메모·보안 저장소, 앱 전용 숨김 데이터/RLS, 카탈로그, 연결 이력 schema/RPC 초안. 공통 write 변경은 이관훈님과 협의.
- Supabase CLI 대상 프로젝트 접근 및 앱 팀 운영 이력은 확인했지만 모든 DDL 권한을 검증하거나 이번 재설계 DB 변경을 실행한 것은 아니다.
- petcam-lab의 활동 view·공유 clip 가시성 정책과 사용자 숨김을 섞지 않는다. 스칼라 활동 초나 raw 영상 길이로 새 정확 활동 통계를 임의 대체하지 않는다.
- 하이라이트 `scheduled_for`와 실제 공개 시각은 다르다. MyCre 자정 집계가 기존 FCM의 D20:00~D+1 08:00 촬영/검수/08:00 알림 정책을 바꾸지 않는다.
