# 탈퇴 계정 30일 후 실제 삭제 요청 (2026-11-17)

> 관련: [회신 BACKEND_REPLY_DELETE_ACCOUNT_2026-11-17](https://github.com/gwanhun/terra-server/pull/67) · [첫 요청서](2026-11-16-delete-account-server-request.md) · [Google Play SOT](../ops/google-play-account.md)

## 1. 결정 사항

- 회신 §4의 "N일"을 **30일**로 정했다(백승수, 2026-11-17).
- 공개 문구는 이 기준으로 바꾼다.
  - 개인정보처리방침: https://www.vivanaut.co.kr/privacy
  - 계정 삭제 요청 페이지: https://www.vivanaut.co.kr/account-deletion
  - 앱 탈퇴 화면(0.180.1)
  - 문구: "탈퇴하면 바로 로그인이 막히고 기기 연결이 해제되며, 남은 데이터는 30일 안에 모두 삭제".
- 앱은 0.180.0부터 `POST /account/delete`를 부른다. 응답 코드는 회신 §3 그대로(200 / 409 `admin_account` / 500)다. 404가 오면 "서버에 아직 없음"으로 보고 웹 삭제 요청을 안내한다.

## 2. 확인 부탁: 배포 상태

- 회신 문서에는 "11-17 운영 반영"이라고 적혀 있다.
- 그런데 11-17에 확인했을 때 [gwanhun/terra-server#67](https://github.com/gwanhun/terra-server/pull/67)은 **OPEN(머지 안 됨)** 상태였다. 운영에 실제로 떠 있는지 알려 주세요.

## 3. 요청: 탈퇴 30일 뒤 실제 삭제

**대상:** `auth.users.deleted_at`이 30일보다 오래된 계정(소프트 삭제된 계정)

**지울 것**
- 그 사용자의 DB 행 전부. 첫 요청서 §3·§4의 테이블 목록을 기준으로 한다.
- R2 영상·썸네일: `motion_clips`, `live_recordings`
- Supabase Storage 파일: `pet-media`, `user-avatars`, `community-media`
- 마지막으로 계정 자체: `auth.users` 하드 삭제

**회신에 적힌 차단 요인에 대한 결정 요청**
- **라벨링·분석 테이블 45개**(`motion_clips` 참조, CASCADE 없음)
  - 고객 영상의 라벨을 지울지, 사용자와의 연결만 끊고 남길지(익명화)를 정해 주세요.
  - 남긴다면 개인정보처리방침에 "AI 모델 개선(영상 라벨링)" 목적을 추가해야 한다. 고객 앱 영상을 라벨링에 쓰는지는 아직 정해지지 않았다.
- **`auth.users` DELETE 트리거 500**(`BETA_ONBOARDING.md` §6): 하드 삭제 전에 고쳐야 한다.
- **실행 방식**: 매일 한 번 도는 작업(cron 등)을 제안한다. 다시 돌려도 안전해야 한다(멱등). 지운 건수는 로그로 남겨 주세요.

## 4. 요청: 탈퇴 직후 커뮤니티 노출

- 소프트 삭제 뒤 30일 동안 탈퇴자의 커뮤니티 글·댓글이 다른 사용자에게 보인다(회신 §3 "남는 것").
- 앱 쪽에서 숨기려면 탈퇴자를 구분할 수 있어야 한다. 아래 중 하나를 골라 주세요.
  - (a) `public_profiles` 뷰에 탈퇴 여부(또는 `deleted_at`)를 노출
  - (b) 탈퇴 처리 때 `community_posts`·`community_comments`에 숨김 표시를 함께 기록
  - (c) RLS로 탈퇴자 글을 조회에서 제외
- 앱은 고른 방식에 맞춰 피드·댓글을 숨긴다. 그 전까지 처리방침에는 "탈퇴 즉시 숨김"을 쓰지 않는다.

## 5. 확인 방법

- 테스트 계정을 탈퇴시킨 뒤 `deleted_at`을 31일 전으로 바꿔 작업을 돌린다.
- 아래가 모두 0개인지 확인한다.
  - DB: `auth.users`와 각 테이블에서 그 uid 행
  - Storage: 세 버킷에서 그 사용자 경로의 파일
  - R2: 그 사용자 카메라 경로의 객체
- 작업을 두 번 돌려도 오류가 없는지 확인한다.
- 회신 §5의 `push_devices` 행이 탈퇴 직후 사라지는지도 같이 봐 주세요.
