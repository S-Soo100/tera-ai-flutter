# Wi-Fi 바꾸기 — 펌웨어·서버 요청 (2026-09-28)

앱 0.139.x에 **기기를 지우지 않고 Wi-Fi만 바꾸는 기능**을 넣었다(기기 상세 [Wi-Fi 바꾸기], 라이브 오프라인 안내). 앱은 BLE로 `SSID:` → `PASS:` → `CONNECT`만 보내고(`UNPAIR`·`NAME`·`JWT` 없음), 결과는 그 기기 행의 `last_seen_at`이 새로 갱신되는지로 판정한다.

지금은 추정에 기대는 부분이 있어 아래를 요청한다. **P0는 기능 동작의 전제**이고, P1은 판정·식별을 추정에서 확정으로 바꾸는 항목이다.

## P0 — 동작 전제 (사육장 `terra-iot`)

### 1. 등록을 유지한 채 Wi-Fi만 바꾸기
- **요청:** NVS에 서버 자격증명(`device_id`·`mqtt_token`)이 있을 때 `SSID/PASS/CONNECT`만 받으면 다음처럼 동작해야 한다.
  - pair를 호출하지 않는다.
  - **같은 `device_id`로 MQTT에 다시 접속한다.**
  - 새 SSID·비밀번호를 NVS에 저장한다. 재부팅 뒤에도 새 Wi-Fi로 붙어야 한다.
  - 성공하면 `WIFI_OK`, 실패하면 `WIFI_FAIL`을 BLE로 보낸다.
- **근거:** terra-server `FIRMWARE_INTEGRATION.md` §2는 "`CONNECT` 시 NVS 자격증명이 없을 때만 pair"라고 되어 있다. 다만 실기기로는 확인하지 않았다.
- **확인 방법:** 앱 → 사육장 상세 → [Wi-Fi 바꾸기] → 다른 공유기로 연결한다. `devices`에 새 행이 생기지 않고 기존 행의 `last_seen_at`이 이어지면 된다.
- **안 될 때:** 앱은 상수 `kWifiChangeDeviceEnabled=false`로 사육장만 기능을 끈다(사용자 결정). 카메라는 유지한다.

### 2. 새 Wi-Fi 연결에 실패하면 기존 설정 유지
- **요청:** 새 비밀번호가 틀려 `WIFI_FAIL`이면 NVS의 기존 SSID·비밀번호를 덮어쓰지 않는다. **성공한 뒤에만 저장**한다.
- **이유:** 틀린 비밀번호 한 번에 기기가 네트워크를 영영 잃으면 안 된다. 앱은 `WIFI_FAIL`이면 같은 화면에서 다시 입력받는다.

### 3. 등록된 기기도 BLE 광고
- **요청:**
  - 전원을 켠 뒤 광고하는 시간을 정해 알려 달라(카메라는 3분).
  - **Wi-Fi 연결에 실패하고 있는 동안에는 계속 광고**해 달라.
- **이유:** 공유기를 바꾼 경우 기기는 옛 Wi-Fi를 못 찾는 상태다. 이때 앱에서 검색돼야 Wi-Fi를 바꿀 수 있다. 앱 안내 문구는 "전원을 껐다 켜면 몇 분 동안 검색돼요"다.

## P1 — 판정·식별을 확정으로

### 4. 연결된 Wi-Fi 이름 보고 (`wifi_ssid`)
- **펌웨어:** 부팅·재접속 때 MQTT 상태 메시지에 현재 SSID를 넣어 달라(가능하면 RSSI도). 사육장·카메라 공통.
- **서버(이관훈님):** `devices.wifi_ssid`, `cameras.wifi_ssid` text 컬럼을 추가하고 받은 값을 저장해 달라.
- **앱:** 이미 `wifi_ssid`가 있으면 그 값을 먼저 보여 주게 만들어 두었다. 지금은 이 폰이 마지막에 붙인 이름을 대신 보여 준다. 그래서 다른 폰에서 바꾸면 옛 이름이 남는다.
- **판정에도 쓴다:** 대상 기기가 옛 Wi-Fi로 계속 온라인이면, 앱은 새 신호가 새 Wi-Fi에서 온 것인지 가릴 수 없다. 지금은 "연결돼 있지만 이 기기인지 확인 못 했어요"로 안내한다. `wifi_ssid`가 방금 보낸 SSID로 바뀌는 것을 보면 확정할 수 있다.

### 5. BLE로 기기 알아보기
- **현재:** 목록에서 대상 기기를 알아보는 근거는 두 가지다.
  - 이 폰이 등록했던 기억
  - 추정 규칙: `hw_id`와 안드로이드 블루투스 주소의 차이가 0 또는 2(ESP32는 블루투스 MAC = 기준 MAC + 2로 추정). 앱 로그 `[device-add] wifi-target`에 두 값의 끝 4자리를 남겨 실측 중이다.
  - iOS는 블루투스 주소가 UUID라 사육장을 알아볼 방법이 없다. 사육장 광고 이름이 `terra-iot` 하나뿐이기 때문이다.
- **요청(둘 중 하나):**
  - (a) 광고 이름에 MAC 하위 2바이트를 붙인다(`terra-iot_254A`). 카메라 `FB2_P4_CAM_XXXX`와 같은 방식이고, 앱은 이미 이름 끝 4자리를 본다.
  - (b) BLE 명령 `INFO` → `INFO <hw_id> <device_id|none> <fw_ver>`. 등록 여부와 어느 행인지까지 알 수 있어 가장 확실하다.
- **알려 달라:** `hw_id`가 Wi-Fi(STA) MAC인지 블루투스 MAC인지.

### 6. `hw_id` 누락
- **현재:** 운영 `devices`에 `hw_id`가 비어 있는 행이 있다(예: `terra-9e3f0f4a`, 펌웨어 `terra-fw 0.1.0`).
- **요청:** 모든 펌웨어가 pair할 때 `hw_id`를 보내 달라. 없으면 5번 알아보기가 동작하지 않는다.

## P2

### 7. Wi-Fi만 바꿀 때 등록 관련 응답 생략
- **요청:** `NAME`·`JWT` 없이 `CONNECT`했을 때 `PAIR_FAIL no_name` 같은 등록 응답을 보내지 않아 달라.
- **이유:** 앱은 첫 응답(`WIFI_OK`/`WIFI_FAIL`)만 보지만, 불필요한 응답은 로그 해석을 흐린다.

### 8. 카메라 `FB2_P4_CAM`
- JWT 없이 `SSID/PASS/CONNECT`를 받으면 재부팅 뒤 기존 `camera_id`로 재접속하는 동작은 코드로 확인했다(app_ble_prov.c `have_jwt`). 요청은 없다.
- 4번(`wifi_ssid`)·5번(b, `INFO`)은 카메라에도 똑같이 요청한다.

## 실기기 확인 목록 (앱 쪽)
1. 사육장 Wi-Fi 바꾸기 뒤 새 행이 없고 기존 행이 이어지는가 (P0-1)
2. 재부팅 뒤 새 Wi-Fi 유지 (P0-1)
3. 틀린 비밀번호 뒤에도 옛 Wi-Fi로 계속 붙는가 (P0-2)
4. 켠 뒤 광고 시간, 옛 공유기가 없을 때 계속 광고하는가 (P0-3)
5. `[device-add] wifi-target` 로그의 BLE 주소와 hw 끝 4자리 차이 (P1-5)
