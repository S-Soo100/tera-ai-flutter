## 1. 회신이 필요한 질문

### Q1. 온도 보정 "끔"과 펌웨어 기본 보정 −1.5℃

앱에 Figma "온도 보정" 화면이 생긴다. 토글 켬/끔, 빼기·더하기, 크기 0.1~4.0℃(0.1 단위)이고, 저장하면 `set_temp_offset`을 보낸다.
`docs/MQTT.md:90`에 따르면 기기는 보정값이 없을 때 빌드 기본값 `CONFIG_APP_TEMP_OFFSET_MDEG` = **−1.5℃**를 쓴다. 그래서 지금 운영 기기 대부분이 이미 −1.5로 보정된 값을 보내고 있다.

1. −1.5℃는 센서 오차를 바로잡는 **공장 보정**인가요, 임시 **기본값**인가요?
2. 앱의 "온도 보정 끔"은 기기에 **0**을 보내야 하나요, **−1.5로 되돌려야** 하나요?
3. 사용자 보정(예: 더하기 1.0)은 기기에 **그 값 그대로**(`offset_c=1.0`) 보내나요, **공장 보정에 더해서**(`−1.5 + 1.0 = −0.5`) 보내나요?
4. 지금 −1.5가 적용된 기기를 앱 첫 화면에서 "보정 꺼짐"으로 보여도 되나요?

> **앱 임시 결정(회신 전까지)**: 끔 = `offset_c: 0` 전송, 사용자 보정 = 그 값 그대로 전송. 첫 화면은 `temp_offset_c == 0`일 때만 "꺼짐"으로 보여 준다. 회신에 따라 바뀌는 건 "기기에 보낼 값" 계산 한 곳이다.

### Q2. 앱이 `POST /devices/{id}/commands`의 `set_temp_offset`을 쓴다

앱은 보정 저장에 이 REST 엔드포인트를 쓰기로 했다(`{"action":"set_temp_offset","payload":{"offset_c": <값>}}`, ±10 검증은 서버에 맡김). 지금 문서에는 "운영 콘솔 대행용"이라고 적혀 있다. 앱 사용자 JWT로 호출해도 문제없는지, 호출 빈도 제한이나 다른 제약이 있는지 알려 주세요.

저장 완료 판정은 `devices.temp_offset_c`가 보낸 값으로 바뀌는 것(최대 15초 대기)으로 한다. 기기가 적용한 뒤 보고까지 걸리는 시간이 이보다 길면 알려 주세요.

### Q3. 자동 환기·자동 분무 (Figma)

Figma 환기팬·분무 시트에 "자동 환기"·"자동 분무" 토글이 있다. 설명은 "습도 {MAX}% 초과 또는 온도 {MAX}℃ 초과 시 자동 환기를 시작하고, 적정 범위에 도달하면 종료", "습도가 {MIN}% 미만이면 자동으로 1회 분무"다.
서버·펌웨어에 이 기능 계획이 있는지 알려 주세요. 앱은 계약이 생길 때까지 이 토글을 만들지 않는다.
