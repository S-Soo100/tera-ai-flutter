## 1. 회신이 필요한 질문

### Q1. 온도 보정 "끔"과 펌웨어 기본 보정 −1.5℃

앱에 Figma "온도 보정" 화면이 생긴다. 토글 켬/끔, 빼기·더하기, 크기 0.1~4.0℃(0.1 단위)이고, 저장하면 `set_temp_offset`을 보낸다.
`docs/MQTT.md:90`에 따르면 기기는 보정값이 없을 때 빌드 기본값 `CONFIG_APP_TEMP_OFFSET_MDEG` = **−1.5℃**를 쓴다. 그래서 지금 운영 기기 대부분이 이미 −1.5로 보정된 값을 보내고 있다.

1. −1.5℃는 센서 오차를 바로잡는 **공장 보정**인가요, 임시 **기본값**인가요?
2. 앱의 "온도 보정 끔"은 기기에 **0**을 보내야 하나요, **−1.5로 되돌려야** 하나요?
3. 사용자 보정(예: 더하기 1.0)은 기기에 **그 값 그대로**(`offset_c=1.0`) 보내나요, **공장 보정에 더해서**(`−1.5 + 1.0 = −0.5`) 보내나요?
4. 지금 −1.5가 적용된 기기를 앱 첫 화면에서 "보정 꺼짐"으로 보여도 되나요?

> ~~**앱 임시 결정(회신 전까지)**: 끔 = `offset_c: 0` 전송, 사용자 보정 = 그 값 그대로 전송. 첫 화면은 `temp_offset_c == 0`일 때만 "꺼짐"으로 보여 준다. 회신에 따라 바뀌는 건 "기기에 보낼 값" 계산 한 곳이다.~~ → §5에서 회신대로 바꿨다.

### Q2. 앱이 `POST /devices/{id}/commands`의 `set_temp_offset`을 쓴다

앱은 보정 저장에 이 REST 엔드포인트를 쓰기로 했다(`{"action":"set_temp_offset","payload":{"offset_c": <값>}}`, ±10 검증은 서버에 맡김). 지금 문서에는 "운영 콘솔 대행용"이라고 적혀 있다. 앱 사용자 JWT로 호출해도 문제없는지, 호출 빈도 제한이나 다른 제약이 있는지 알려 주세요.

저장 완료 판정은 `devices.temp_offset_c`가 보낸 값으로 바뀌는 것(최대 15초 대기)으로 한다. 기기가 적용한 뒤 보고까지 걸리는 시간이 이보다 길면 알려 주세요.

### Q3. 자동 환기·자동 분무 (Figma)

Figma 환기팬·분무 시트에 "자동 환기"·"자동 분무" 토글이 있다. 설명은 "습도 {MAX}% 초과 또는 온도 {MAX}℃ 초과 시 자동 환기를 시작하고, 적정 범위에 도달하면 종료", "습도가 {MIN}% 미만이면 자동으로 1회 분무"다.
서버·펌웨어에 이 기능 계획이 있는지 알려 주세요. 앱은 계약이 생길 때까지 이 토글을 만들지 않는다.

## 4. 앱 Supabase 운영 반영 (2026-11-02)

## 5. 서버 회신 반영 (2026-11-03, 앱 0.166.0)

### 5.1 앱에 반영한 것

| 회신 | 앱 반영 |
|---|---|
| Q1 −1.5℃는 공장 보정, 끔 = −1.5 전송, 사용자 보정은 −1.5에 더해서 | `TempOffset.fromDevice`·`toDeviceValue`가 공장 보정 상수 `factoryDeviceValue = −1.5`를 거친다. `temp_offset_c = −1.5`는 **꺼짐**, −0.5는 "측정값 +1℃", −3.0은 "측정값 -1.5℃". 끔 = `offset_c: −1.5`. 편집기 끝값(±4)은 기기 값 −5.5 ~ +2.5 |
| Q1 `null`(구 펌웨어) | 보정 토글 잠금 + "펌웨어 업데이트 후 사용할 수 있어요". 보정값 설정 화면은 열리지 않는다(열려도 안내만) — 그래서 구 펌웨어용 ack 판정은 쓸 일이 없다 |
| Q2 사용자 JWT·빈도 제한 없음·보통 5초 | 저장은 한 번만 보내고 확인까지 버튼을 잠근다. 성공 = `devices.temp_offset_c`가 보낸 값과 같아짐(1차) 또는 `acked`·`result = ok`(이 경우 보고를 15초까지 더 기다린 뒤 성공). `no_ack`·`expired`·`lost`는 바로 "기기가 응답하지 않아요", 그 밖의 `result`는 "받지 못했어요", 15초 무소식도 "응답하지 않아요". 기기가 오프라인이면 저장 버튼을 막는다 |
| Q3 자동 환기·분무 계획 없음 | 토글을 만들지 않는다(그대로) |
| 끔 확인 모달(앱 계획 D1의 +1.5℃ 위험 대비) | 끔 = 공장 보정이라 온도가 튀지 않는다 — **모달 없이** 바로 보낸다(Figma에도 없음). 기기 확인까지 꺼진 모양으로 잠그고, 실패하면 켜짐으로 돌아오며 안내 |

### 5.2 서버에 돌려줄 답

| 항목 | 앱 답 |
|---|---|
| 1단계 `ALERTS_V4_ENABLED`(+`ALERTS_V4_SINCE`) | **켜도 됩니다.** 배포된 옛 앱은 `alerts`를 읽지 않아 영향이 없고, 새 앱(0.164 이상)이 실시간 이탈 카드를 그린다 |
| 2단계 `PUSH_ENV_ALERTS_ENABLED` | 회신대로 **앱 배포 후** 앱이 "켜도 됨"을 따로 보낸다(끄는 화면이 있는 0.165 이상). 아직 스토어 배포 전 |
| Stage N2(설정 범위 검증) PR #29 | **배포해도 됩니다.** 배포된 옛 앱은 MIN/MAX를 보내지 않고, 새 앱은 온도 15~29(0.5 단위)·습도 35~85(5 단위)·MIN < MAX 안의 값만 보낸다 |
| 보정 명령 | 앱 0.166.0부터 `set_temp_offset`을 사용자 JWT로 보낸다(위 5.1 값). 공장 보정이 보드마다 달라지면 `capabilities` 계약을 먼저 알려 달라 — 앱은 상수 한 곳만 바꾸면 된다 |
| ③④ 일일·주간 카드 | 앱 계획 작성 전. 하루 경계(서버 08:00~08:00 vs 앱 온습도 상세 자정 페이징)를 앱에서 먼저 정한 뒤 일정을 알린다 |
