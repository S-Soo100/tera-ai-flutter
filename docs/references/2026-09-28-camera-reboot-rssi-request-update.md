## 1. 확정된 것

### 1-1. 펌웨어 버전 문자열

- 형식 확정: `fb2-p4 <major.minor.patch>[-<build>]` (예: `fb2-p4 0.2.0-20260928`)
- 페어링 때 저장되는 값과 15초 하트비트로 갱신되는 값이 펌웨어의 같은 상수에서 나옵니다. 빌드마다 올라갑니다.
- → 이전 요청서 §2-1 의 `isNewFirmware()` 그대로 쓰시면 됩니다.

### 1-2. 재부팅 완료 신호

- `clip_stats.sys.reset` 값은 정확히 `"SW:mqtt_reboot"` 입니다.
- → 이전 요청서 §2-3 의 완료 판정(`uptime_s < before` AND `reset == "SW:mqtt_reboot"`) 그대로 쓰시면 됩니다.

### 1-3. 재부팅 소요 시간 (실측, 9/28 카메라 1대)

| 구간 | 시간 |
|---|---|
| 버튼 → 카메라 재부팅 시작 | 약 1.5초 |
| 재부팅 → 서버 재연결 | 약 12초 |
| 재부팅 → 첫 하트비트 (= 앱이 완료를 아는 시점) | 최대 약 27초 |

- 다이얼로그 문구 "약 30초 동안 꺼졌다 켜집니다" 그대로 두세요.
- 2분 타임아웃도 그대로 두세요. 정상이면 30초 안에 "재시작 완료"가 뜹니다.

## 2. 아직 기다리는 것 — REST 누락 필드

- 서버 코드는 main 에 수정이 들어갔고, **운영 서버 반영은 아직**입니다.
- 반영되면 REST `GET /cameras` · `GET /cameras/{id}` 에도 `clip_stats` · `rotate_180` · `capabilities` 가 제대로 실립니다.
- **그때까지는 이전 요청서 §1 그대로** Realtime 구독 + Supabase 직접 조회로 읽어 주세요. 반영되면 따로 알려드리겠습니다.

## 3. 테스트 방법 — 관훈님이 앱 빌드로 확인

지금 신 펌웨어 카메라는 **카메라 9 (p4cam-0d1b47b4) 1대**뿐이고, **관훈님 계정 소유**입니다. 앱 개발자 계정으로 로그인하면 이 카메라가 보이지 않고, 재부팅 API 도 404 가 납니다. 그래서 역할을 나눕니다.

### 3-1. 앱 개발 담당이 할 것

1. **구 펌웨어 카메라로 "없음 처리" 확인** (본인 계정의 아무 카메라)
   - 재시작 버튼이 **보이지 않음**
   - WiFi 약함 배너가 **뜨지 않음**
   - 에러 · 크래시 없음
2. **WiFi 약함 배너 로직은 테스트 코드로 확인** — 카메라 9 는 신호가 강해서(rssi −36) 실기로는 배너를 띄울 수 없습니다. 아래 경우를 가짜 데이터로 확인해 주세요.
   - −75 이하가 연속 4번 → 배너 뜸
   - 3번 연속 후 −74 → 카운트 초기화, 배너 안 뜸
   - 같은 `clip_stats_at` 이 반복 수신 → 1번으로 셈
   - 배너가 뜬 뒤 값이 좋아져도 → 사용자가 닫기 전까지 유지
3. **운영 서버를 바라보는 테스트 빌드**(TestFlight / APK 등)를 관훈님께 전달

### 3-2. 관훈님께 부탁할 것 (빌드 받은 뒤, 카메라 9 로)

| # | 확인 | 기대 결과 |
|:---:|---|---|
| 1 | 카메라 9 상세 화면 | "카메라 재시작" 버튼이 보임 |
| 2 | 버튼 누름 | 확인 다이얼로그 문구 표시 |
| 3 | [재시작] | "재시작 중…" 표시 → **30초 안에** "재시작 완료" |
| 4 | 완료 직후 다시 누르기 | 60초 동안 버튼 비활성 |
| 5 | 라이브 보기 중 재시작 | 라이브 끊김 → 완료 후 다시 열면 정상 |
| 6 | 카메라 9 상세 화면 | WiFi 약함 배너가 **안 뜸** (신호 강함) |

결과(통과/실패 + 실패 시 화면 캡처)를 앱 개발 담당에게 바로 공유해 달라고 관훈님께 요청해 두겠습니다.

> 2분 타임아웃 안내("전원을 뽑았다가…")는 정상 카메라로는 재현이 안 됩니다. 3-1 의 테스트 코드처럼 가짜 데이터로 확인해 주세요.
