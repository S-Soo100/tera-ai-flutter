## 1. 데이터를 어디서 읽나

- REST `GET /devices` · `GET /devices/{id}` 와 `devices` Realtime UPDATE 모두 `sys_state` 가 들어 있습니다. (카메라 때 같은 REST 누락은 없습니다.)
- 재시작 명령 결과는 앱이 이미 쓰는 **`commands` Realtime 구독**으로 받습니다.
- ⚠️ 서버 운영 배포 전에는 `sys_state` 가 항상 `null` 이고 재시작 API 는 404 입니다. 버튼 노출 조건(§2-1) 때문에 화면에는 아무것도 안 나오니 앱 쪽 대응은 필요 없습니다.

## 2. 기기 재시작 버튼

### 2-1. 위치 · 노출 조건

- **위치**: 사육장 기기 상세 화면 (카메라와 같은 자리)
- **노출 조건**: `is_online == true` **그리고** `sys_state != null`
- 조건이 안 맞으면 **버튼 자체를 숨김**

### 2-2. 누르면

1. **확인 다이얼로그**
   > 기기를 재시작할까요?
   > 약 20초 동안 꺼졌다 켜집니다. 켜져 있던 펌프·팬·조명은 모두 꺼집니다.
   > **예약으로 켜져 있던 조명·팬은 다음 예약 시각까지 꺼져 있을 수 있어요.**
   >
   > [취소] [재시작]

   굵은 문장은 **임시 문구**입니다. 서버가 재부팅 뒤 예약 상태를 다시 켜 주는 기능을 요청해 둔 상태라, 배포되면 이 문장만 빼 달라고 따로 알려드리겠습니다.

2. **호출**: `POST /devices/{device_uuid}/reboot` (본문 없음, 사용자 JWT)
   - `commands` 에 직접 INSERT 하는 방법도 있지만, REST 를 써 주세요. 서버가 소유권 검증과 TTL 60초를 넣어 줍니다.

3. **응답 처리**

| 응답 | 화면 |
|---|---|
| `201 { "id": "<command id>", "action": "reboot", "status": "pending" }` | `id` 를 기억하고 2-3 진행 표시로. 버튼 60초 비활성 |
| `404` | 토스트 "기기를 찾을 수 없어요" |
| 그 밖의 에러 (5xx · 네트워크) | 일반 에러 토스트 |

### 2-3. 진행 표시 · 완료 판정 · 실패 처리

기기는 카메라와 달리 명령 결과(`commands`)가 오고, 완료는 `devices` Realtime 으로 판정합니다.

```
[버튼 누름 직전] 현재 sys_state.uptime_s 를 기억 (= before)
      │
      ▼
 "재시작 중…" 표시
      │
      ├─ commands Realtime (id = 2-2 에서 받은 id)
      │    status == "acked" AND result == "ok"   → 계속 기다림 (기기가 명령을 받음)
      │    status == "acked" AND result != "ok"   → 실패 (아래 표)
      │    status == "no_ack"                      → 실패 (아래 표)
      │
      ├─ devices Realtime UPDATE 에서
      │    sys_state.uptime_s < before
      │    AND sys_state.reset == "SW:mqtt_reboot"
      │      → "재시작 완료" 토스트, 진행 표시 해제
      │
      └─ 2분 동안 완료 신호 없음
           → "기기가 응답하지 않아요. 전원을 뽑았다가 다시 꽂아 주세요." 진행 표시 해제
```

| 실패 신호 | 안내 |
|---|---|
| `status == "no_ack"` | "기기가 응답하지 않아요. 잠시 후 다시 시도해 주세요." |
| `result == "unknown_action"` | "기기 펌웨어 업데이트가 필요해요." |
| 그 밖의 `result` | "재시작하지 못했어요. 잠시 후 다시 시도해 주세요." |

⚠️ **`status` 만 보지 마세요.** 기기가 명령을 거부해도(`unknown_action` 등) `status` 는 `"acked"` 로 기록되고 `result` 만 달라집니다. 성공은 `result == "ok"` 뿐입니다.

⚠️ **기존 명령 결과 토스트와 겹치지 않게 해 주세요.** 앱에 `commands` 결과를 "✓ 완료"로 보여주는 공통 처리가 있다면, `action == "reboot"` 은 그 공통 토스트에서 빼 주세요. ack 는 재부팅 **직전**에 오기 때문에, 여기서 "완료"가 뜨면 실제로는 막 꺼지려는 순간입니다.

- 소요 시간은 아직 실측 전입니다(백엔드 예상 10~20초). 2분 타임아웃이면 충분합니다.
- 재시작 중에도 `is_online` 은 보통 `true` 로 유지됩니다(오프라인 판정 3분).
- 사용자가 화면을 나가면 진행 표시는 버려도 됩니다.

### 2-4. 재부팅 뒤 화면

- 펌프·팬·조명은 **모두 OFF** 에서 시작합니다. 기기 telemetry 가 OFF 로 보고하니, 제어 화면의 켜짐/꺼짐 표시는 평소처럼 telemetry 를 따라가면 됩니다(따로 처리 불필요).
- 분무 중에 재시작해도 기기가 부팅 초기에 펌프를 끄므로 안전합니다.

## 3. WiFi 약함 배너

카메라와 같은 규칙이고, 보고 주기만 다릅니다.

- **평소에는 신호 세기를 보여주지 않습니다.**
- **조건**: 기기 상세 화면을 보는 동안 `sys_state.rssi` 가 **약 1분 동안 계속 −75 이하** — 기기는 3초마다 보고하므로 **서로 다른 보고 20번 연속**.
  - "서로 다른 보고"는 `last_seen_at` 이 바뀐 UPDATE 만 셉니다.
  - −74 이상이 한 번이라도 오거나, `rssi` 키가 없는 보고가 오면 카운트를 0 으로.
  - 화면을 나가면 카운트 초기화.
- **표시**: 기기 상세 상단 배너
  > WiFi 신호가 약해요. 기기를 공유기와 더 가까운 곳에 두거나 공유기를 가까이 옮겨 주세요.  [닫기]
- 한 번 뜬 배너는 **사용자가 닫을 때까지 유지**, 닫으면 그 화면 방문 동안은 다시 띄우지 않음.
- `sys_state` 가 `null` 이면 아무것도 하지 않습니다.

> 카메라 배너 로직과 공통 코드로 만들고 "연속 횟수"만 기기 20 / 카메라 4 로 넘기는 방식을 권장합니다.

---

## 4. 표시하지 않는 필드

`sys_state.reset`(2-3 완료 판정에만 사용) · `sys_state.heap` · `sys_state.uptime_s`(판정에만 사용)는 **화면에 표시하지 않습니다.** 진단은 운영 콘솔에서만 합니다.

## 5. 구 펌웨어 처리

| 상황 | 앱 동작 |
|---|---|
| `sys_state == null` | 재시작 버튼 숨김, 배너 없음 |
| `sys_state` 는 있는데 `rssi` 키 없음 | 배너 카운트만 0 으로, 에러 없음 |

어떤 키가 없어도 크래시 · 에러 표시 없이 "없음"으로 처리해 주세요.
