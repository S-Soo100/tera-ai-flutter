## 1. 데이터를 어디서 읽나 — ⚠️ REST 누락 주의

현재 REST `GET /cameras` · `GET /cameras/{id}` 응답에는 아래 필드가 **빠져 있습니다**. 서버 수정 PR 을 준비 중이지만, 배포 전까지는 REST 로 받으면 값이 틀립니다.

| 필드 | REST 응답 (현재) | Realtime / `sb.from('cameras').select()` |
|---|---|---|
| `firmware_ver` | ✅ 정상 | ✅ |
| `clip_stats` · `clip_stats_at` | ❌ 항상 `null` | ✅ |
| `rotate_180` | ❌ **항상 `false`** | ✅ |
| `capabilities` | ❌ 항상 `null` | ✅ |

**요청**: 이번 기능은 `cameras` 행을 **Realtime 구독 + Supabase 직접 조회**로 읽어 주세요. 이미 REST 로 `rotate_180` 을 읽고 있는 곳이 있다면 같이 확인 부탁드립니다. 서버 PR 이 배포되면 REST 도 쓸 수 있게 되고, 그때 따로 알려드리겠습니다.

## 2. 카메라 재시작 버튼

### 2-1. 위치 · 노출 조건

- **위치**: 카메라 상세 화면
- **노출 조건**: `is_online == true` **그리고** 신 펌웨어(`firmware_ver` 버전 ≥ `0.2.0`)
- 조건이 안 맞으면 **버튼 자체를 숨김** (비활성 표시 X). 구 펌웨어에서는 눌러도 아무 반응이 없어서 혼란만 줍니다.

펌웨어 버전 판별 — 문자열 비교 말고 숫자로 파싱해 주세요. 형식은 `"fb2-p4 0.2.0-20260928"` 처럼 `<이름> <major.minor.patch>[-<빌드>]` 입니다.

```dart
/// 신 펌웨어(0.2.0 이상)면 true. null · 파싱 실패 · 구 펌웨어("fb2-p4 0.1.0")는 false.
bool isNewFirmware(String? fw) {
  if (fw == null) return false;
  final m = RegExp(r'(\d+)\.(\d+)\.(\d+)').firstMatch(fw);
  if (m == null) return false;
  final v = [1, 2, 3].map((i) => int.parse(m.group(i)!)).toList();
  const min = [0, 2, 0];
  for (var i = 0; i < 3; i++) {
    if (v[i] != min[i]) return v[i] > min[i];
  }
  return true;
}
```

> 버전 문자열 형식은 백엔드에 최종 확인 요청 중입니다. 파싱 실패 시 `false`(숨김)로 두면 형식이 달라도 안전합니다.

### 2-2. 누르면

1. **확인 다이얼로그**
   > 카메라를 재시작할까요?
   > 약 30초 동안 꺼졌다 켜집니다. 라이브 보기와 녹화가 잠시 중단됩니다.
   >
   > [취소] [재시작]
2. **호출**: `POST /cameras/{camera_uuid}/reboot` (본문 없음, 사용자 JWT)
3. **응답 처리**

| 응답 | 화면 |
|---|---|
| `200 { "published": true, "msg_id": "…" }` | 2-3 진행 표시로 넘어감. 버튼 60초 비활성 |
| `200 { "published": false, "msg_id": null }` | 토스트 "잠시 후 다시 시도해 주세요" · 버튼 바로 다시 활성 |
| `404` | 토스트 "카메라를 찾을 수 없어요" (해제되었거나 타인 카메라) |
| 그 밖의 에러 (5xx · 네트워크) | 일반 에러 토스트 |

- `msg_id` 는 저장할 필요 없습니다.
- 라이브 보기 중이었다면 WebRTC 가 끊깁니다. 재시작 완료 후 사용자가 다시 열면 됩니다(자동 재연결 불필요).

### 2-3. 진행 표시 · 완료 판정 · 2분 타임아웃

앱은 카메라의 ack 를 직접 받지 못해서, `cameras` Realtime 으로 완료를 판정합니다.

```
[버튼 누름 직전] 현재 clip_stats.sys.uptime_s 를 기억 (= before)
      │
      ▼
 "재시작 중…" 표시
      │
      ├─ Realtime UPDATE 에서
      │    clip_stats.sys.uptime_s < before
      │    AND clip_stats.sys.reset == "SW:mqtt_reboot"
      │      → "재시작 완료" 토스트, 진행 표시 해제
      │
      └─ 2분 동안 위 신호 없음
           → 안내: "카메라가 응답하지 않아요. 전원을 뽑았다가 다시 꽂아 주세요."
             진행 표시 해제
```

- 정상이면 20~40초 안에 완료 신호가 옵니다(백엔드 추정치).
- 재시작 중에는 `is_online` 이 보통 `true` 로 유지됩니다(오프라인 판정 3분). 중간에 `false` 가 되어도 타임아웃까지는 그대로 기다립니다.
- 사용자가 화면을 나가면 진행 표시는 버려도 됩니다(재진입 시 복원 불필요).

## 3. WiFi 약함 배너

- **평소에는 신호 세기를 보여주지 않습니다.** 아이콘 X.
- **조건**: 카메라 상세 화면을 보는 동안 `clip_stats.sys.rssi` 가 **연속 4번(약 1분) −75 이하**.
  - "연속"은 서로 다른 heartbeat 기준입니다. `clip_stats_at` 이 바뀐 UPDATE 만 셉니다.
  - 중간에 −74 이상이 한 번이라도 오면 카운트를 0 으로 되돌립니다.
  - 화면을 나가면 카운트도 초기화합니다.
- **표시**: 카메라 상세 상단 배너
  > WiFi 신호가 약해요. 카메라를 공유기와 더 가까운 곳에 설치해 주세요.  [닫기]
- 한 번 뜬 배너는 **사용자가 닫을 때까지 유지**합니다(값이 좋아져도 자동으로 사라지지 않음 — 깜빡임 방지). 닫으면 그 화면 방문 동안은 다시 띄우지 않습니다.
- `rssi` 키가 없으면(구 펌웨어) 아무것도 하지 않습니다.

> 경계 −75: 백엔드 원문은 "−75 미만 약함"으로 적혀 있지만 운영 콘솔 기준(−75 이하 빨강)으로 통일하기로 했습니다. 앱도 **−75 이하 = 약함**.

## 4. 표시하지 않는 필드

아래 필드는 **앱에 표시하지 않습니다.** 진단은 운영 콘솔에서만 합니다.

`last_err` · `sys.reset`(2-3 완료 판정에만 사용) · `up_fail` / `up_ok` · `up_busy_s` · `last_rec_s` · `sys.heap`

## 5. 구 펌웨어 처리 (지금 18대 전부 해당)

| 상황 | 앱 동작 |
|---|---|
| `firmware_ver` 가 `null` 또는 `"fb2-p4 0.1.0"` | 재시작 버튼 숨김 |
| `clip_stats` 가 `null` / `sys` 없음 / `rssi` 없음 | 배너 없음, 에러 없음 |

어떤 키가 없어도 크래시 · 에러 표시 없이 "없음"으로 처리해 주세요.
