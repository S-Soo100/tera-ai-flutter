# 재설계 앱 제어 구현 및 서버 회신 반영

2026-09-15. `.worktrees/redesign-20260915`, `codex/figma-redesign-20260915`.
사용자는 이관훈님 회신 수신과 petcam-lab 작업 진행을 알리고 앱 구현 계속을 지시했다.
전체 재설계 완료 기록이 아니라 이번 구현 단위와 남은 계약을 보존하는 문서다.

## 사용자 체험과 구현 결과

- [화면] 냉각팬 ON/OFF, 미보고는 `--` → [조작] 꺼진 팬 탭 → [반응] 10/30/60/120분·연속 중 선택, 시작 버튼에서만 명령 → [감정] 작동 시간을 알고 실행한다. 취소는 명령을 보내지 않는다. 켜진 팬 탭은 해당 팬 OFF다.
- 환기팬과 냉각팬은 선택 기억값·타이머·알림 ID를 분리한다. 원래 환기팬 저장 키와 알림 ID는 보존했다. 두 팬이 돌면 두 타이머를 표시한다. 미보고 냉각팬은 탭/길게 누르기 모두 비활성이다.
- [화면] LED 실제 보고값 75% → [조작] 밝기창 열기 → [반응] 선택 제안만 80%, 20~100%/10% 단위 → [감정] 현재 상태와 적용할 설정을 구분한다. 적용 전 전송하지 않으며 대상 변경/오프라인이면 전송을 막는다. 밝기 미지원 보드는 켜기/끄기만 제공한다.
- [화면] LCD 입력과 20자 카운터 → [조작] 적용 → [반응] 공백 포함 20 grapheme 이내 전송, 전송 중 입력/버튼 잠금, 실패 입력 보존 → [감정] 중복 전송 없이 재시도한다. 중복 허용, 기기 이름과 독립. 현재 문구 GET이 없어 앱 캐시를 현재 기기 문구처럼 보여주지 않는다.
- fan2 wire/telemetry/일정 on·off/구간 편집/기록·마커를 함께 확장했다. 기존 일정을 삭제하거나 일괄 변환하지 않았다.
- 기록 36px, 차트 28px는 `redesign_v2/3636`, `2828` 전용 SVG를 원래 크기와 색으로 사용한다. 새 세트에 없는 히터 안전 아이콘과 분무 OFF 원본은 기존 표현을 유지한다. 홈 40px 아이콘·전체 화면 Figma 일치 검수는 별도다.
- ACK 결과 `ok`만 성공 기록으로 해석한다. `acked/busy`, `acked/error` 등은 팬 타이머 시작/종료로 적용하지 않는다. ACK 유예 후 팬 이력을 재조회해 로컬 알림도 조정한다.
- 냉각팬 로컬 알림은 설정 시간 경과 안내다. 실제 자동 OFF 완료 이벤트로 표시하지 않는다. 앱 중단/조회 실패/다른 기기 조작을 실시간 보장하는 서버 ended 기능은 아직 없다.

## 로컬 메모 기반

`ClipMemo`와 `HiveClipMemoRepository`를 추가하고 실제 임시 Hive 파일로 검증했다. account+clip 키, 계정별 마지막 색, 6색 무작위·직전 색 제외, 수정 시 색 유지, 삭제 후 재생성, 동시 저장 직렬화, 재시작 유지, 계정 격리를 포함한다. 서버·북마크 저장소 의존성은 없다.

**저장소 기반만 완료**했다. 앱 bootstrap/provider와 전체 영상 편집·북마크 메모 카드 UI는 아직 연결하지 않았다. 기존 `clip_favorites` 동기화를 변경하지 않았다.

## 이관훈님 회신 반영

원문: [재설계 회신](../references/2026-09-15-backend-redesign-reply.md), [푸시 회신](../references/2026-09-15-backend-push-reply.md). Desktop 원문을 보관했다. 문서 속 작업 요청/샘플 SQL은 제안으로 읽었으며 실행하지 않았다.

| 항목 | 확인된 현행/제안 | 앱 처리 및 담당 |
|---|---|---|
| 최초 등록 | 펌웨어 pair API, BLE JWT, `PAIR_OK <device_id>`; Wi-Fi/등록/온라인 성공은 별개 | 우리 BLE UI 연결 전 지원 확인. claim·멱등 키·hardware ID 부족은 이관훈님 보완 |
| 등록 해제 | 현행 devices/cameras DELETE는 기록 cascade 삭제. soft unlink는 제안 | 기존 DELETE를 새 해제 버튼에 연결 금지. 이관훈님 보완 필요 |
| 영상 숨김 | 현행 clips DELETE는 R2+DB 삭제 | 우리 앱 전용 숨김 데이터 설계; 원본 DELETE 사용 금지 |
| 과거 접근 | clip owner는 촬영 당시 보존, telemetry는 devices.owner_id를 따라 소유권 변경 위험 | 이관훈님 접근권 보완 + 우리 연결 이력/legacy 승계 |
| 그룹/이름 | 서버 이름 유일성·10자·기본 번호·유형당 1개 원자성 미지원 | 우리 SQL/RPC 초안, 이관훈님 공통 write/trigger 검토·적용. 이름 표준화/409 계약 필요 |
| pets/RPC | 회신은 백엔드 저장소에서 없다고 조사했지만 앱은 pets와 assign_pet_to_enclosure 사용 중 | 운영 schema 확인 전 없다고 단정하거나 덮어 만들지 않음 |
| 온습도 평균 | sample_count는 전체 행 수. 지표별 count/오류 필터 보완 제안 | 이관훈님 보완, t_a_count/h_a_count/t_b_count/h_b_count 최종 응답 후 매핑. 복구 불가능한 과거는 null |
| 활동/coverage | 수집 이력 원장 부족, petcam-lab 주관 | petcam-lab 진행 중. 활동 구간·완료/결측·공개 메타 수신 후 통합 |
| fan2/LED/분무/LCD | 기존 계약으로 앱 구현 가능 | 우리 직접 구현. 서버 신규 배포 불필요. 실기기 검증 별도 |

그룹 삭제의 현행 SET NULL만으로 과거 연결 이력이 보존되지는 않는다. 기존 사용자 기록 유지와 신규 개체 연결 이후 귀속 정책을 함께 지켜야 한다.

## 푸시 회신에서 남은 결정

- ACK 성공/실패는 status가 아니라 원문 result로 판단한다. 앱 기록·타이머에 반영했다.
- 제안된 outcome 정규화 + result 원문 분리, device_id UUID + device_key TEXT, issued_by/source_id 정합성은 기존 알림 계약과 대조 후 반영할 항목이다. 새 푸시 배포 완료로 보지 않는다.
- ended는 구간 일정의 명시 OFF에서 관측 가능하나 oneshot 자동 타이머 종료 ACK는 없다. 구간 일정에만 ended를 제공하는 제안 A의 사용자 승인/최종 계약은 아직 없다.
- source=manual에 수동 duration이 포함된다. source=timer 정의, guard 스킵/no-ACK 알림 범위도 합의가 남았다. 임의로 서버 동작이나 승인 범위를 확대하지 않는다.
- 외부 답신 전송/서버 배포/운영 SQL은 실행하지 않았다.
