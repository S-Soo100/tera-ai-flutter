## 3. 계획과 달라진 점

- **진단 내보내기 위치:** 계획은 환경설정(`/env-settings`)이었으나 그 화면은 **앱 안 진입점이 없다**(9/18 점검 미결). 마이페이지 "앱 설정"의 화면 모드 아래로 옮겼다(0.133.9).
- **망 변경 유예 조건:** 계획은 `streaming`일 때만 유예했지만 `stalled`(영상 있음)도 포함했다.
- **정지 테스트 틱 수:** 첫 샘플은 진행으로 세므로 "마지막 진행 뒤 5틱"으로 테스트를 맞췄다.

## 4. 남은 검증

- ~~Android 실기기 같은 Wi-Fi 장시간 시청~~ → §5 (S21+ 약 32분 + 6분). **iOS 실기기**는 미시험.
- ~~휴대폰 망 단절 후 복구~~ → §5 (버그 2건 발견·수정·재확인). Wi-Fi↔셀룰러 전환 10회·반복 단절은 미시험.
- **약한 신호**(휴대폰 쪽): 시험 환경 Wi-Fi가 너무 강해 재현하지 못했다. 거리 두기·핫스팟 대역 제한·공유기 QoS로 재시도.
- **카메라 쪽 약한 Wi-Fi**(고객 제보에 가까움): 카메라를 공유기에서 멀리 두고 정지 원인이 `no-data`인지 확인.
- 카메라 전원 차단(→ `recovering` → 카메라 오프라인 `failed` → 전원 복귀 시 자동 연결), 배터리 소모.
- "다시 연결" 연타 시 서버 로그 offer 1건.
- 1초 getStats 비용이 크면 `kWebRtcStatsInterval` 2초로 조정하고 감지 지연(틱 × 2초)을 보고.

## 5. Android 실기기 시험 (Galaxy S21+ SM-G996N · 릴리즈 빌드 · 2026-09-24)

같은 Wi-Fi, 실카메라 `953f913d`. 로그는 `flutter run --release` + `adb logcat`의 `[webrtc-timing]`(로컬 진단과 같은 내용).

### 5.1 `0.133.10` — 장시간 시청·앱 복귀·망 끊김

| 항목 | 결과 |
|---|---|
| 첫 화면 | 진입 4.0초(응답 1.6·연결 2.3), **앱 복귀 후 2.7초** |
| 앱 복귀 | `suspend` → `resume` → 연결 시도 1회(중복 없음) |
| 연속 재생 | 약 32분(01:32:53~02:05:16) 동안 **정지 2회**(01:47:06, 02:11:33 — 각 약 6초). 둘 다 `stall-soft` → 1초 뒤 `stall-recovered`, **재연결 없이 자체 회복** |
| 휴대폰 망 끊김 | 5초 안내 → 15초 실패 ✅, 그러나 **"카메라가 오프라인이에요" 오안내 ❌**, 같은 Wi-Fi 복귀 후 **자동 재연결 안 됨 ❌**(수동 "다시 연결" 필요, 이후 카메라 응답 0.7초 — 카메라는 온라인이었음) |

위 두 결함은 `0.133.11`에서 수정했다: 망 없음 판정을 카메라 오프라인보다 먼저, 망이 끊겼다 돌아오면 어떤 대기 상태든 한 번 재연결.

`0.133.10`의 정지 2회는 수신량 진단이 없던 빌드라 **원인(카메라 송출 vs 디코딩)을 판정하지 못했다.** 이 공백을 `0.133.12`에서 메웠다(§5.2).

### 5.2 `0.133.12` — 망 끊김 수정 재확인 + 정지 원인 진단

앱을 지우지 않고 업데이트 설치(로그인 유지).

```text
t=0.0s    start → answer 1.6s(offer_attempts=1) → connected 2.3s → first-frame 4.4s
t=34.4s   stable
t=382.1s  network-none                         ← 휴대폰 Wi-Fi 끔
t=385.4s  stall-soft  cause=no-data bytes_delta=0 lost_delta=0
t=395.4s  stall-hard  cause=no-data bytes_delta=0 → fail(outcome=stalled)
          wait-network                         ← "휴대폰이 인터넷에 연결되어 있지 않아요" ✅
t=401.1s  network-back → restart reason=network-back   ← 버튼 없이 자동 ✅
+0.6s answer · +1.3s connected · +3.1s first-frame · +33.1s stable
```

| 항목 | 0.133.10 | 0.133.12 |
|---|---|---|
| 망 끊김 안내 | ❌ 카메라 오프라인 | ✅ 휴대폰 인터넷 없음 |
| 망 복귀 | ❌ 수동 필요 | ✅ 자동, 첫 화면 3.1초 |
| 정지 원인 | 판정 불가 | ✅ `no-data`(실제 상황과 일치) |

부수 관찰:
- 망이 없던 동안 원격 `webrtc_connect_logs` INSERT 1건이 DNS 실패로 유실됐다(기획 §6의 예고된 한계). 같은 내용은 앱 내부 진단 버퍼에 남는다.
- 같은 시각 `[fan-timer-notif] resync query failed`(DNS 실패)가 찍혔다 — 망 없음의 예상 오류이며 라이브·앱 동작에 영향 없음.

### 5.3 이 시험으로 말할 수 있는 것과 없는 것

- **말할 수 있음:** 강한 같은 Wi-Fi에서 Android 릴리즈 빌드의 첫 화면(3~4.4초)·앱 복귀·휴대폰 망 단절 복구는 설계대로 동작한다. 짧은 정지(약 6초)는 연결을 끊지 않고 회복한다.
- **말할 수 없음:** 약한 신호, 카메라 쪽 무선 품질, iOS, 녹화·업로드와의 경합, 장기(수 시간) 안정성. 표본 1대·1카메라라 비율(성공률·정지율)은 산출하지 않는다.
