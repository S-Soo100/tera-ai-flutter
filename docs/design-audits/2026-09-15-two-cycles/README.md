## 구현한 체험 흐름

- [화면] 기기 연결 성공 → 등록된 개체 카드. [조작] 한 마리 선택. [반응] 선택300 체크와 저장 버튼 활성화. [체감] 어떤 개체를 연결할지 명확히 확인.
- [조작] 다른 그룹 개체 선택 → 기존 이동 확인. 취소하면 기존 선택 유지. 저장은 기존 기기/카메라를 보존하고 개체만 교체.
- [반응] 실패하면 오류와 선택을 유지. ‘나중에 하기’는 쓰기 없이 홈으로 이동. 개체가 없으면 등록 경로 제공.
- [화면] 종 입력칸 → [조작] 열기 → [반응] 입력칸 아래 흰 목록. 신규 종은 크레스티드 게코 한 항목, 기존 다른 종은 그대로 유지. 바깥을 누르면 선택 변경 없이 닫힘.

## 검증

- 수정 화면 기능·캡처 검증 **22 통과**.
- 전체 Flutter 회귀 **864 통과 / 7 skip**. 마지막 큰 글자 버튼 보완 후 해당 공통 위젯을 사용하는 사육장·카메라 관련 전체 테스트 **290 통과 / 1 skip**으로 재검증.
- `flutter analyze --no-pub`: **오류 0 / 경고 0**, 기존 info 6.
- 시뮬레이터 검수 빌드 성공. 실제 시뮬레이터에서 개체 선택, ‘나중에 하기’ 홈 복귀, 종 팝업 열기/닫기를 확인하고 `final/simulator-*.png` 저장.
- `final/pairing-*`, `final/redesign-*` 등은 **Flutter 위젯 렌더링**이다. 일부 렌더링 글꼴 두께는 네이티브와 차이가 있어 실제 글꼴·그림자는 시뮬레이터 이미지로 교차 확인했다.
- 화면의 개체/측정값은 **로컬 검수 데이터**다. 서버·BLE 실기기 연결 및 운영 데이터 쓰기는 수행하지 않았다. 실제 그룹 저장은 기존 RPC 계약을 사용하며 이번 검증은 mock RPC다.
- QA 진입점은 재현용 `.dart.txt`만 보관한다. 시뮬레이터는 일반 `lib/main.dart` 빌드로 복원한다.

## 유지한 기능상 차이와 검수 한계

- **빈 비밀번호 버튼**: 원본은 비활성이지만 현 BLE AP 모델에는 보안 방식 정보가 없다. 개방형 AP를 막지 않도록 기존 빈 비밀번호 연결 동작을 유지했다. UI 일치만을 위해 공백 차단을 추가하지 않았다.
- 다시 검색/직접 입력/다른 네트워크 선택은 기존 복구 기능으로 유지했다. 원본의 성공 경로 캡처에 없는 버튼도 이 때문에 남는다.
- 종 목록은 승인대로 한 종이므로 원본 여러 종 사이의 구분선이 현재 화면에 나타나지 않는다.
- 이번 두 차례 비교의 집중 범위는 직전 원본 검수에서 남은 **기기 연결·개체 선택·종 팝업**이다. 홈은 시뮬레이터 캡처로 재확인했으며, 모든 탭의 모든 팝업을 전수 재검증했다는 의미는 아니다.
- 추가 네이티브 화면 검수 중 Mac이 잠겼다. 이미 저장한 위 3개 시뮬레이터 화면과 위젯 검증을 완료 근거로 삼았다. 메인 탭 드롭다운 그림자의 원본 효과 수치 전수 확인은 여전히 별도 확인 대상이다.
