## 0. 이 문서에 대하여

### 0.1 왜 새로 썼나

2026-08-08까지 구현된 화면 디자인이 기획 의도를 만족하지 못했다. 그래서 **기존 구현을 전제하지 않고**, 노션 기획서·PRD만으로 요구사항을 다시 정리했다.

### 0.2 작성 원칙

1. **구현 역산 금지.** "지금 이렇게 돼 있으니까"는 근거가 아니다. 원문에 있는 것만 적는다.
2. **없는 것은 없다고 쓴다.** 원문이 기능 요약 수준까지만 정한 영역은 그 사실을 명시하고, 화면을 지어내지 않는다.
3. **원문의 물음표를 지우지 않는다.** "논의 필요", "좀더고민", "굳이 필요없나?" 같은 표기는 **미결로 §6에 그대로 남긴다.** 해석해서 확정으로 바꾸지 않는다.
4. **레이아웃보다 의도.** 원문 와이어프레임은 *"이해를 돕기위한 예시 이미지~ 세부내용은 달라질수있습니다"*라고 명시돼 있다. 이 기획안은 **화면이 무엇을 해야 하는가**를 규정하고, 픽셀 배치는 디자인 단계에 넘긴다.

### 0.3 Figma를 근거에서 뺀 이유

Figma `Final Design`의 주력은 **현재 앱에 대한 피드백 보드**이고, 완성된 화면 설계는 통계 24시간 그래프 하나뿐이다. 즉 "구현을 평가한 결과물"이라 **구현 배제 원칙과 충돌**한다.
다만 Figma의 **디자인 시스템**(컬러 팔레트·타이포·컴포넌트)은 기획이 아니라 표현 규격이므로, 디자인 단계에서 그대로 쓴다 → `docs/figma-final-design-transcript.md` §4.

## 1. 제품 개요

### 1.1 정의

> 게코를 위한 **스마트 사육장**과 **소형 캠**에 연동해 쓰는 앱.
> 핵심은 **사육장 온습도 조절 장치의 원격 조정**과 **펫캠 확인**이다.

### 1.2 제품 라인업 — 화면 분기의 근원

사용자가 무엇을 샀는지에 따라 앱이 달라진다. **모든 화면 분기는 이 한 축에서 나온다.**

| 라인업 | 사육장 | 캠 | 앱이 할 수 있는 것 |
|---|---|---|---|
| **통합 세트** | ○ | ○ | 전부 |
| **사육장 단품** | ○ | ✕ | 환경 제어·환경 통계만. 영상·행동 데이터 없음 |
| **캠 단품** | ✕ | ○ | 영상·행동 데이터만. 환경 제어·환경 통계 없음 |

**규칙**: 미보유 기능은 **숨기지 않고 비활성으로 노출**한다. 없애면 "지원하지 않는 기능"으로 오해한다.

> ⚠️ 원문 미결: *"라인업이 나뉘었을 때 미사용 기능을 어떻게 처리할 것인지?"* — 비활성 노출은 PRD §3.3(서브탭 분기)에서 확인되는 방향이나, 전 화면 공통 규칙으로 확정된 문구는 없다.

### 1.3 사육장 : 개체 관계 — **1:1 확정**

> ✅ **결정 (2026-08-08)**: 원문 전제대로 **1 사육장 : 1 캠 : 1 개체**로 간다.

원문 댓글에 1:N 제안이 달려 있었으나,

> **"크레를 포함해서, 1:N(한개의 사육장, n마리의 도마뱀)이 되어야 할 거 같아요!"**

**당장은 1:1로 확정한다.** 이 기획안의 모든 화면·데이터 서술은 1:1을 전제로 한다.

**1:N은 폐기가 아니라 후속 과제로 보류**다. 나중에 다시 올라올 때를 위해 영향 범위 분석을 §6-A에 남겨 뒀다. 다만 **지금 1:N을 미리 대비해 구조를 열어두지는 않는다** — 화면 설계가 없는 상태에서 미리 열면 실제 요구가 왔을 때 다시 뒤집힐 가능성이 크다.

**1:1 확정이 주는 것** (이 기획안이 기대는 단순화):

- 사육장을 고르면 곧 개체를 고른 것이다 → 헤더 드롭다운 하나로 끝난다
- 그 사육장의 온습도가 곧 그 개체의 환경이다 → 통계에서 환경과 행동을 바로 겹쳐 읽을 수 있다
- 캠에 찍힌 것은 그 개체다 → **영상 속 개체 식별이 필요 없다**
- 적정 온습도는 그 개체의 종에서 유일하게 도출된다 → 목표값 충돌이 없다

## 2. 정보 구조 (IA)

### 2.1 탭

| # | 탭 | 한 줄 목적 |
|---|---|---|
| 1 | **홈** (크레캠 + 사육장) | 지금 우리 애가 어떤지 보고, 사육장을 바로 조작한다 |
| 2 | **통계** | 시간에 걸친 환경·행동 변화를 읽고 분석한다 |
| 3 | **마이크레** | 개체 프로필과 사육 기록을 남긴다 |
| 4 | **커뮤니티** | 사육 정보를 나누고 찾아본다 |

> 원문 기능 요약의 탭명은 `크레캠+사육장`이고, PRD에서는 같은 화면을 **홈 탭(`/home`)**으로 부른다. 이 기획안은 **홈**으로 통일한다.

### 2.2 탭에 속하지 않는 화면

| 화면 | 진입 |
|---|---|
| 알림 센터 | 홈 헤더 🔔 |
| 사육장 세트 설정 | 홈 헤더 ⚙️ |
| 기기 등록 위저드 (BLE/Wi-Fi 페어링) | 사육장 설정 내 `[+ 새 기기/사육장 추가]` |
| 타이머 & 일정 설정 | 홈 → 사육장 제어 서브탭 |

### 2.3 푸시

원문이 정한 것은 두 가지뿐이다 — **주기적인 사육장 청소(물통 세척) 알림**, **온도 경고 알림**.
알림 센터의 카테고리는 4종으로 더 세분돼 있다(§3.3). 둘의 관계는 원문에 없다. → §6

## 3. 공통 정책

### 3.1 시간 정책

야행성 개체를 다루므로 **자정이 하루의 경계가 아니다.** 시간 개념이 셋이며, 역할이 서로 다르다.

| # | 개념 | 구간 | 역할 |
|---|---|---|---|
| ① | **당일** (날짜 경계) | `07:00 ~ 익일 07:00` | **어느 날에 속하는가**를 정한다. 날짜 스크롤러 조회 범위, 클립 피드 범위, 환경 최고/최저 |
| ② | **밤** (활동 집계 창) | `22:00 ~ 06:00` | **개체 활동을 집계하는 유일한 창.** 움직임·휴식 시간, 식사·물 마신 횟수 |
| ③ | **실시간 차트** | `전날 19:00 ~ 현재` | 홈 온습도 차트의 X축 |

> ✅ **결정 (2026-08-08)**: **활동 집계는 밤(22:00~06:00)만 센다.**
> 야행성이라 낮 데이터는 활동 지표로서 의미가 적다. 원문 *"10시 6시까지가 밤"*을 활동 집계 창으로 채택한다.
> 이로써 기능 요약의 *"하루: 어제 오후 7시 ~ 오늘 오전 7시"*는 **폐기**된다 — 의도(밤을 본다)는 같지만 구간이 더 넓었다.

**②는 ①의 부분집합이다.** `8/5 22:00 ~ 8/6 06:00`은 `8/5의 당일 창` 안에 들어가므로 **"8월 5일의 밤"**으로 귀속된다. 날짜 귀속 규칙이 필요해서 ①을 07:00 경계로 유지한다.

> 📌 **해석 주의 — 확인 필요**: "활동 **집계**"를 수치 요약으로 읽었다. 즉 **요약 칩의 숫자는 밤(②)만 세고, 클립 피드 목록 자체는 당일 창(①) 전체를 보여준다.** 피드까지 밤으로 좁히면 낮에 찍힌 영상이 화면에서 사라져 "영상이 없어졌다"가 된다. 이 구분이 의도와 다르면 알려줄 것.

### 3.2 라인업별 화면 구성

| 화면 | 통합 세트 | 사육장 단품 | 캠 단품 |
|---|---|---|---|
| 홈 상단 | 실시간 영상 | **개체 프로필 카드로 대체** | 실시간 영상 |
| 홈 서브탭 | 제어 + 타임라인 | 제어만 (타임라인 비활성) | 타임라인만 (제어 비활성) |
| 통계 | 전체 | 온습도만 (활동량 비활성) | 활동량만 (온습도 비활성) |

### 3.3 알림 카테고리

긴급/안전 · 제어·동작 결과 · 주간 AI 리포트 · 마케팅/혜택. 미읽음이 있으면 헤더 🔔에 Red Dot.

## 4. 화면 기획

### 4.1 홈 탭

**목적**: 실시간 펫캠 감상, 사육장 모니터링, 퀵 제어, 타이머 현황 확인, 당일 타임라인 확인.

**구조**: 헤더 / 상단 고정 영역 / 서브탭 바 / 서브탭 컨테이너.

#### 4.1.1 헤더

| 요소 | 동작 | 예외 |
|---|---|---|
| 개체 선택 드롭다운 | 등록된 사육장 세트 목록 팝업 → 전환 | **세트가 1개면 드롭다운 화살표를 숨긴다** |
| 🔔 알림 센터 | 알림 센터로 이동 | 미읽음 있으면 Red Dot |
| ⚙️ 사육장 설정 | 해당 세트 상세 설정으로 이동. 여기서 기기 등록 위저드 진입 | – |

#### 4.1.2 상단 고정 영역

**캠이 있으면 — 실시간 영상**

- 16:9 실시간 스트리밍
- **좌/우 스와이프로 다음 세트 전환** (페이지 인디케이터와 연동)
- 상태 뱃지: 연결 정상 `LIVE`(빨강 점) / 네트워크 해제 `OFFLINE`(회색)
- 오버레이: 현재 시각, 전체 화면 전환, **캡처**, **수동 녹화**
- 스트림이 끊기면 영상 중앙에 경고 레이어 + `[재연결]`

**캠이 없으면 — 개체 프로필 대표 카드로 대체**

- 대표 사진, D-Day(`젤리와 함께한 지 D+152일`), 최근 상태 요약(마지막 급여일·체중), 사육장 상태 뱃지(`온습도 정상 🟢`)

#### 4.1.3 서브탭 바

`[사육장 제어] | [타임라인]` 2구분.
**핵심 제약**: 서브탭을 전환해도 **상단 영상은 끊기지 않고 유지**된다.

#### 4.1.4 사육장 제어 서브탭

위에서부터:

1. **진행 중 타이머 칩** — 가동 중일 때만. `팬 30분 타이머 가동 중 (18분 20초 남음)`. 터치하면 타이머 설정으로 이동
2. **실시간 온습도** — 현재 온도/습도 + **당일(07:00~) 최고/최저**
3. **최근 24시간 차트**
   - X축 전날 19:00 ~ 현재 (5분 단위)
   - 온도·습도 라인
   - **기기 동작 마커** — 분무·팬·히터·LED가 언제 돌았는지 차트 위에 표기
   - 터치하면 **통계 탭으로 이동**
4. **퀵 제어 4종**
   - 팬 ON/OFF · 히터 ON/OFF · LED ON/OFF(밝기 0~100% 슬라이더) · **1회 즉시 분무**
5. **타이머 & 일정 설정 진입 버튼**

**분무 예외 처리**: 명령 송출 후 **5초간 버튼 비활성화**(중복 클릭 방지) + 완료 토스트.

#### 4.1.5 타임라인 서브탭

1. **요약 칩** — 움직임 시간, 휴식 시간, 식사 횟수, 물 마신 횟수
   - **집계 창은 그 날짜의 밤(`22:00 ~ 익일 06:00`)** — §3.1 ②. 낮 활동은 세지 않는다
2. **날짜 스크롤러** — `[◀] YYYY.MM.DD [▶]`. **조회 범위는 그 날짜 `07:00 ~ 익일 07:00`** — §3.1 ①
   - 즉 **요약 숫자와 클립 목록의 구간이 다르다.** 요약은 밤만, 목록은 당일 전체.
   - 사용자가 혼란스럽지 않게 요약 칩 근처에 집계 기준(밤)을 밝혀야 한다
3. **이벤트 필터 칩** — `전체 / 움직임 / 식사 / 물마심 / 탈피` **고정 노출**
   - **당일 0건인 필터는 비활성으로 고정 표기** (숨기지 않는다)
4. **클립 피드** — 시간순 세로 스크롤. 시간·이벤트명·녹화 길이 표기

> ⚠️ **재생 방식이 원문 내에서 엇갈린다.** 2026-08-05 시점 원문은 *"상단 Live 비디오 영역에서 즉시 재생"*, 2026-08-08 시점 원문은 *"전체화면으로 재생"*이다. → §6

### 4.2 타이머 & 일정 설정

**진입**: 홈 → 사육장 제어 → `[타이머 & 일정 설정]`
**전환**: 1뎁스는 아래에서 올라오는 풀스크린 모달, 2뎁스는 그 위로 한 번 더 올라오는 바텀시트/모달.

#### 4.2.1 타이머 (즉시·일회성)

- 대상: **팬 또는 히터** 중 선택
- 시간: 10분 / 30분 / 1시간 / 2시간
- `[타이머 시작]` → **즉시 기기 ON + 카운트다운 개시**
- 가동 즉시 홈 사육장 제어 최상단에 진행 중 칩 노출 (`[취소]` 포함)

#### 4.2.2 일정 (반복·예약)

목록에서 각 일정을 **토글로 즉시 ON/OFF**. `[+ 추가]`로 대상 기기(분무·LED·팬·히터)를 고르고 상세 설정으로.

| | 분무 | 히터 | 팬 | LED |
|---|---|---|---|---|
| **시간** | 회차별 시각 (예: 08:00, 20:00) | 시작~종료 (휠 피커) | 시작~종료 | 시작~종료 |
| **반복 요일** | 월~일 다중 선택 | 〃 | 〃 | 〃 |
| **제어 옵션** | – | – | – | 밝기 0~100% |
| **스마트 조건**<br>(안전 가드, on/off 가능) | 목표 습도 이상이면 **스킵** (예: 80%↑) | 목표 온도 도달 시 **정지** (정지 온도 슬라이더에 적정/위험 구간 시각화) | 과건조 방지 **자동 정지** (예: 습도 50%↓) | – |
| **개체 가이드** | 적정/위험 온도 배너 | 적정/위험 온도 배너 | 적정/위험 온도 배너 | – |
| **제외** | 분사 시간(길이) 설정 불가 | – | – | – |

> **스마트 조건은 이 기능의 핵심이다.** 단순 예약이 아니라 *"조건이 어긋나면 알아서 멈춘다"*가 안전 장치다. 특히 히터는 과열이 개체 폐사로 이어진다.

#### 4.2.3 작동 기록

원문 기능 요약: *"작동 기록 — 실제로 작동했는지 안내하기 위한 확인, 안심용"*. **실행 예정**과 **실행 결과**를 모두 보여준다.
PRD에서는 이 기록의 전체 조회를 **통계 탭의 작동 이력(Audit Log)으로 이관**한다(§4.3.7).

### 4.3 통계 탭 — ⚠️ 원문 제목에 **"좀더고민.."** 이 붙어 있다

**확정 스펙이 아니다.** 아래는 원문에 적힌 내용이며, 착수 전 확정이 필요하다.

**목적**: 환경(온·습도)과 행동(활동량)을 기간별로 시각화하고, **둘 사이의 연관성**을 읽는다. 기기 제어 이력 검증도 겸한다.

#### 4.3.1 기간 선택

`[일간] [주간] [월간]`

| 기간 | 범위 | 포인트 단위 |
|---|---|---|
| 일간 | 선택 날짜 07:00 ~ 익일 07:00 | 10분 |
| 주간 | 최근 7일 | 1일 |
| 월간 | 최근 30일 | 1일 |

#### 4.3.2 메트릭 필터

`[전체] [온도] [습도] [활동량]` **다중 선택**. 라인업상 불가한 메트릭은 비활성.

#### 4.3.3 메인 복합 차트

| 축 | 데이터 | 표현 |
|---|---|---|
| Y1 (좌) | 온도 · 습도 | 라인 |
| Y2 (우) | 활동량 (%) | 세로 막대 (AI Vision 움직임 비율) |
| 오버레이 | 기기 제어 이벤트 | 분무·팬·히터·LED 가동 시점 마커 |

임의 시점을 터치하면 그 시점 값 툴팁.

#### 4.3.4 AI 사육 환경 분석 리포트

주간 이상 데이터가 쌓이면 자동 생성.

- 요약 예: *"젤리는 평균 온도 24.5℃, 습도 65%에서 가장 왕성하게 활동해요."*
- 제안 예: *"야간(22시 이후) 습도가 80% 이상으로 유지되는 경향이 있습니다. 팬 환기 일정을 조정하는 것을 권장합니다."*

#### 4.3.5 주간 행동 요약

활동/휴식 시간, 식사/물 마신 횟수를 요일별 누적 막대로. 요일을 누르면 그 날 일간 차트로 이동.

#### 4.3.6 주간 온습도 분포 범위

요일별 Min–Max 범위 바. **개체 프로필의 적정 구간을 초록 밴드로 겹쳐** 이탈 여부를 한눈에 본다.

#### 4.3.7 공간 히트맵

펫캠 AI Vision의 개체 좌표 추적으로 사육장 내 체류 시간 분포를 색으로. 은신처·바스킹 존·쿨존 이용 비율 파악이 목적.

#### 4.3.8 기기 작동 이력 (Audit Log)

- 필터: `전체 / 자동 일정 / 수동 제어 / 안전 가드 작동`
- 표시: 시각(HH:mm:ss), 기기, **실행 주체**(일정·타이머·수동), **상세 이유**
- 예: `16:20:05 팬 자동 정지 (목표 습도 50% 도달)`
- 20건 단위 무한 스크롤 또는 더보기

### 4.4 마이크레 탭 — ⚠️ 원문이 **"우선 후순위"**로 명시

**원문에 화면 명세가 없다. 기능 나열까지만 있다.**

- **프로필**: 사진, 이름, 성별, 종, 체중, 입양일 (사용자 수기)
- **활동 기록·메모**: 급여, 탈피, 체중, 건강, 자유 메모 (사용자 수기)

원문 주석 그대로:
> *"이런 간단한 기능만 구현할거면 통계로 통합해도 될듯 / 달력+다이어리처럼 한눈에 보여주는 형태로 간다면 따로 빼는게 맞고 / **우선 후순위**, 가나먼저 구체화"*

**→ 탭 존치 여부 자체가 미결이다.** 화면을 설계하기 전에 "통계 통합 vs 달력+다이어리 독립" 중 하나를 골라야 한다.

### 4.5 커뮤니티 탭

**원문에 화면 명세가 없다. 구성 나열까지만 있다.**

- 공지사항
- QnA
- 자유 게시판
- **사육 위키** — 백색목록 검색 / 종 정보 / 모프 계산기

> 사육 위키는 커뮤니티 **하위**다. 별도 탭이 아니다.

### 4.6 온보딩 — **미설계**

원문:
> *"맨 처음에 크레, 사육장, 캠을 연결하는 스텝은 더 고민 필요"*

첫 실행에서 개체·사육장·캠을 어떤 순서로 연결시킬지 정해지지 않았다. **라인업 3종을 모두 태울 수 있어야 하므로 분기 설계가 필요하다.**

## 6. 미결 사항

원문이 결정하지 않은 것들. **착수 전 확정 필요.** 임의로 메우지 않는다.

| # | 미결 | 원문 표기 | 영향 |
|---|---|---|---|
| ~~A~~ | ~~사육장 : 개체 = 1:N 전환~~ | 댓글 *"1:N이 되어야 할 거 같아요!"* | ✅ **해소 — 2026-08-08 1:1 확정**(§1.3). 1:N은 후속 보류, 영향 분석은 §6-A에 존치 |
| B | 타임라인 클립 재생 방식 | 원문 내 엇갈림 (상단 인라인 ↔ 전체화면) | 홈 상단 영역 역할이 달라진다 |
| ~~C~~ | ~~하루 기준~~ | 기능요약 `어제19:00~오늘07:00` vs PRD `07:00~익일07:00` | ✅ **해소 — 2026-08-08.** 활동 집계는 밤(22:00~06:00), 날짜 경계는 07:00 유지(§3.1). 기능요약 값은 폐기 |
| D | 통계 탭 전체 | 제목에 *"좀더고민.."* | 탭 하나 전체 |
| E | 마이크레 탭 존치 | *"통계로 통합해도 될듯 / 우선 후순위"* | 탭 하나 전체 |
| F | 온보딩 플로우 | *"더 고민 필요"* | 첫 실행 경험 |
| G | 캠/사육장 없이 "크레 일기장"만 쓰는 사용자 | *"고려할 필요가 있나? 없겠죠?"* | 라인업 4번째 케이스 |
| H | 정성 분석 가능 여부 | *"가능한지 기술 체크 필요"* — 이상행동, 활동량 증감, 좋아하는 은신처·장난감 | 통계 탭 범위 |
| I | 마이크레 기록 자동화 범위 | *"근데 일부는 자동화 가능한가?"* | 수기 입력 부담 |
| J | 최고/최저 온도 실시간 갱신 | *"굳이 필요없나?"* | 홈 온습도 카드 |
| K | AI 분석 시간대 제한 | *"캠은 24시간 라이브지만 AI 분석은 시간 제한을 두는게 어떨지? 17시~07시 등"* | 분석 파이프라인 + 사용자 설정 |
| L | 다수 제품 구매 시 제어 | *"3개 이하는 하나씩 제어해도 무방, 4개 이상일 때 고민"* | 세트 전환 UX |
| M | 라인업별 미사용 기능 처리 | *"어떻게 처리할 것인지?"* | 전 화면 |

### 6-A. (보류) 나중에 1:N으로 갈 때 흔들리는 것

> 📌 **지금은 1:1로 확정됐다(§1.3).** 이 절은 **1:N 요구가 다시 올라올 때를 위한 참고**이며,
> 현재 설계를 여기에 맞춰 미리 열어두지 않는다.

1:N이 되면 다음이 전부 다시 정의돼야 한다.

| 지점 | 1:1일 때 | 1:N이면 |
|---|---|---|
| 헤더 드롭다운 | 세트 = 개체 | 세트를 고른 뒤 **개체를 또 고르는 축**이 생긴다 |
| 상단 스와이프 | 세트 간 이동 | 세트 간? 개체 간? 둘 다? |
| 프로필 카드 (사육장 단품) | 개체 1명 | N명을 어떻게 한 카드에 |
| 타임라인 | 세트의 클립 = 그 개체 | **클립 속 개체를 식별할 수 있어야** 개체별 분리가 가능 |
| 당일 요약·행동 통계 | 개체 1명 기준 | 개체별 분리 vs 사육장 합산 |
| 어젯밤 리포트 | 개체 1명 | 〃 |
| 적정 온습도 | 개체의 종에서 도출 | **종이 다른 개체가 한 사육장에 있으면 적정값이 충돌한다** |

**마지막 줄이 특히 중요하다.** 종이 다르면 적정 온습도가 다른데 사육장은 하나다. 1:N을 허용하려면 *"한 사육장 안 개체는 같은 종"* 같은 제약을 두거나, 적정값 산출 규칙을 새로 정해야 한다.

## 7. 다음 단계 제안

원문이 정한 우선순위는 *"우선 후순위, **가나먼저** 구체화"* — 즉 **가(홈) · 나(통계) 먼저**, 마이크레는 뒤로.

~~미결 A(1:N)~~ → ✅ **1:1 확정** (2026-08-08)
~~미결 C(하루 기준)~~ → ✅ **활동 집계 = 밤 22:00~06:00, 날짜 경계 07:00 유지** (2026-08-08)

1. **미결 B(클립 재생 방식) 결정** — 상단 인라인 재생 ↔ 전체화면. **홈 상단 영역의 역할이 달라지므로 홈 설계 전에 정할 것.** 선택지가 둘뿐이라 오래 끌 사안은 아니다
2. **홈 탭 화면 설계** ← 여기부터가 본 작업. 기획이 가장 촘촘해 디자인만 나오면 된다
3. **미결 D(통계) 확정** → 통계 탭 설계
4. 마이크레(미결 E)·커뮤니티·온보딩(미결 F)

> **홈 설계를 막던 큰 미결(A·C)은 정리됐다.** 남은 B 하나만 정하면 홈 설계에 들어갈 수 있다.
> 아울러 **노션 원문도 고쳐야 한다** — 기능 요약의 "하루: 어제 오후 7시~오늘 오전 7시"가 이제 폐기됐는데 원문에는 그대로 남아 있다. 이 기획안과 원문이 어긋난 채로 두면 다음 사람이 또 헷갈린다.
