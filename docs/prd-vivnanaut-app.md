## 0. 이 문서에 대하여

### 0.1 왜 새로 썼나

2026-08-08까지 구현된 화면 디자인이 기획 의도를 만족하지 못했다. 그래서 **기존 구현을 전제하지 않고**, 노션 기획서·PRD만으로 요구사항을 다시 정리했다.

### 0.2 작성 원칙

1. **구현 역산 금지.** "지금 이렇게 돼 있으니까"는 근거가 아니다. 원문에 있는 것만 적는다.
2. **없는 것은 없다고 쓴다.** 원문이 기능 요약 수준까지만 정한 영역은 그 사실을 명시하고, 화면을 지어내지 않는다.
3. **원문의 물음표를 지우지 않는다.** "논의 필요", "좀더고민", "굳이 필요없나?" 같은 표기는 **미결로 §6에 그대로 남긴다.** 해석해서 확정으로 바꾸지 않는다.
4. **레이아웃보다 의도.** 원문 와이어프레임은 *"이해를 돕기위한 예시 이미지~ 세부내용은 달라질수있습니다"*라고 명시돼 있다. 이 기획안은 **화면이 무엇을 해야 하는가**를 규정하고, 픽셀 배치는 디자인 단계에 넘긴다.

### 0.3 Figma를 근거에서 뺀 이유

Figma `Final Design`의 주력은 **현재 앱에 대한 피드백 보드**이고, 완성된 화면 설계는 통계 24시간 그래프 하나뿐이다. 즉 "구현을 평가한 결과물"이라 **구현 배제 원칙과 충돌**한다.
다만 Figma의 **디자인 시스템**(컬러 팔레트·타이포·컴포넌트)은 기획이 아니라 표현 규격이므로, 디자인 단계에서 그대로 쓴다 → `docs/figma-final-design-transcript.md` §4.

> ✅ **2026-09-02 갱신**: 위 서술은 구 `Final Design` 페이지 이야기다. 새로 그린 **`vivanaut app` 페이지**(Home·Camera·Navigation·Asset 섹션)는 피드백 보드가 아니라 **완성 화면 설계**이며, 이번 개정의 근거이자 **디자인 SOT**다.
> - **디자인 시스템**: Asset 섹션 팔레트(다크 네이비 + 그레이 + 레드 포인트, 버튼 S/M/L·칩·세그먼트·토스트)를 채택한다. 섹션 내 *"이거 확정아님"* 메모는 **사용자 결정으로 확정 전환**(2026-09-02). 현행 B안(Flighty 전광판) 토큰은 교체 대상.
> - 적용 범위: 홈·카메라(·온습도 상세)는 화면 전면 재설계, **마이크레·커뮤니티는 팔레트만 우선 적용**(레이아웃 유지).

## 1. 제품 개요

### 1.1 정의

> 게코를 위한 **스마트 사육장**과 **소형 캠**에 연동해 쓰는 앱.
> 핵심은 **사육장 온습도 조절 장치의 원격 조정**과 **펫캠 확인**이다.

### 1.2 제품 라인업 — 화면 분기의 근원

사용자가 무엇을 샀는지에 따라 앱이 달라진다. **모든 화면 분기는 이 한 축에서 나온다.**

| 라인업 | 사육장 | 캠 | 앱이 할 수 있는 것 |
|---|---|---|---|
| **통합 세트** | ○ | ○ | 전부 |
| **사육장 단품** | ○ | ✕ | 환경 제어·환경 통계만. 영상·행동 데이터 없음 |
| **캠 단품** | ✕ | ○ | 영상·행동 데이터만. 환경 제어·환경 통계 없음 |

**규칙**: 미보유 기능은 **숨기지 않고 비활성으로 노출**한다. 없애면 "지원하지 않는 기능"으로 오해한다.

> ⚠️ 원문 미결: *"라인업이 나뉘었을 때 미사용 기능을 어떻게 처리할 것인지?"* — 비활성 노출은 PRD §3.3(서브탭 분기)에서 확인되는 방향이나, 전 화면 공통 규칙으로 확정된 문구는 없다.

### 1.3 사육장 : 개체 관계 — **1:1 확정**

> ✅ **결정 (2026-08-08)**: 원문 전제대로 **1 사육장 : 1 캠 : 1 개체**로 간다.

원문 댓글에 1:N 제안이 달려 있었으나,

> **"크레를 포함해서, 1:N(한개의 사육장, n마리의 도마뱀)이 되어야 할 거 같아요!"**

**당장은 1:1로 확정한다.** 이 기획안의 모든 화면·데이터 서술은 1:1을 전제로 한다.

**1:N은 폐기가 아니라 후속 과제로 보류**다. 나중에 다시 올라올 때를 위해 영향 범위 분석을 §6-A에 남겨 뒀다. 다만 **지금 1:N을 미리 대비해 구조를 열어두지는 않는다** — 화면 설계가 없는 상태에서 미리 열면 실제 요구가 왔을 때 다시 뒤집힐 가능성이 크다.

**1:1 확정이 주는 것** (이 기획안이 기대는 단순화):

- 사육장을 고르면 곧 개체를 고른 것이다 → 헤더 드롭다운 하나로 끝난다
- 그 사육장의 온습도가 곧 그 개체의 환경이다 → 통계에서 환경과 행동을 바로 겹쳐 읽을 수 있다
- 캠에 찍힌 것은 그 개체다 → **영상 속 개체 식별이 필요 없다**
- 적정 온습도는 그 개체의 종에서 유일하게 도출된다 → 목표값 충돌이 없다

## 3. 공통 정책

### 3.1 시간 정책

야행성 개체를 다루므로 **자정이 하루의 경계가 아니다.** 시간 개념이 셋이며, 역할이 서로 다르다.

| # | 개념 | 구간 | 역할 |
|---|---|---|---|
| ① | **당일** (날짜 경계) | `07:00 ~ 익일 07:00` | **어느 날에 속하는가**를 정한다 — **활동·클립 귀속 전용.** 날짜 스크롤러 조회 범위, 클립 목록 범위 |
| ② | **밤** (활동 집계 창) | `22:00 ~ 06:00` | **개체 활동을 집계하는 유일한 창.** 움직임·휴식 시간, 식사·물 마신 횟수 |
| ③ | **환경(온습도) 하루** | `자정 ~ 자정` | ✅ **2026-09-02 결정.** 온습도 상세의 일간 페이징(`← YYYY.M.D →`) 및 홈 최고/최저의 경계. 달력과 일치시켜 직관 우선 |

> ✅ **2026-09-02**: 구 ③ "실시간 차트(전날 19:00~현재)"는 **폐기** — 홈에는 차트를 그리지 않고(§4.1), 차트는 온습도 상세(§4.3)로 이동하며 날짜 단위(자정 경계)로 페이징한다. 활동·클립의 07:00 경계(①)와 환경의 자정 경계(③)는 **서로 다른 축**이니 혼용 금지.

> ✅ **결정 (2026-08-08)**: **활동 집계는 밤(22:00~06:00)만 센다.**
> 야행성이라 낮 데이터는 활동 지표로서 의미가 적다. 원문 *"10시 6시까지가 밤"*을 활동 집계 창으로 채택한다.
> 이로써 기능 요약의 *"하루: 어제 오후 7시 ~ 오늘 오전 7시"*는 **폐기**된다 — 의도(밤을 본다)는 같지만 구간이 더 넓었다.

**②는 ①의 부분집합이다.** `8/5 22:00 ~ 8/6 06:00`은 `8/5의 당일 창` 안에 들어가므로 **"8월 5일의 밤"**으로 귀속된다. 날짜 귀속 규칙이 필요해서 ①을 07:00 경계로 유지한다.

> 📌 **해석 주의 — 확인 필요**: "활동 **집계**"를 수치 요약으로 읽었다. 즉 **요약 칩의 숫자는 밤(②)만 세고, 클립 피드 목록 자체는 당일 창(①) 전체를 보여준다.** 피드까지 밤으로 좁히면 낮에 찍힌 영상이 화면에서 사라져 "영상이 없어졌다"가 된다. 이 구분이 의도와 다르면 알려줄 것.

## 4. 화면 기획

### 4.1 홈 탭 — ✅ 2026-09-02 전면 개정 (Figma Home 섹션)

**목적**: 라이브를 보면서 사육장을 바로 조작한다.

**구조**: **서브탭 없는 단일 스크롤** — 헤더 / 라이브 / 온습도 요약 / 사육장 제어 그리드 / 일정 설정 진입.
구 [사육장 제어|타임라인] 서브탭과 "캠 없으면 개체 프로필 카드 대체" 분기는 **둘 다 폐기**(사용자 결정 2026-09-02). 타임라인의 클립 탐색은 **카메라 탭이 흡수**(§4.4). 라이브 바로 아래에 제어 그리드가 오면서 *"캠을 보면서 조작"* 피드백도 자연 해소(미결 N 해소).

#### 4.1.1 헤더

| 요소 | 동작 | 예외 |
|---|---|---|
| 세트 드롭다운 (`크랑이 ∨`) | 등록된 사육장 세트 목록 팝업 → 전환 | **세트가 1개면 드롭다운 화살표를 숨긴다** |
| `[+]` | 메뉴: **기기 추가 / 개체 추가 / 사육세트 추가** | – |
| `[사람]` | **계정 화면**으로 이동 — 알림 센터·사육장 설정·프로필·차단 관리 등을 이 안에 둔다 | 미읽음 알림 있으면 Red Dot(계정 아이콘에) |

#### 4.1.2 라이브 (캠이 있으면)

- 16:9 실시간 스트리밍, 좌/우 스와이프로 세트 전환
- 상태 뱃지 `LIVE`/`OFFLINE`, 전체 화면 전환, 끊기면 경고 레이어 + `[재연결]` (구 스펙 유지)
- **캠이 없으면**: 개체 프로필 카드 대체는 폐기. 라이브 영역 처리 방식 미결 → §6 P

#### 4.1.3 온습도 요약

- 현재 온도/습도 + **오늘(자정~) 최고/최저** (§3.1 ③)
- **홈에는 차트를 그리지 않는다** — 영역을 탭하면 **온습도 상세**(§4.3)로 이동
- 구 "최근 24시간 차트"(전날 19:00~현재)는 폐기

#### 4.1.4 사육장 제어 그리드

- 타일: **환기팬 / 분무 / 냉각팬 / 히터팬 / LED**(켜짐·밝기 % 표기)
- ✅ **팬 3종 분리 (2026-09-02)**: **환기팬 = 순수 환기(온도 관리에 관여하지 않음), 냉각팬 = 냉각, 히터팬 = 가온** — 서로 다른 기기다.
  - **기존 fan 명령은 환기팬에 배선**한다
  - **냉각팬·히터팬은 전용 API가 아직 없다** — **UI를 먼저 만들고** 배선은 후속(사용자 결정). 기존 `heater_*` 명령의 귀속, Figma 그리드 4칸에 히터팬을 어떻게 넣을지는 미결 → §6 Q
- 안전 규칙 유지(§5): 히터(가온) 조작 전 2단 확인, 분무 송출 후 5초 잠금 + 완료 토스트, 제어는 절대 상태 명령
- 진행 중 타이머 칩은 유지하되 배치는 디자인을 따른다

### 4.2 타이머 & 일정 설정

**진입**: 홈 → `[일정 설정]` (2026-09-02 개편 — 구 "사육장 제어 서브탭" 경유는 소멸)

#### 4.2.1 타이머 (즉시·일회성)

- 대상: **팬 또는 히터** 중 선택
- 시간: 10분 / 30분 / 1시간 / 2시간
- `[타이머 시작]` → **즉시 기기 ON + 카운트다운 개시**
- 가동 즉시 홈 사육장 제어 최상단에 진행 중 칩 노출 (`[취소]` 포함)

#### 4.2.2 일정 (반복·예약)

목록에서 각 일정을 **토글로 즉시 ON/OFF**. `[+ 추가]`로 대상 기기(분무·LED·팬·히터)를 고르고 상세 설정으로.

| | 분무 | 히터 | 팬 | LED |
|---|---|---|---|---|
| **시간** | 회차별 시각 (예: 08:00, 20:00) | 시작~종료 (휠 피커) | 시작~종료 | 시작~종료 |
| **반복 요일** | 월~일 다중 선택 | 〃 | 〃 | 〃 |
| **제어 옵션** | **분사 시간 1/2/3초** | – | – | 밝기 0~100% |
| **스마트 조건**<br>(안전 가드, on/off 가능) | 목표 습도 이상이면 **스킵** (예: 80%↑) | 목표 온도 도달 시 **정지** (정지 온도 슬라이더에 적정/위험 구간 시각화) | 과건조 방지 **자동 정지** (예: 습도 50%↓) | – |
| **개체 가이드** | 적정/위험 온도 배너 | 적정/위험 온도 배너 | 적정/위험 온도 배너 | – |
| **제외** | – | – | – | – |

> **스마트 조건은 이 기능의 핵심이다.** 단순 예약이 아니라 *"조건이 어긋나면 알아서 멈춘다"*가 안전 장치다. 특히 히터는 과열이 개체 폐사로 이어진다.

> **2026-08-12 개정 — 분사 시간 설정 가능.** 원문은 분무만 *"분사 시간(길이) 설정 불가"*로 제외했으나, 백엔드가 `mist` + `duration_ms`(1000/2000/3000) 계약을 열면서 1/2/3초 선택을 채택했다. 앱은 지속시간만 보내고 **펌웨어가 자동으로 끈다** — OFF 명령은 보내지 않는다. 계약: `APP_TIMER_MIST.md` §1, 대조: `docs/backend-handoff-timer-mist.md`.

### 4.3 온습도 상세 — ✅ 2026-09-02 신설 (구 통계 탭 대체, 미결 D 해소)

**통계 탭은 폐지**한다. 원문의 통계 기획(활동량 복합 차트·AI 리포트·주간 행동 요약·공간 히트맵·메트릭 필터 — 구 §4.3.2~4.3.7)은 **탭과 함께 보류 폐기**하며, 필요해지면 재기획한다(원문 자체가 *"좀더고민.."* 미확정이었다). 남기는 것은 **온습도 시각화와 제어 이력**이고, 이것을 홈에서 진입하는 상세 화면으로 흡수한다.

**진입**: 홈 온습도 요약 영역 탭. 풀스크린 모달(✕ 닫기), 세그먼트 `[일간 | 주간]`.

#### 4.3.1 일간

- **날짜 페이징** `← YYYY.M.D →`, 하루 경계는 **자정~자정**(§3.1 ③)
- **듀얼 라인 차트**: 온도(좌축)·습도(우축)
- **액추에이터 마커 행**: 차트 상단에 기기 동작 시점을 아이콘으로 — 분무·팬(3종)·LED
- **터치 스크러버**: 임의 시점 터치 시 시각 + 온습도 값 툴팁
- 오늘 페이지의 기본 스크롤 위치는 **현재 시각 기반**(Figma 탐색안 채택), 미도래 시간은 빈 영역
- 차트 아래: 현재 온습도 + 그날 최고/최저

#### 4.3.2 사육장 제어 기록 (일간 하단)

- 그날의 기기 동작 리스트: 기기·동작(켜짐/꺼짐/분무 작동)·시각 + **그 시점 온습도** + **변화량**
- **변화량 = 기기를 켠 시점~끈 시점 사이의 온습도 차이** (예: `-5°C +2%` — Figma 메모 *"EX. 냉각팬 켠시점~끈시점의 차이"*)
- 구 통계 탭의 기기 작동 이력(Audit Log) 역할을 이 리스트가 흡수한다

#### 4.3.3 주간

- **주 페이징** `← M.D - M.D →` (7일 단위)
- 요일별 **최저~최고 범위 바** 차트 — 온도 1단 + 습도 1단
- 데이터는 30분 집계(`telemetry_30m`)의 일별 min/max

### 6-A. (보류) 나중에 1:N으로 갈 때 흔들리는 것

> 📌 **지금은 1:1로 확정됐다(§1.3).** 이 절은 **1:N 요구가 다시 올라올 때를 위한 참고**이며,
> 현재 설계를 여기에 맞춰 미리 열어두지 않는다.

1:N이 되면 다음이 전부 다시 정의돼야 한다.

| 지점 | 1:1일 때 | 1:N이면 |
|---|---|---|
| 헤더 드롭다운 | 세트 = 개체 | 세트를 고른 뒤 **개체를 또 고르는 축**이 생긴다 |
| 상단 스와이프 | 세트 간 이동 | 세트 간? 개체 간? 둘 다? |
| 프로필 카드 (사육장 단품) | 개체 1명 | N명을 어떻게 한 카드에 |
| 타임라인 | 세트의 클립 = 그 개체 | **클립 속 개체를 식별할 수 있어야** 개체별 분리가 가능 |
| 당일 요약·행동 통계 | 개체 1명 기준 | 개체별 분리 vs 사육장 합산 |
| 어젯밤 리포트 | 개체 1명 | 〃 |
| 적정 온습도 | 개체의 종에서 도출 | **종이 다른 개체가 한 사육장에 있으면 적정값이 충돌한다** |

**마지막 줄이 특히 중요하다.** 종이 다르면 적정 온습도가 다른데 사육장은 하나다. 1:N을 허용하려면 *"한 사육장 안 개체는 같은 종"* 같은 제약을 두거나, 적정값 산출 규칙을 새로 정해야 한다.
