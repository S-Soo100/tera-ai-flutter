# Clarity 앱 적용·검증 기록

대상 정책: [기획자용 정책](clarity-policy.md) · 적용 버전: `0.98.0+188` · 2026-09-12

## 적용 방식

- 프로필의 **앱 사용 분석**에서 선택 참여. 기본 OFF이며 계정별로 기기에 저장한다.
- 동의 전에는 SDK를 초기화하지 않는다. 철회·계정 전환·제외 화면·백그라운드에서 앱의 이벤트 전송을 차단하고 SDK를 pause한다.
- 화면 전체를 기본 마스킹한다. 메인 하단탭의 고정 라벨만 별도로 공개한다. 임의 문자열·엔티티 ID·사용자 입력은 SDK에 전달하지 않는다.
- 로그인·가입·이메일 인증·프로필·알림·오류·개발 화면과 알 수 없는 경로는 제외한다. 허용 화면명도 고정된 이름으로 변환한다.
- `environment=qa/production`과 `analytics_schema=1`만 고정 태그로 보낸다. 앱 버전은 SDK가 수집하는 메타데이터로 확인한다.
- SDK 세션 준비가 확인된 뒤만 이벤트를 보낸다. 세션·계정·동의 경계가 바뀐 후 돌아온 이전 비동기 결과는 버린다.

## 실제로 측정하는 것

`feature_<기능>_used`는 해당 SDK 세션에서 한 번만 기록된다. 기능 사용은 아래의 명시적 행동이며, 읽기 완료·만족도·실제 사람 수를 뜻하지 않는다.

| 기능 | 사용으로 기록하는 행동 |
|---|---|
| `live` | 라이브 전체화면 직접 진입 |
| `clips` | 사용자 선택 클립의 플레이어 재생 상태 확인 |
| `highlights` | 하이라이트 진입 또는 항목 선택 |
| `bookmarks` | 북마크 목록/영상 선택 또는 저장 성공 |
| `environment` | 온습도 상세의 기간·날짜·차트 직접 조작 |
| `control` | 제어 명령 직접 요청 |
| `routines` | 일정 추가·편집·토글·삭제 조작 |
| `pets` | 개체 직접 선택·추가·편집·목록 선택 |
| `reports` | 리포트 탭 직접 선택 |
| `community` | 손가락 스크롤·새로고침·게시물/댓글 선택·반응·게시 조작 |

| 결과 이벤트 묶음 | 해석 |
|---|---|
| `pair_started`, `pair_device_selected`, `pair_wifi_submitted`, `pair_wifi_succeeded`, `pair_failed`, `pair_cancelled` | 페어링 과정. `wifi_succeeded`는 WIFI_OK일 뿐 기기 등록/라이브 성공이 아님 |
| `live_requested`, `live_connected`, `live_failed` | 라이브 진입·스트림 연결 상태·실패. 첫 영상 프레임 확인을 보장하지 않음 |
| `clip_requested`, `clip_playing`, `clip_auto_playing`, `clip_failed` | 직접 선택과 자동 다음 재생을 구분. playing은 플레이어 상태이며 완주가 아님 |
| `bookmark_added`, `bookmark_removed`, `bookmark_replayed` | 저장/제거 성공 및 북마크 영상 재생 선택. 실제 재생은 clip_playing으로 별도 확인 |
| `clip_share_opened` | 공유 서비스 반환(취소 포함 가능). 전달 성공이 아님 |
| `control_requested`, `control_accepted`, `control_failed` | 요청과 서버 접수/오류. 기기 ACK·실제 동작 완료가 아님 |
| `routine_saved`, `pet_saved`, `community_published`, `community_liked` | 해당 저장 작업 성공. 내용이나 대상 ID는 포함하지 않음 |

기능이 실제로 보였는지의 노출 건수, 전체 사용자 대비 비율, 여러 날 재사용률, 정밀한 시도별 퍼널은 이번에 집계하지 않는다. 자동 홈 라이브와 자동 리포트 진입도 의도적 사용에 넣지 않는다. 기획자는 준비된 기능 사용 기록과 리플레이만 활용하고 위 지표는 ‘미측정’으로 표시한다.

## 활성화 방법 — 개발·운영 담당자

**기본 빌드에서는 `CLARITY_ENABLED=false`라 실제 수집하지 않는다.** 사용자 선택 저장과 배포 수집 허용은 별개다. 화면 보호·실제 기록·운영 기준을 확인한 후 담당자가 활성화한 빌드를 배포한다.

QA 예시(별도로 만든 테스트 프로젝트 ID 필요):

```sh
flutter run --dart-define=CLARITY_ENABLED=true --dart-define=CLARITY_PROJECT_ID=YOUR_QA_PROJECT_ID
```

debug/profile에서 운영 프로젝트 ID를 사용하면 수집이 차단된다. 운영 검증 완료 뒤 release 빌드는 `--dart-define=CLARITY_ENABLED=true`로 활성화하며, 기본 운영 프로젝트 ID를 사용한다. Web·desktop·미지정/유효하지 않은 QA 설정에서는 초기화하지 않는다. 끄는 빌드는 `--dart-define=CLARITY_ENABLED=false`이다. 이것은 즉시 원격 중단 스위치가 아니며 이미 설치된 빌드는 자동 변경되지 않는다.

## 출시 전 실제 기기·대시보드 확인

- [ ] Android/iOS에서 동의 전 SDK가 시작되지 않고, 동의 후 허용 화면에서만 시작한다.
- [ ] 프로필에서 동의를 끈 뒤 새 앱 이벤트가 없고, 재실행 후 선택이 유지된다.
- [ ] 이메일·SSID/비밀번호 표시 전환·사용자 글·사진/썸네일·라이브/클립이 리플레이에서 가려진다.
- [ ] 로그인·계정·제외 화면으로 전환하는 순간과 복귀가 보호된다.
- [ ] 다른 계정으로 바꾼 뒤 이전 계정의 작업 결과가 새 세션에 포함되지 않는다.
- [ ] BLE 실제 연결/실패/취소와 재생/제어 결과가 정의한 의미대로 기록된다.
- [ ] 대시보드에서 화면명·앱 버전·기능 사용 이벤트·기간별 고유 세션 수의 사용 가능 범위를 확인한다.
- [ ] 운영 담당자가 수집 고지·열람 권한·보관 기간·기존 데이터 삭제·긴급 중단 절차를 확인한다.

위 항목은 자동 테스트 통과만으로 완료 처리하지 않는다. 실제 테스트 프로젝트 ID와 대시보드 증거가 아직 제공되지 않았다.

## 알려진 한계

- SDK pause는 이미 수집한 업로드 큐를 지우지 않으며, 이미 예약된 마스킹 프레임이 처리될 수 있다. 철회 안내는 새 앱 이벤트 차단을 의미하고 기존 데이터 삭제를 약속하지 않는다.
- 저장 장치 오류로 철회 저장이 실패하면 현재 실행에서는 차단하고 오류를 알린다. 기기 저장 실패 상태에서 다음 재실행까지 선택이 저장됐다고 보장하지 않는다.
- SDK 세션 콜백이 누락되면 메모리에서 세션 URL 변화만 최대 30초 확인한다. URL은 저장·전송·로그에 남기지 않고, 확인되지 않으면 이벤트 전송을 계속 차단한다.
- BLE 원시 응답에는 요청 ID가 없어 같은 연결 시도 안의 늦은 응답을 완전히 구분하지 못한다. 이전 시도의 콜백과 이전 비동기 작업 결과는 제외한다.
- 세션 준비 전 행동은 소급 전송하지 않으므로 초기 구간의 누락이 있을 수 있다. 개인정보 보호를 위해 오래된 결과를 다음 계정·세션으로 보내지 않는다.
- 개체 저장 실패의 신규 위젯 테스트 2건은 기존 UI의 버려진 Future와 테스트 오류 영역 충돌 때문에 중단했다. 성공·계정 전환 검증은 유지하며, 기존 제품 오류 처리 변경은 포함하지 않았다.
