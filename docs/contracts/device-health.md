## 카메라·사육장 재시작·Wi-Fi 약함 (2026-09-28 ~)

**카메라·사육장 재시작·Wi-Fi 약함**(2026-09-28, 0.140.0 카메라 → 0.141.0 사육장 공통화 `domain/sys_health.dart`·`sys_health_controllers.dart`·`widgets/sys_health_widgets.dart`, 대상 키 `SysTarget=(PairTargetKind, id)`. **사육장 차이:** 값 `devices.sys_state`(3초, 기준 `last_seen_at`), 신 펌웨어 판별은 버전이 아니라 `sys_state != null`, `POST /devices/{uuid}/reboot`는 201 `{id}` → 그 `commands` 행을 따로 구독 — **`status`만 보지 말 것**(거부도 `acked`, 성공은 `result == ok`뿐이고 ok는 재부팅 직전이라 완료가 아님), `no_ack`/`expired`/`lost`=응답 없음, `unknown_action`=펌웨어 업데이트, 약함 20번 연속·rssi 없는 보고는 0으로, 확인창 예약 임시 문장 `kDeviceRebootScheduleNote`(서버 예약 복원 배포 시 false). 요청서 `docs/references/2026-09-28-device-reboot-rssi-request.md`. 카메라 원문: petcam 요청서 `docs/references/2026-09-28-camera-reboot-rssi-request.md` + 보충 `…-update.md` — 버전 형식·완료 표기 확정, 신 펌웨어 카메라 9(p4cam-0d1b47b4)는 이관훈님 계정이라 실기 확인은 그쪽 빌드 테스트): 기기 상세(카메라)에 `RebootRow`·`WeakWifiBannerView`(`widgets/sys_health_widgets.dart`, Figma 밖). 재시작 = REST `POST /cameras/{id}/reboot`(`published` false면 재시도 안내, 404=찾을 수 없음), 노출은 `is_online && isRebootCapableFirmware(firmware_ver)`(0.2.0+ 숫자 비교, 파싱 실패=숨김). 완료 판정은 ack가 없어 `clip_stats.sys.uptime_s`가 누르기 직전보다 줄고 `reset == 'SW:mqtt_reboot'`(2026-09-28 확정, 실측 재부팅→첫 heartbeat 최대 27초)일 때, 2분 무소식이면 전원 재연결 안내, 발행 뒤 60초 재입력 금지. 약함 = `sys.rssi ≤ −75`가 서로 다른 heartbeat(`clip_stats_at`) 연속 4번, 닫을 때까지 유지. **`clip_stats`는 `camerasProvider`에 넣지 말 것**(생존 신호만 바뀐 갱신을 버리는 곳 — heartbeat마다 바뀌어 홈이 깜빡인다) — 상세를 보는 동안만 `sysHealthProvider`(`sys_health_controllers.dart` — 카메라·사육장 그 행의 UPDATE 필터 구독, autoDispose). REST `GET /cameras`는 `clip_stats`·`rotate_180`·`capabilities`가 누락돼 있어 읽기는 직결만(서버 PR 대기). 진단 필드(`last_err`·`up_fail` 등)는 앱에 표시하지 않는다. **라이브 실패 화면에서 재시작(2026-10-03, 0.151.0, 가이드 `docs/references/2026-10-03-camera-reboot-app-web-guide.md`·기획 `docs/superpowers/specs/2026-10-03-camera-reboot-from-live-design.md`):** 무응답·영상 없음·멈춤(`WebRtcLiveView.rebootErrorKeys`, 멈춤은 공유기 안내 유지) + `cameraRebootCapable`(domain `sys_health.dart`) + 보내는 중·60초 금지 아님이면 2차 버튼 [카메라 재시작](확인·요청은 `confirmAndRequestReboot` 공용). `rebootProvider`는 진행 중 `keepAlive`(화면 없이도 유지, 끝나면 놓음)·heartbeat 구독은 누른 뒤에만(라이브 제어기가 늘 듣는다 — 평소에 열면 라이브마다 채널). 라이브 제어기는 `WebRtcLivePhase.rebooting`에서 **모든 재연결 금지**(`_isCurrent` + 제한·재시작 공통 `_held`를 `_restart`·`_resume`·보임·`_suspend`가 본다 — 새 "자동 재연결 멈춤" 상태는 `_held`에 더할 것, 진입점마다 따로 검사하지 말 것), 안 보이는 중에 끝나면 `_suspend('hidden')`으로 내리고 보일 때 붙음(시간 초과면 `_rebootTimedOutAway`로 복귀 시 안내), 재시작 중 `takeover()`는 버림, 완료면 `_forceAttempt`로 즉시 연결, 2분 무소식이면 `crecam_live_error_reboot_timeout` + 60초 저빈도. 시청 기록은 닫고 연결 기록은 `outcome='reboot'`. 60초 `slow`="늦어지고 있어요". 서버 버그(gwanhun/terra-server#17 — 발행 성공해도 `published:false`, `/webrtc/ice` 늘 502)는 2026-10-03 운영 배포로 해소 → `kCameraRebootPublishedReliable=true`(`published == true`만 성공, false는 진짜 브로커 장애). 재발하면 이 값만 false로. 응답 `msg_id`는 `[camera-reboot]` 로그로 남긴다(서버 로그 추적용). **리셋 사유는 괄호 앞부분으로 비교(`resetReasonBase`·`isMqttRebootReason`)** — 펌웨어가 어느 사유에나 `SW:xxx(WDT)`처럼 하드웨어 사유를 덧붙일 수 있다(2026-10-03 실측·백엔드 회신). 정확 일치면 완료를 못 보고 2분 뒤 전원 안내가 잘못 뜬다. 새로 사유로 분기하는 곳도 반드시 `resetReasonBase`를 거칠 것. **세로 확대 화면(`CameraLiveFullscreenScreen`, 2026-10-03 0.152.0):** 영상 틀은 실제 비율(`_LiveAspectBox`, 기본 4:3)로 좌우 꽉, 맨 아래 [카메라 재시작](Figma 971:1837 `ManagementButton`+restart_alt, 좌우 12·SafeArea 위 66, 가로 모드엔 없음) — 못 하면 **비활성+이유**(사용자 결정, 다른 화면은 숨김), 이 화면 실패 안내엔 버튼 없음(`showReboot:false`). 완료 판정 보강 = `uptime_s ≤ 누른 뒤 폰 시간 + 2초`(`clock.stopwatch()`, 서버 시각과 비교하지 말 것 — 폰 시계 어긋남). **마이페이지 사육장 기기 재시작(2026-10-04, 0.153.0, 가이드 `docs/references/2026-10-03-device-reboot-app-guide.md`):** 비상용 진입점 `/profile/device-reboot`(`DeviceRebootScreen`, Figma 밖) — 사육장 기기 전부를 보여 주고 못 하면 흐리게+이유(오프라인·구 펌웨어·60초 대기, 상세의 `RebootRow`는 숨김과 다름), 흐름은 `rebootProvider`·`confirmAndRequestReboot`·`listenRebootOutcome` 공용. 카메라는 넣지 않음. 실기기 확인(사육장 2 `terra-5710e59c`): acked/ok 0.8초, 재부팅 완료 약 12초. 서버가 재부팅 뒤 예약상 켜져 있어야 할 조명·팬·냉각팬을 복원하므로 확인창 예약 문장은 "다시 켜져요·직접 켠 장치는 다시 켜 주세요"로 바뀜(`kDeviceRebootScheduleNote` true 유지) — 복원 자체는 예약 있는 기기로 아직 미확인.
