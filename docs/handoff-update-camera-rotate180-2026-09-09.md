# 카메라 180° 회전 — 후속 통보 (2026-09-09)

> **수신**: 앱(Flutter) 담당
> **발신**: FB2_P4_CAM 펌웨어 + terra-server 담당
> **관련**: 완료 보고 `HANDOFF_DONE_CAMERA_ROTATE180_2026-09-08.md` (그 문서 §5-1 "Bayer 색 검증"의 결과 통보)
> **결론**: 색 검증 완료(정상). **계약 변경 1건(R6 적용 시점)**. 앱 코드·문구 변경은 없고, 안내 한 줄만 검토 부탁.

## 1. R6 적용 시점 변경 (유일한 계약 변경)

| | 완료 보고(09-08) | **확정(09-09)** |
|---|---|---|
| 카메라 온라인일 때 | 즉시 (다음 프레임) | **토글 후 카메라가 재부팅, 약 20초 뒤 적용** |
| 라이브 시청 중 토글 | 재연결 없이 뒤집힘 | **라이브가 끊겼다가 자동 재연결됨** (앱의 기존 재연결 로직으로 복귀) |
| 카메라 오프라인 | 다음 재연결 시 | 다음 부팅 시 (동일) |

- 이유: 회전 시 센서의 컬러 필터 배열 위상이 바뀌어 ISP 색 순서를 다시 잡아야 하는데, 이 재설정은 스트리밍 중에 안전하게 할 수 없어 카메라가 스스로 재부팅합니다.
- **앱에서 할 일**: 없음. `PATCH /cameras/{id} {"rotate_180": bool}` → 200 → Realtime UPDATE 흐름 그대로입니다. 권장 문구 "잠시 후 적용돼요. 카메라가 꺼져 있으면 다시 켜질 때 적용돼요."도 그대로 유효합니다.
- **검토 부탁(선택)**: 라이브 화면을 보면서 토글하는 사용자를 위해 "적용 중 잠시 연결이 끊겼다 다시 연결돼요" 정도의 안내를 붙일지 판단해 주세요. 토글 직후 약 20초간 카메라는 오프라인으로 보일 수 있습니다.

## 2. 색 검증 결과

- 회전 상태에서 색이 틀어지던 문제(보라 캐스트, 색 모아레)는 펌웨어에서 해결했고 실기·육안 확인을 마쳤습니다.
- 회전 여부와 무관하게 정방향 색은 이전과 동일합니다. 앱에서 색 관련 처리는 없습니다.

## 3. 같이 알아둘 것 (앱 변경 없음)

- **카메라 온라인 표시 정확도** (09-08 보고 §4와 동일): 브로커 권한 누락으로 카메라 heartbeat가 버려지던 문제를 고쳤습니다. 이전엔 라이브를 안 보면 몇 분 뒤 오프라인으로 잘못 표시됐습니다.
- **낮에 흑백으로 나오던 문제**: 회색 사육장을 야간(IR)으로 오판하던 펌웨어 판정을 고쳤습니다. 야간 IR 상태에서 흑백은 정상 동작이며 유지됩니다.
- **모션 클립이 같은 자리에서 반복 생성되던 문제**: 케이블 흔들림 같은 제자리 노이즈가 60초 클립을 반복 생성하던 것을 억제했습니다. 커뮤니티/클립 목록에 같은 장면 클립이 연달아 뜨던 현상이 줄어듭니다.
- **라이브 화면이 멈추던 문제**: 녹화 중 라이브 프레임이 거의 안 나가던 원인을 고쳤습니다. 실기 확인은 진행 중이라 재발 시 알려주시면 됩니다. 재현 정보로는 "부팅 후 첫 라이브인지, 두 번째 이후인지"가 가장 유용합니다.

## 5. 앱 E2E 체크리스트 (변경분 반영)

1. 토글 ON → 200 응답, Realtime으로 행 갱신
2. 약 20초 뒤 라이브 재연결 → 화면 뒤집힘, 거울상 아님, 색 정상
3. 그 상태에서 모션 클립·썸네일이 뒤집혀 나오는지
4. 토글 OFF → 원복
5. 라이브 시청 중 토글 시 앱의 재연결 UX가 자연스러운지 (§1 검토 항목)
